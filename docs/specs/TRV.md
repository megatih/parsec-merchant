# TRV: Travel, transit, arrival and day advance

> Format (PRD §7): `- **ID** {Mn} [M][W][P] statement (source)`. `[M]` Modern, `[W]` Windows 2.01, `[P]` Palm 1.2.2. A bullet carries only the tags of the rulesets for which it holds; differing values get separate bullets.
> Milestones: Windows 2.01 baseline and shared behaviour {M3}; Palm-only and Modern-only variants {M5}; quest-counter effects {M4} (the quest consequences themselves are owned by QST-*.md).
> C# sources are relative to `/Users/megatih/Downloads/SpaceTraderSource201`; Palm sources are `docs/reference/palm-src/Src/…`. Every number and order below was re-read from those lines on 2026-11-16. `[verify]` marks a statement that could not be fully confirmed from source alone.
> **Modern = Windows 2.01 plus the closed MOD list (PRD §4.3).** A Windows quirk that no MOD entry fixes is tagged `[M][W]`. Flag names are those of RUL.md; flags this spec needs that RUL.md does not yet list are collected in §12.
> Notation: `D` = difficulty (Beginner 0 … Impossible 4); `rand(n)` = one game-RNG draw uniform in `0..n-1` (C# `Functions.GetRandom`, Palm `GetRandom`); `cur` = the current system; `target` = `state.warpSystem`; `distance` = GAL-007 (floor) for Modern/Windows and GAL-008 (rounded `realDistance`) for Palm; `fuel` = the ship's fuel (Palm `GetFuel() = min(Fuel, tanks)`, SHP-017); `Engineer` = the ship's effective Engineer skill (CRW-011/013). `/` is truncating integer division.

## 1. Reachability and targets

- **TRV-001** {M3} [M][W] `destOk(s)` (C# `StarSystem.DestOk`) is true iff `s != cur` and (`distance(cur, s) <= Ship.Fuel` or `wormholeExists(cur, s)`, GAL-031). (source: StarSystem.cs:305-313)
- **TRV-002** {M5} [P] Palm reachability is `wormholeExists(cur, s)` or `0 < realDistance(cur, s) <= GetFuel()`. Because no two systems are closer than 7 parsecs (GAL-025), this equals `destOk` evaluated with Palm distance and Palm fuel; one predicate serves all rulesets. (source: Palm: Src/Traveler.c:631-668 `ShowExecuteWarp`, :748-754 `NextSystemWithinRange`)
- **TRV-003** {M3} [M][W][P] `selectTarget(s)` accepts any system index (in or out of range), sets `warpSystem = s` and `targetWormhole = false`, and changes nothing else; an index outside the galaxy is rejected with `CommandError.invalidArgument`. (source: Game.cs:4288-4299 `SelectedSystemId` setter; Palm: Src/WarpFormEvent.c:372)
- **TRV-004** {M3} [M][W] `selectWormhole(w)` requires `w` to be a wormhole system (else `invalidArgument`); it sets `targetWormhole = true` and `warpSystem = Wormholes[(k + 1) % 6]` where `Wormholes[k] == w`. Any wormhole system may be chosen, not only the current one, so the resulting target is in range only if it is reachable by fuel or `w == cur`. (source: Game.cs:4328-4344 `TargetWormhole` setter, Form_SpaceTrader.cs:3808-3820)
- **TRV-005** {M5} [P] Palm accepts a wormhole selection only when `w == cur`; otherwise it is rejected with `CommandError.wormholeNotAtCurrentSystem` (Palm `WormholeOutOfRangeAlert`) and the target is unchanged. (source: Palm: Src/WarpFormEvent.c:400-412)
- **TRV-006** {M3} [M][W][P] `preview(.destinations)` returns the indices of every system `s` with `destOk(s)`, in ascending index order (C# `Game.Destinations`). (source: Game.cs:3346-3361; Palm: Src/Traveler.c:734-760)
- **TRV-007** {M3} [M][W] `selectNextTarget(forward:)`: let `dest = preview(.destinations)`; if empty, nothing changes (no error, no event). Otherwise `index = dest.firstIndex(of: warpSystem)`; if absent, `index = forward ? 0 : dest.count − 1`, else `index = (dest.count + index ± 1) % dest.count`. If `wormholeExists(cur, dest[index])` the engine applies `selectWormhole(cur)` (so `targetWormhole = true`), else `selectTarget(dest[index])`. (source: Game.cs:3002-3023)
- **TRV-008** {M5} [P] Palm `selectNextTarget(forward:)` scans `i = warpSystem ± 1, ± 2, …` with wrap-around over `0..119`, stops when it returns to `warpSystem`, and selects the first `i` that is reachable (TRV-002); if none, nothing changes. When `warpSystem` is itself in range the result equals TRV-007; when it is not, Palm picks the next reachable index after the old target while Windows picks the first (or last) of the list. (source: Palm: Src/Traveler.c:734-760, :2716-2745)
- **TRV-009** {M3} [M][W][P] `track(s?)` sets `trackedSystem` to any system index or to `nil`; tracking never affects travel rules except the Palm singularity target (TRV-020) and the arrival auto-off (TRV-050/TRV-060). (source: Form_SpaceTrader.cs:3657-3661; Palm: Src/WarpFormEvent.c:564)
- **TRV-010** {M3} [M][W][P] After every arrival `warpSystem` equals the arrival system (the target is not cleared), so `destOk(warpSystem)` is false until the player selects a new target. (source: Game.cs:311, :4394-4408; Palm: Src/Traveler.c:2436)

## 2. Warp command and preconditions

- **TRV-011** {M3} [M][W][P] `perform(.warp)` is accepted only in phase `.docked` with no pending decision (else `notAllowedInPhase` / `pendingDecisionFirst`). It first rejects `!destOk(warpSystem)` (which includes `warpSystem == cur`) with `CommandError.destinationOutOfRange` (the source simply hides the Warp button), then runs the ruleset's affordability and consent checks. A rejection changes no state. (source: Form_SpaceTrader.cs:3214-3220, :3663-3678; Palm: Src/Traveler.c:647-668)
- **TRV-012** {M3} [M][W] Check order (`warpCheckOrder`, BNK-057): (1) `debt > 100000` → `debtTooLargeToTravel`; (2) `cash < mercenaries` → `cannotPayMercenaries`; (3) `cash < mercenaries + insurance` → `cannotPayInsurance`; (4) `cash < mercenaries + insurance + wormholeTax` → `cannotPayWormholeTax`; (5) the Wild consent (TRV-014). The first failing check is returned. Interest is never checked. (source: Game.cs:3155-3178)
- **TRV-013** {M5} [P] Palm check order: (1) the Wild consent; (2) `Debt > 100000`; (3) `MercenaryMoney() > Credits`; (4) only if insured, `InsuranceMoney() + MercenaryMoney() > Credits`; (5) `InsuranceMoney() + MercenaryMoney() + WormholeTax > Credits`. Each Palm `a > Credits` test equals the C# `cash < a` test, and Palm `InsuranceMoney()` is 0 when uninsured. (source: Palm: Src/Traveler.c:483-530, :95-102)
- **TRV-014** {M3} [M][W][P] Wild consent: when Wild is aboard and the ship lacks a qualifying laser (`wildRequiresRealLaser`, RUL-111: Windows `HasWeapon(BeamLaser, exact: false)`, which disruptors satisfy; Modern and Palm Beam, Military or Morgan's), `.warp` without `acknowledging: [.wildLeavesWithoutLaser]` returns `needsConfirmation(Confirmation(.wildLeavesWithoutLaser))` and changes nothing. With the acknowledgement, Wild leaves (quest status 0; effects owned by QST-WILD), the event `.wildLeftShip` is emitted and the warp continues in the same step. (source: Game.cs:3167-3177; Palm: Src/Traveler.c:483-498)
- **TRV-015** {M5} [P] Because the Palm Wild consent comes first, acknowledging it removes Wild even when a later check fails. The step then commits the Wild removal and returns `rejection: nil` with events `[.wildLeftShip, .departureBlocked(error)]`. This is one of the two documented exceptions (with TRV-021) to "a rejected step changes nothing". (source: Palm: Src/Traveler.c:488-530)
- **TRV-016** {M3} [M][W][P] The wormhole tax is `25 × fuel cost per parsec` when `wormholeExists(cur, warpSystem)`, else 0, with the fuel column of `palmFuelRepairColumns` (BNK-052/053, RUL-117): a Gnat pays 25 in Windows and 50 in Modern and Palm; a Wasp pays 125 and 500. (source: Game.cs:4410-4416, Consts.cs:58; Palm: Src/Traveler.c:167-173)
- **TRV-017** {M3} [M][W][P] `preview(.warpAffordability(target))` (BNK-062) evaluates TRV-011..013 for `target` without changing state and reports the consent requirement separately (`wildWillLeave: Bool`); `perform(.warp)` returns exactly the error the preview reports. (source: Game.cs:3153-3178; Palm: Src/Traveler.c:483-530)

## 3. Singularity jump

- **TRV-018** {M3} [M][W][P] `perform(.jump)` requires `quests.canSuperWarp == true`, else `CommandError.noSingularity`. It is accepted only in `.docked` with no pending decision and performs no range or fuel test: any system may be the destination. (source: Form_SpaceTrader.cs:3048, :3542-3566; Palm: Src/WarpFormEvent.c:325, :550-566)
- **TRV-019** {M3} [M][W] The Windows jump destination is `warpSystem`; `warpSystem == cur` is rejected with `singularityTargetIsCurrentSystem` (ALR-020). Because the engine's `warpSystem` is never `nil`, ALR-021 `singularityNoTarget` cannot occur in these rulesets. (source: Form_SpaceTrader.cs:3544-3548)
- **TRV-020** {M5} [P] The Palm jump destination is `trackedSystem`: `nil` → `singularityNoTarget`; `== cur` → `singularityTargetIsCurrentSystem`; on consent `warpSystem = trackedSystem` before the departure checks. Flag `singularityTargetSource` (§12). (source: Palm: Src/WarpFormEvent.c:550-566)
- **TRV-021** {M3} [M][W][P] Without `acknowledging: [.useSingularity]` the jump returns `needsConfirmation(Confirmation(.useSingularity, amounts: [destination]))` and changes nothing. With it, `canSuperWarp = false` is committed **before** the departure checks (TRV-012/TRV-013, including the Wild consent): if a check fails the singularity is lost and the step returns `rejection: nil` with events `[.singularityLost, .departureBlocked(error)]`. The app SHOULD disable Jump using `preview(.jump)` so this quirk is only reachable deliberately. (source: Form_SpaceTrader.cs:3549-3557; Palm: Src/WarpFormEvent.c:562-566)
- **TRV-022** {M3} [M][W][P] If the Wild consent is needed during a jump and `.wildLeavesWithoutLaser` is not acknowledged, the step returns that confirmation without committing anything, so declining keeps the singularity. This deviates from both sources (declining there still loses the singularity); it is recorded in §12 for a RUL audit row. [verify] (source: Form_SpaceTrader.cs:3551-3557, Game.cs:3170-3172; Palm: Src/Traveler.c:488-491)
- **TRV-023** {M3} [M][W] A Windows singularity departure (`singularitySideEffects`, RUL-068) charges no mercenaries, insurance, wormhole tax or interest, uses no fuel and does not call `IncDays`; `arrivedViaWormhole = wormholeExists(cur, destination)`; it adds `NewsEvent.experimentArrival`, which the news reset of TRV-029 clears immediately, so that headline never appears. Countdown, news reset, `CalculatePrices(destination)`, fabric rip, the 20-click transit and the arrival pipeline run as for a normal warp. (source: Game.cs:3182-3194)
- **TRV-024** {M5} [P] A Palm singularity departure charges nothing and skips `PayInterest`, `IncDays(1)` and `++NoClaim`, but still recharges the shields, sets `arrivedViaWormhole = true`, sets Clicks = 21, heals the Space Monster and applies record decay using the unchanged day; the singularity news flag is added after the news reset and therefore appears. (source: Palm: Src/Traveler.c:532-591; research 04 errata #4)
- **TRV-025** {M5} [M] A Modern singularity departure behaves as TRV-023 and additionally applies the MOD-003 record decay (TRV-033) at the same point, using the unchanged day; it does not heal the Space Monster or recharge shields at departure. (source: PRD §4.3 MOD-003; RUL-068, RUL-103)

## 4. Departure (normal warp)

- **TRV-026** {M3} [M][W] Windows departure order after the checks pass: (1) `arrivedViaWormhole = wormholeExists(cur, target)`; (2) `cash -= mercenaries + insurance + wormholeTax`; (3) `Ship.Fuel -= (arrivedViaWormhole ? 0 : distance(cur, target))`; (4) `PayInterest()` (BNK-020/024); (5) `IncDays(1)` (§9); (6) `cur.countDown = D + 3` (ECO-033); (7) news reset (TRV-031); (8) `CalculatePrices(target)` (ECO-016); (9) the fabric-rip test (§5); (10) the transit starts (§6). (source: Game.cs:3182-3196, :2849-2855)
- **TRV-027** {M3} [M][W] The three departure costs are computed once, before any deduction, from the pre-departure state (the insurance premium uses the no-claim value before `IncDays(1)` raises it). The fuel deduction never makes fuel negative because `destOk` held. (source: Game.cs:2851-2852, :3831-3837)
- **TRV-028** {M3} [M][W][P] The departure emits `.departed(from: cur, to: target, viaWormhole: arrivedViaWormhole)` after the countdown, news reset and `CalculatePrices(target)` and before any fabric-rip event; the amounts charged are recoverable from `preview(.dailyCosts)` taken before the warp (BNK-061). (source: Game.cs:2849-2855; Palm: Src/Traveler.c:532-567)
- **TRV-029** {M3} [M][W] The news-event list is cleared after `IncDays(1)`, so a `NewsEvent.experimentPerformed` added by the departure's own `IncDays` (TRV-078) is lost; it survives only when the experiment completes during jail or escape-pod days. Kept in Modern (no MOD entry). (source: Game.cs:2854, :2627, :3192)
- **TRV-030** {M3} [M][W][P] `CalculatePrices(target)` runs at departure, before the fabric-rip test and before any click, using the police record after the departure's day advance and decay; these are the prices trade in orbit uses during the trip (ECO-016(b)). (source: Game.cs:3194; Palm: Src/Traveler.c:593)
- **TRV-031** {M5} [P] Palm departure order after the checks pass: (1) if not a singularity, `Credits -= wormholeTax`, then `-= mercenaries`, then `-= insurance`; (2) every shield recharged to its power (`shieldRechargeTiming`); (3) `cur.countDown = 3 + D`; (4) wormhole or singularity → distance 0 and `arrivedViaWormhole = true`, else `Fuel -= min(distance, GetFuel())` and `arrivedViaWormhole = false`; (5) news reset; (6) if not a singularity: `PayInterest()`, `IncDays(1)`, then `++NoClaim` if insured (BNK-044); else add the singularity news flag; (7) Clicks = 21 and Raided, Inspected and LitterWarning cleared; (8) Space Monster heal (TRV-032); (9) record decay (TRV-033); (10) the fabric-rip test is armed; (11) `DeterminePrices(target)`; (12) `Travel()`. (source: Palm: Src/Traveler.c:532-594)
- **TRV-032** {M5} [P] Palm heals the Space Monster once per warp, including singularity jumps: `MonsterHull = MonsterHull × 105 / 100`, capped at the monster's hull strength (500) (`monsterRegeneration`). A hull below 20 never grows (e.g. 19 → 19; 100 → 105). (source: Palm: Src/Traveler.c:577-579)
- **TRV-033** {M5} [M][P] MOD-003 `policeRecordDecay`: once per warp, including singularity jumps, using `days` after the warp's day advance (unchanged for a singularity): `if days % 3 == 0 && record > 0 { record -= 1 }`, then `if record < −5 { if D <= Normal { record += 1 } else if days % D == 0 { record += 1 } }`. In Modern it runs immediately after the departure's `IncDays(1)` (or where it would run), before the countdown and `CalculatePrices(target)`; it never runs inside `IncDays`. (source: Palm: Src/Traveler.c:580-589; PRD §4.3 MOD-003; RUL-103)
- **TRV-034** {M5} [M][P] Decay examples: Normal, days 9 after the advance, record 10 → 9, record −10 → −9; Normal, days 10, record 10 → 10; Hard (D = 3), days 10, record −10 → −10; Hard, days 12, record −10 → −9; Impossible (D = 4), days 12, record 3 → 2 and record −8 → −7. (source: Palm: Src/Traveler.c:580-589)
- **TRV-035** {M5} [P] Palm clears the news events **before** `IncDays(1)`, so `EXPERIMENTPERFORMED` raised by the departure day advance survives into the arrival newspaper (contrast TRV-029). Flag `newsResetBeforeDayAdvance` (§12). (source: Palm: Src/Traveler.c:559-571, :1729-1738)

## 5. Fabric rip

- **TRV-036** {M3} [M][W] At the start of the transit (after TRV-030), if `experiment == 12 && fabricRipProbability > 0 && (fabricRipProbability == 25 || rand(100) < fabricRipProbability)`, the destination becomes `rand(N)` (N = 128) and `targetWormhole = false`. When the probability is exactly 25 no draw is made for the test. (source: Game.cs:3108-3113, Consts.cs:93)
- **TRV-037** {M5} [P] Palm tests `PossibleToGoThroughRip && ExperimentStatus == 12 && FabricRipProbability > 0 && (rand(100) < FabricRipProbability || FabricRipProbability == 25)`: the draw always happens first, then `WarpSystem = rand(120)`. The test runs once per trip (`PossibleToGoThroughRip` is cleared on first entry to `Travel`). (source: Palm: Src/Traveler.c:1764-1772, :591)
- **TRV-038** {M3} [M][W][P] A rip changes only the destination (`TransitState.destination` and `warpSystem`): fuel, costs and interest already charged are not refunded, the departure prices stay those of the original target, `arrivedViaWormhole` keeps its departure value, and the new destination may be any system including the original target or the departure system. The step emits `.fabricRip(newDestination:)` (ALR-165 `SpecialTimespaceFabricRip`). (source: Game.cs:3111-3112; Palm: Src/Traveler.c:1768-1769)
- **TRV-039** {M3} [M][W][P] The rip test applies to normal warps and singularity jumps alike. Because a probability of 25 always rips, the first trip whose departure day advance completes the experiment always rips (TRV-078 sets 25 in that same `IncDays`); every later `IncDays(n)` lowers the probability by n (TRV-078), so later trips rip with chance `p/100`. (source: Game.cs:2622-2631, :3108-3109; Palm: Src/Traveler.c:1729-1745, :1764-1767)

## 6. Transit state machine

- **TRV-040** {M3} [M][W][P] A successful departure sets `phase = .inTransit(TransitState(destination:, clicksRemaining: 20, viaWormhole: arrivedViaWormhole, hadEncounter: false))` and then runs the click loop of TRV-041 within the same `.warp` / `.jump` step. Every ruleset performs exactly 20 click steps numbered 20 down to 1 (`transitClicks`, RUL-069); Palm's `Clicks = 21` sentinel is represented by `hadEncounter`. (source: Game.cs:3115-3121, Consts.cs:71; Palm: Src/Traveler.c:573-576, :1774-1777)
- **TRV-041** {M3} [M][W][P] Click loop (C# `Travel`): while `clicksRemaining > 0`: (1) per-click repairs (§7); (2) encounter determination for click `c = clicksRemaining` (owned by ENC); (3) if an encounter starts, set `hadEncounter = true`, keep the transit state, set `phase = .encounter(…)`, emit `.encounterStarted(type:opponent:clicks: c)` and end the step with `clicksRemaining` unchanged; otherwise `clicksRemaining -= 1`. When the loop ends, the trip arrives (§8) in the same step and the phase becomes `.docked`. The app animates the 20-tick track from these events. (source: Game.cs:3121-3148; Palm: Src/Traveler.c:1777-2204)
- **TRV-042** {M3} [M][W][P] When an encounter ends with the player still flying, the step that ended it sets `clicksRemaining -= 1`, restores `phase = .inTransit` and continues the click loop (TRV-041) in that same step. The transit is resumable and `Codable`: saving and loading in `.encounter` (with the saved transit state) produces the same subsequent results. (source: Game.cs:3147; Palm: Src/Encounter.c:2309)
- **TRV-043** {M3} [M][W][P] An encounter ending in arrest runs the arrest sequence (POL; RUL-137) and an escape-pod ending runs the pod sequence (POL; BNK-047); both end the click loop and the trip still arrives at the destination in the same step, running no further click. An encounter ending in the player's death sets `phase = .gameOver(.killed)` and returns `decision: .gameOver(.killed)`; no arrival runs. (source: Game.cs:3134-3143; Palm: Src/Encounter.c:592, :738-781)
- **TRV-044** {M5} [P] Palm post-Marie customs (`postMarieCustomsTiming`, RUL-070): when the loop ends with `justLootedMarie` set, a police encounter starts after the loop (Palm `Clicks++` makes it click 1 again) and `justLootedMarie` is cleared; when it ends the trip arrives with no further repair or click. (source: Palm: Src/Traveler.c:2207-2217)
- **TRV-045** {M3} [M][W][P] `.uneventfulTrip` (ALR-168) is emitted at arrival iff `hadEncounter == false` (C# `uneventful`; Palm `StartClicks > 20`), before every arrival-pipeline event; `.arrived(system:)` is the last event of the pipeline. An arrest or escape pod always implies an encounter, so they never produce it. (source: Game.cs:3196-3205; Palm: Src/Traveler.c:2220)
- **TRV-046** {M3} [M][W][P] Raided, Inspected and LitterWarning are reset at departure, after the fabric-rip test (C# `Travel`); which encounters occur and how they resolve is owned by ENC, CMB and POL. While in transit or in an encounter every docked command is rejected with `notAllowedInPhase`. (source: Game.cs:3116-3118; Palm: Src/Traveler.c:574-576)

## 7. Per-click repairs

- **TRV-047** {M3} [M][W] Each click, before the encounter check, the player's ship repairs `r = rand(Engineer)`: `used = min(r, hullStrength − hull)`, `hull += used`, `r -= used`; if `r > 0` then `r *= 2` and shields are recharged in slot order, each by `min(r, power − charge)`, until `r` is exhausted (`inFlightRepairHalved` off). (source: Ship.cs:664-694)
- **TRV-048** {M5} [P] Palm per-click repair is `r = rand(Engineer) >> 1`, with the same hull-first, overflow ×2 to shields in slot order rule. (source: Palm: Src/Traveler.c:1779-1804)
- **TRV-049** {M3} [M][W][P] The repair draw happens on every click, even at full hull and shields, so the RNG sequence does not depend on damage. Example (Windows): Engineer 6, draw 5, hull 2 below maximum, one shield 10 below power → hull +2, shield +6. (source: Ship.cs:669-692; Palm: Src/Traveler.c:1780)

## 8. Arrival pipeline

- **TRV-050** {M3} [M][W] Windows arrival order (`arrivalPipelineOrder`): (1) `cur = destination`, mark it visited, `paidForNewspaper = false`, and if `trackedSystem == cur && options.trackAutoOff` then `trackedSystem = nil`; (2) reactor check (TRV-052); (3) tribbles (TRV-053); (4) debt warning or reminder (TRV-054); (5) arrival repairs, shield recharge and auto-fuel/auto-repair (TRV-055..057); (6) pressures and quantities (ECO-034..037); (7) the Og Easter egg (TRV-058); (8) `CalculatePrices(cur)`; (9) arrival news events (NEWS §4); (10) the newspaper if `options.newsAutoShow` (NEWS-012). (source: Game.cs:309-330)
- **TRV-051** {M3} [M][W] The full Windows pipeline also runs after an arrest or escape pod, with the day count already advanced by the jail term or pod days. (source: Game.cs:3134-3141, :3207)
- **TRV-052** {M4} [M][W] Reactor check: status 20 → event `.reactorMeltdown`, status = 0, then the escape pod if owned (BNK-047, POL), after which the pipeline continues, else `phase = .gameOver(.killed)` and the pipeline stops. Otherwise status 2 → `.reactorWarning(.fuelConsumption)`, 16 → `.fuelStarvation`, 18 → `.coreTemperature`. Quest effects are owned by QST-REACTOR. (source: Game.cs:365-393)
- **TRV-053** {M4} [M][W][P] The tribble update runs at the pipeline position of its ruleset and follows `tribbleAlgorithm` (RUL-151); its rules and events are owned by QST-TRIBBLES. (source: Game.cs:395-457; Palm: Src/Traveler.c:2264-2318)
- **TRV-054** {M3} [M][W][P] The debt check follows BNK-034 (Windows: warning, else reminder), BNK-036 (Palm) and BNK-037 (Modern, both at the Windows position), with `debtWarningAndReminder` (MOD-018). (source: Game.cs:332-340; Palm: Src/Traveler.c:2222-2230)
- **TRV-055** {M3} [M][W] Arrival repairs: if `hull < hullStrength`, `hull += min(hullStrength − hull, rand(Engineer))` (no draw at full hull); then every shield is set to its full power. (source: Game.cs:464-469)
- **TRV-056** {M3} [M][W] Auto-buy is all-or-nothing and uses cash (`arrivalAutoBuyPartial` off, SHP-057): with `options.autoFuel` and `need = tanks − fuel > 0`, fill the tank only if `cash >= need × fuelCost`, else `fuelOk = false`; then with `options.autoRepair` and `need = hullStrength − hull > 0`, repair fully only if `cash >= need × repairCost`, else `repairOk = false`. Purchases emit `.boughtFuel` / `.repairedHull`. Cost columns follow `palmFuelRepairColumns`. (source: Game.cs:471-495)
- **TRV-057** {M3} [M][W] Auto-buy warnings: both failed → `.autoRefuelAndRepairIncomplete`; else fuel failed → `.autoRefuelIncomplete`; else repair failed → `.autoRepairIncomplete` (ALR-007/008/010). (source: Game.cs:497-502)
- **TRV-058** {M4} [M][W] Og Easter egg: at Og, if every cargo slot holds exactly 1 unit and a shield slot is free, a fully charged Lightning shield is installed, every cargo count and cost basis is set to 0, and `.easterEggLightningShield` is emitted (ALR-034); otherwise nothing happens. (source: Game.cs:342-363, Shield.cs:42-49)
- **TRV-059** {M3} [M][W][P] The market part of the arrival is ECO's `arrivalMarketUpdate(arrival:)` (ECO-041). In Windows and Modern the Easter egg sits between the pressure/quantity update and `CalculatePrices`; the egg draws no random number and changes nothing prices depend on, so running the egg after the whole market update gives identical state. (source: Game.cs:322-325; Palm: Src/Traveler.c:2434-2441)

## 9. Day advance (IncDays)

- **TRV-069** {M3} [M][W][P] `IncDays(n)` is called with n = 1 by a normal departure, n = jail term by the arrest sequence and n = 3 by the escape-pod sequence; a singularity jump never calls it. (source: Game.cs:2854, :305, :2097; Palm: Src/Traveler.c:564, Src/Encounter.c:648, :740)
- **TRV-070** {M3} [M][W] Windows `IncDays(n)` order: (1) `days += n`; (2) if insured, `noClaim += n` (stored clamped 0…90, BNK-043); (3) record decay (TRV-071); (4) Space Monster heal (TRV-073); (5) Gemulon counter; (6) reactor counter; (7) experiment counter or fabric-rip decay; (8) Jarek, (9) Princess and (10) Wild impatience. Events are emitted in this order. (source: Game.cs:2584-2683)
- **TRV-071** {M3} [W] Windows record decay inside `IncDays(n)`: if `record > 0`, `record = max(0, record − n/3)`; else if `record < −5`, `record = min(−5, record + n / (D <= Normal ? 1 : D))`. With n = 1 a positive record never decays and a negative one never improves on Hard or Impossible. (source: Game.cs:2592-2596; RUL-103)
- **TRV-072** {M3} [W] Decay examples: n = 1, record 10 → 10; n = 1, Normal, record −10 → −9; n = 1, Hard, record −10 → −10; n = 3 (pod), record 10 → 9; n = 3, Impossible, record −10 → −10; n = 30, record 20 → 10. (source: Game.cs:2592-2596)
- **TRV-073** {M3} [M][W] Space Monster heal: if `hull < hullStrength`, `hull = min(hullStrength, (int)(hull × 1.05^n))` in double precision. Examples: 100, n = 1 → 105; 19, n = 1 → 19; 200, n = 3 → 231; 490, n = 1 → 500. (source: Game.cs:2599-2600)
- **TRV-074** {M5} [P] Palm `IncDays(n)` only advances `days` and the Gemulon, reactor and experiment counters (TRV-076, TRV-077, TRV-078); no-claim, decay and monster heal happen per warp (TRV-031..033) and there is no passenger impatience (`passengerImpatience`). ## 12. Open points and discrepancies

- **Flags this spec needs that RUL.md does not list yet** (each defaults to the Windows behaviour): `singularityTargetSource` (warp target vs tracked system, TRV-020), `nextTargetOrdering` (list wrap vs index scan, TRV-008), `wormholeSelectionScope` (any wormhole vs current only, TRV-005), `newsResetBeforeDayAdvance` (TRV-035), `arrivalPipelineAfterArrest` (full vs market only, TRV-062), `invasionStatusCapped` (TRV-076), `eggMessageWithoutSlot` (TRV-066), `fabricRipDrawFirst` (TRV-037, RNG order only).
- **[verify] Jump plus Wild consent (TRV-022).** In both sources, declining the Wild prompt after confirming the jump loses the singularity. The two-phase API cannot lose state on a declined confirmation, so the engine keeps the singularity. Needs a RUL audit row (keep-as-deviation) before M5.
- **Research 01 §6 says the singularity jump "adds the ExperimentArrival news".** It does add it, but `NewsResetEvents()` runs four lines later (Game.cs:3185, :3192), so the headline never appears in Windows or Modern (TRV-023). Palm resets first, so its headline appears (TRV-024).
- **Research 01 §6 lists "news events" as an arrival product without noting** that the departure's own `ExperimentPerformed` news is cleared by the departure reset (TRV-029).
- **Research 04 §3 lists Palm `DoWarp` steps 6–9 as "pay, recharge shields, fuel, interest/IncDays, Clicks, decay, prices"**; the source also resets the news between fuel and interest and heals the monster before decay (TRV-031). The countdown is set between the shields and fuel.
- **Research 04 §3 (Arrival) omits** that a Palm meltdown with a pod runs `Arrival()` twice (TRV-061) and that Palm skips the whole post-`Arrival()` pipeline after arrest or the pod (TRV-062).
- **Naming mismatches with ALR.md:** ALR-030 says `debtTooLargeToDepart`, ALR-116..118 give `cannotPay…(amount:)` payloads, ALR-029/033 say `loanReminder(debt:)` / `debtWarning(debt:)`, and ALR-187 says `WarningID.departWithoutWild(system:)`. This spec follows BNK-063 and the existing `WarningID` enum (`wildLeavesWithoutLaser`, `useSingularity`); ALR.md should be aligned when the cases are added to the code.
