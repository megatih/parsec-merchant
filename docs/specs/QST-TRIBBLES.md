# QST-TRIBBLES: Tribbles

> Format (PRD §7): `- **ID** {Mn} [M][W][P] statement (source)`. `{M4}` is C# 2.01 behaviour, kept in Modern, plus anything shared with Palm. `{M5}` is a Palm-only variant or a Modern-only fix that needs a ruleset flag.
> Sources: C# 2.01 at `/Users/megatih/Downloads/SpaceTraderSource201`, Palm 1.2.2 at `docs/reference/palm-src/Src`, re-read on 2026-11-17. Shared rules are QST-INDEX §3. Placement: `Tribble` is placed randomly once and `TribbleBuyer` three times (GAL-037).
> State: `commander.ship.tribbles` (`Ship.tribbles`, 0…`MaxTribbles` = 100000, Consts.cs:102) and `GameState.tribbleMessage`. `T` = tribbles, `food`/`narc`/`furs` = the ship's cargo of those items, `rand(n)` = one game-RNG draw in `0..n−1` (`rand(0)` returns 0 and still consumes a draw, RNG-012). There is no quest status: the "quest" is open while `T > 0`.

## 1. Buying a tribble

- **QST-TRIBBLES-001** {M4} [M][W][P] `Tribble` is always shown; it is a question with price 1000 (`Confirmation(.acceptSpecialEvent, amounts: [1000])`), and `cashToSpend < 1000` is rejected with `insufficientFunds`. Accepting **sets** `T = 1` (an assignment, not an increment), charges 1000 and removes the event. The app shows ALR-175 from `specialEventCompleted(.tribble)`. (source: StarSystem.cs:198-199; Game.cs:2524-2527, :2577-2581; Consts.cs:334; Palm: Src/SpecialEvent.c:207-210, Src/Global.c:502)
- **QST-TRIBBLES-002** {M5} [P] Palm hides `Tribble` while more than 3 quests are open, and counts `T > 0` as an open quest (`openQuestCap`, RUL-141). (source: Palm: Src/SystemInfoEvent.c:302-314, Src/QuestEvent.c:84)

## 2. Selling to a tribble buyer

- **QST-TRIBBLES-003** {M4} [M][W][P] `TribbleBuyer` is shown iff `T > 0`; it is a question with price 0. Accepting adds `T / 2` (truncating) to cash, sets `T = 0` and removes that buyer's event; the other buyers stay. The app shows ALR-171 from `specialEventCompleted(.tribbleBuyer)`. (source: StarSystem.cs:276-278; Game.cs:2528-2532; Consts.cs:335; Palm: Src/SpecialEvent.c:212-216, Src/SystemInfoEvent.c:275)
- **QST-TRIBBLES-004** {M4} [M][W] The newspaper prints `.tribbleBuyer(i)` for every reachable system whose event is `TribbleBuyer`, whether or not the player has tribbles (NEWS-022). (source: Game.cs:3956-3957)

## 3. The arrival update (C# `ArrivalCheckTribbles`)

- **QST-TRIBBLES-005** {M4} [M][W] The update runs at step 3 of every Windows arrival pipeline (TRV-050, TRV-053), including the arrival after an arrest or the escape pod (POL-109), and only when `T > 0`. Exactly one branch applies: **reactor** if the reactor is aboard (QST-REACTOR); else **narcotics** if `narc > 0`; else **food/growth**. In every branch it then sets `tribbleMessage = false` and emits `GameEvent.tribblesChanged(from:to:)` (TRV-082) after the branch events. (source: Game.cs:319, :395-457)
- **QST-TRIBBLES-006** {M4} [M][W] Reactor branch (no RNG): if `T < 20`, `T = 0` with `GameEvent.tribblesDied(.allFromReactor)` (ALR-169); else `T = T / 2` with `.tribblesDied(.halfFromReactor)` (ALR-172). No growth and no inspector warning follow. (source: Game.cs:405-417)
- **QST-TRIBBLES-007** {M4} [M][W] Narcotics branch: `dead = min(1 + rand(3), narc)`; `priceCargo[narc] = priceCargo[narc] × (narc − dead) / narc`; `narc −= dead`; `furs += dead` (the furs' cost basis is unchanged); then `T −= min(dead × (rand(5) + 98), T − 1)`, so at least one tribble survives. Draw order: `rand(3)`, then `rand(5)`. Event `.tribblesDied(.narcotics(converted: dead))` (ALR-174). No growth and no inspector warning follow. (source: Game.cs:418-426)
- **QST-TRIBBLES-008** {M4} [M][W] Food branch, eating: if `food > 0 && T < 100000`: `eaten = food − rand(food)` (1…food); `priceCargo[food] −= priceCargo[food] × eaten / food` (with the count before eating); `food −= eaten`; `T += eaten × 100`; event `.tribblesAteFood(eaten:)` (ALR-170). (source: Game.cs:429-436)
- **QST-TRIBBLES-009** {M4} [M][W] Food branch, growth: then, if `T < 100000`, `T += 1 + rand(food > 0 ? T : T / 2)` using the food left after eating and the current `T`; finally `T = min(T, 100000)`. With `T = 1` and no food the bound is 0, so the draw is consumed and `T` becomes 2. (source: Game.cs:438-442)
- **QST-TRIBBLES-010** {M4} [M][W] Food branch, inspector warning: if the update raised `T` across 100, 1000, 10000 or 50000 (previous value below, new value at or above), or to exactly 100000 from below, emit `.tribbleInspectorWarning(count: T)` once (ALR-177; `count == 100000` is shown as "a dangerous number"). (source: Game.cs:444-453)
- **QST-TRIBBLES-011** {M4} [M][W] Worked example: `T = 10`, food 4 with cost basis 400, no reactor, no narcotics; draws `rand(4) = 1`, `rand(310) = 9`: eaten 3, food 1, cost basis 100, `T = 310`, then `T = 320`; events `[.tribblesAteFood(eaten: 3), .tribbleInspectorWarning(count: 320), .tribblesChanged(from: 10, to: 320)]`. (source: Game.cs:429-453)
- **QST-TRIBBLES-012** {M5} [P] Palm update (`tribbleAlgorithm`, RUL-151), only on the normal arrival path (TRV-060 step 6; skipped after arrest or pod, TRV-062): reactor aboard → `T /= 2`, and `T < 10` → 0 (TribblesAllIrradiated) else TribblesIrradiated; else `narc > 0` → `T = 1 + rand(3)`, then `i = min(1 + rand(3), narc)` moves `i` narcotics to furs with the cost basis scaled by `(narc − i)/narc`; else `food > 0` → `T += 100 + rand(food × 100)`, then `food = rand(food)` with the cost basis scaled by `food_new/food_old`. Then, after **any** branch, if `0 < T < 100000`: `T += 1 + rand(max(1, food branch taken ? T : T / 2))`; clamp to 100000. The inspector warning tests only 100, 1000, 10000 and 50000 and says "a dangerous number" when `T >= 100000`. (source: Palm: Src/Traveler.c:2264-2318)

## 4. Value, trade and loss

- **QST-TRIBBLES-013** {M4} [M][W][P] With `T > 0` the ship's trade-in value counts its hull at `price × 1 / 4` instead of `× 3 / 4` (`BaseWorth(false)`, SHP-027, BNK-007); this lowers ship trade-in (SHP-034) and the trade-in-based worth (Modern MOD-019, Palm), but not the insurance value (`forInsurance`) nor the Windows list-price worth. (source: Ship.cs:133-136; Palm: Src/ShipPrice.c:79)
- **QST-TRIBBLES-014** {M4} [M][W] While `T > 0`, the shipyard's purchase preview carries the advisory note `tribblesReduceTradeIn` (ALR-179); nothing is blocked. The engine never needs the C# once-per-visit flag: `tribbleMessage` is kept in the state for parity (set false by QST-TRIBBLES-005) and is not read by any rule. (source: Form_ShipList.cs:151-155; Game.cs:456)
- **QST-TRIBBLES-015** {M4} [M][W] A new ship (shipyard trade or designer build) starts with `T = 0` (SHP-044): the tribbles stay with the old ship. (source: Ship.cs:36, :51; Commander.cs:210 (`TradeShip`))
- **QST-TRIBBLES-016** {M4} [M][W][P] Arrest: if the fine is paid from cash the tribbles stay; if the ship is sold to pay it (POL-096) the replacement Flea has `T = 0`. No separate event: the arrest report derives ALR-176 (`TribblesRemoved`) from `arrested(…, shipSold: true)` with tribbles aboard before (POL-093). (source: Game.cs:279-292, :735-741; Palm: Src/Encounter.c:743-758)
- **QST-TRIBBLES-017** {M4} [M][W][P] Escape pod: the Flea has `T = 0` (POL-104 step 3). No separate event: the pod report derives ALR-173 (`TribblesKilled`) from `escapePodUsed` with tribbles aboard before (POL-104). (source: Game.cs:2044-2045, :735-741; Palm: Src/Encounter.c:626-630)
- **QST-TRIBBLES-018** {M4} [M][W][P] Tribbles are not cargo: they use no bays, cannot be sold, dumped, jettisoned, looted, plundered or confiscated, have no effect on inspections, bribes or fines, and opponents never carry any (ENC-079). In encounters they only drive the cosmetic sprite draws of ENC-087. `IncDays` never changes `T`. (source: Ship.cs:959-994, Game.cs:2584-2683, Form_Encounter.cs:1187-1210)

## 5. Scenarios

- **QST-TRIBBLES-019** {M4} [M][W] Buy and sell: at the Tribble system with cash 1000 and `reserveMoney` off, the acknowledged command gives `T = 1`, cash 0; with cash 999 it is rejected with `insufficientFunds`. After arrivals that grow `T` to 5001, a TribbleBuyer pays 2500 and sets `T = 0`; the buyer's event is removed and no other buyer is shown while `T == 0`. (source: Game.cs:2524-2532)
- **QST-TRIBBLES-020** {M4} [M][W] Reactor: arriving with the reactor aboard and `T = 19` → `T = 0` (`.allFromReactor`); with `T = 40` → 20 (`.halfFromReactor`); no RNG draw is made by either. (source: Game.cs:405-417)
- **QST-TRIBBLES-021** {M4} [M][W] Narcotics: `T = 500`, narc 2 with cost basis 300; draws `rand(3) = 2`, `rand(5) = 4`: `dead = 2`, narc 0, cost basis 0, furs +2, `T = 500 − min(204, 499) = 296`; growth does not run. (source: Game.cs:418-426)
- **QST-TRIBBLES-022** {M4} [M][W] Cap: `T = 99990`, no food → growth adds `1 + rand(49995)` and the result is clamped to 100000, emitting `.tribbleInspectorWarning(count: 100000)` when it lands there. (source: Game.cs:438-453)
- **QST-TRIBBLES-023** {M4} [M][W] Loss: buying a new ship with `T > 0` leaves `T = 0`; the escape pod leaves `T = 0`; an arrest whose fine is paid in cash keeps `T`. (source: Game.cs:279-292, :2044-2045)
