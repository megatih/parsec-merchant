## 1. Foundations

- **A11Y-001** {M12} [M][W][P] `AccessibilityPreferences { reduceMotion, increaseContrast, reduceTransparency, differentiateWithoutColor: Bool }` is resolved once per window root from the environment (`accessibilityReduceMotion`, `colorSchemeContrast == .increased`, `accessibilityReduceTransparency`, `accessibilityDifferentiateWithoutColor`), each OR'd with the Debug override of A11Y-002, and published as `@Entry var accessibilityPreferences`. Views, styles and `ArtAccessibility` (ART-004) read only this value, so tests and UI tests can force every variant without changing System Settings. Unit test: `AccessibilityPreferences.resolve(system:override:)` truth table. (source: UX-VISION §1.7, §9; ART "Accessibility as inputs")
- **A11Y-002** {M12} [M][W][P] Debug-only launch arguments, parsed by `LaunchOptions.parse` and ignored in Release (CHEAT-047): `-PMA11y <list>` (comma-separated `reduceMotion`, `increaseContrast`, `reduceTransparency`, `differentiateWithoutColor`); `-PMTips off|all` (A11Y-047); `-PMWindowSize min` (opens the main window at its 1100×720 minimum, ignoring the restored frame). `-PMAppearance light|dark` sets `NSApp.appearance` (Aqua or Dark Aqua) at launch, so light and dark runs do not depend on the Mac's own appearance (the argument-domain `-AppleInterfaceStyle Light` has no effect on a Mac set to Dark). Text Size needs no new argument: UI tests pass `-settings.textSize <case>`, which the argument domain gives to `@AppStorage`. Unit tests for each argument, its Release behaviour and malformed values. (source: CHEAT-047…051; CLAUDE.md "Debug launch arguments")

- **A11Y-030** {M12} [UI] [M][W][P] Known-issue policy. Real failures are never suppressed. `KnownAuditIssues.shouldIgnore` returns true only when one of these holds:
  - the issue's element has no app identifier, is system chrome (window buttons, title bar, toolbar overflow, sheet container, scroll bar, menu bar), and contains no app-supplied text;
  - it is a `.contrast` issue on a disabled control (WCAG 1.4.3 exempts inactive components);
  - it matches an `AuditAllowlist` entry `{ auditType, elementIdentifier or role, surface, reason, feedback: "FB…", reproducedIn: "minimal sample", date }` for a framework defect reproduced outside the app.
  
  Each ignored issue is written to an attachment `a11y-ignored-<surface>.txt`. An allowlist entry that matches nothing during the whole run fails the test as stale. An issue on an element with an app identifier, or with app text, is never ignored by the first two rules. (source: PRD §11 "never weaken a gate"; HIG "Accessibility")

## 9. Localization completeness

- **A11Y-032** {M12} [M][W][P] Populating the catalog from the command line: with `SWIFT_EMIT_LOC_STRINGS = YES` (already set for the app target), every app build writes one `.stringsdata` per source file under `build/DD/Build/Intermediates.noindex/SpaceTraderMac.build/<config>/SpaceTraderMac.build/Objects-normal/<arch>/`. `xcrun xcstringstool sync SpaceTraderMac/Resources/Localizable.xcstrings --stringsdata <file>…` merges them into the catalog, which is what the IDE does on build. A trial sync on 2026-11-17 added 2,054 keys. `scripts/l10n-check.sh --fix` runs this in place on the committed catalog. It then sets source-language (`en`) units from `new` to `translated` only when their value is the mechanical positional form of the key (`%1$@ %2$@` for `%@ %@`), leaving any other `new` unit for human review. The populated catalog is reviewed and committed. App-hosted unit test (`LocalizationCatalogTests`) parses the committed catalog: it has a non-empty `strings` table, `sourceLanguage` "en" and every key the tests' fixture texts use (menu titles from `MenuCatalog`, section titles, `ReasonText` for one `CommandError`). (source: PRD §9 M12 "localization completeness"; `xcstringstool sync --help`)
- **A11Y-033** {M12} [UI] [M][W][P] **The localization check** (`scripts/l10n-check.sh`, exit 0 iff clean, ends with `L10N CHECK PASS` or `L10N CHECK FAIL`):
  1. collects the app target's `.stringsdata` from `build/DD` whose `source` file still exists (deleted files leave orphans behind) and includes `ExtractedAppShortcutsMetadata.stringsdata`;
  2. copies the catalog to `build/l10n/`, syncs the copy and fails if it differs from the committed catalog ("catalog out of date: run scripts/l10n-check.sh --fix and review");

## 12a. Implementation notes (M12, 2026-11-17)

- A11Y-024 `[verify]` resolved: the guard test renders `Text("Parsec").font(.body)` at 16 pt under both `.large` and `.accessibility3`, so `BLOCKED: dynamicTypeSize has no effect on macOS`. The fallback is in place behind the same setting: `AppTextSize` publishes `textScale` (0.85…2.0, `TextSizeSetting.scale`) and the scaled body font, and every text style in the app goes through `.scaledFont(_:)` (`Accessibility/TextScale.swift`). `.dynamicTypeSize` is still applied for anything that honours it.
- A11Y-026 `[verify]` resolved: the macOS SDK has no `.textClipped` (nor `.dynamicType` or `.trait`) audit type; flow 7 uses the spec's fallback check. A11Y-006's traits are therefore checked by the `.parentChild`, `.sufficientElementDescription` and `.action` audits of flow 6 plus the code (header traits on titles, `.isImage` on labelled art).
- A11Y-005 `[verify]` resolved: `XCUIElement` exposes no hint on macOS; the hints are the pure `AccessibilityHints` strings (unit-tested) applied with `.accessibilityHint`.
- A11Y-029 contrast: the system `.secondary`, green, orange and red measure below 4.5:1 for small text on white; app text uses `.readableSecondary` and the `signalGreen`/`signalRed`/`signalOrange` colours (`DisplayStyles.swift`), and grouped-form values use `ReadableLabeledContentStyle`.
- A11Y-030 rule 1 in code: an issue is system chrome when it has no app identifier and no text and is unresolvable, a chrome role (scroll bar, menu, toolbar, window, sheet, split group, help tag, or a slider knob / stepper arrow AppKit draws inside a labelled control), a window/sheet/split-view pane container (at least 90% of its container's height, top-aligned), or a group AppKit builds around a table cell or header cell.
- A11Y-029 scope: `performAccessibilityAudit` covers the whole app, so each issue is classified against a snapshot of the surface's container (its sheet, else its window). Elements outside it — the window or sheet dimmed behind a sheet (the innermost sheet is the surface), other windows, rows scrolled out of a scroll view's visible area, text only partly drawn at a scroll view's edge (a row half under the status bar), and anything under the Dock — are recorded as ignored ("outside the audited surface"), because the same element is audited, undimmed and on screen, on the surface that shows it. Before each audit the app is brought to the front only if it is not already (activating again would make the main window key and dim the titles of the About, Help and Settings windows) and the pointer parked outside the window (no help tag over the content); a surface with failures is audited once more, and only the second result counts (a real failure fails both times; another app's window passing over the main window during the first audit does not).
- A11Y-029 fixes in the app: SwiftUI's `Menu` and menu-style `Picker` expose no press action on macOS 27 ("Action is missing" for each); the target picker, the Galaxy heatmap and "Sells…" filter, the Logbook filter and the Settings Text Size / Arrival report choices are AppKit `NSPopUpButton`s (`PopUpMenuButton`). Every `LazyVGrid` is a labelled container (`AccessibleLazyVGrid`); gauges and bars are progress elements (`accessibilityRepresentation`); compound rows and combined labels carry a role trait.
- A11Y-040/041: the shell recipe finds menu items and tab segments by English title. Under a pseudolanguage, `ParsecUITestCase.pseudoLocalized` makes those lookups match the title's pseudo forms instead (doubled "Game Game", or accented and bounded "[# G̈a̧m̧ë #]", compared diacritic-insensitively), which is the catalog-key mapping through the pseudolanguage transform; every other step already goes by identifier. Deviation: the run walks the shell group (sections, sheets, windows), not the encounter groups.
- A11Y-040 `[verify]` resolved: the pseudolanguage defaults apply to string-catalog strings, and also to keys missing from the catalog (any bundle lookup is transformed). The bounded run therefore catches strings that bypass localization (`Text(verbatim:)`, plain `String`s), while missing catalog keys are caught by A11Y-033. Foundation quirks seen in the screenshots: with doubled strings the first copy of a positional format shows its raw specifiers ("Day 1$@ · 2$@ Day 0 · Sol"); accenting mangles positional `lld` specifiers and plural or substitution formats ("[# @v a̧l̀u̥ë@ #]"), so those strings lose their numbers. String lengths, and so the layout check, are still representative.
- A11Y-041: the data names are in `SpaceTraderMacUITests/UITestFixtures+Names.swift`: all system and crew names, the Quick Start and flow commanders and, a deviation, the people credited in About. `LocalizationCatalogTests` checks them against `GameNames`, `GameSession.defaultCommanderName` and `AboutContent.credits`. Units counted as data: `cr.`, `pc`, `ly`, `d`, `x` and galaxy-code letters. The Help page body (`help.content`) is exempt, because it is localized as a whole file per language (A11Y-033 step 5) and the pseudolanguages do not reach it. The first bounded run found one hard-coded word, the "and" in the About credit "Sam Anderson and Samuel Goldstein". That credit is now a localized "%@ and %@".
- A11Y-032: the populated catalog has 2,220 keys. `--fix` also marks source-language `stringSet` units (the App Shortcuts phrases) translated when their only value is the key. Of the 151 count-bearing keys, 60 have plural variations (substitutions where the key has other arguments). The other 91 are in `scripts/l10n-allowlist.txt`, where no noun that inflects follows the number. Allowlist format: one key per line as a JSON string literal, then the reason.
- A11Y-033 step 2 compares the parsed catalogs, because `xcstringstool sync` does not rewrite a file it does not change. The script writes catalogs in Xcode's own serialization (byte-identical to the tool's output).
- A11Y-034: `-exportLocalizations` needs `-scheme SpaceTraderMac` when given `-derivedDataPath build/DD`. `[verify]` resolved: the export does not rewrite the catalog. Deviation: the script compares the catalogs' checksums before and after the export instead of `git diff --exit-code`, because verify runs before the commit, when catalog edits are still uncommitted.
