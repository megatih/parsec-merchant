# CHEAT: Cheats & debug

> Format (PRD §7): `- **ID** {Mn} [M][W][P] statement (source)`. `[M]` Modern, `[W]` Windows 2.01, `[P]` Palm 1.2.2. `[UI]` marks requirements covered by app or UI tests.
> Milestones: the engine side of every cheat (`Command.cheat`, parsing, effects, flagging) is {M6}; the cheat console sheet, the Find field hook and the debug launch arguments are {M7} [UI]; the developer tester sheet is {M9} [UI]; achievements gating is {M10}.
> C# sources are relative to `/Users/megatih/Downloads/SpaceTraderSource201` (read with `iconv -f cp1252 -t utf-8`); Palm sources are `docs/reference/palm-src/Src/…`. Every citation was re-read on 2026-11-17.
> **Classic behaviour.** C#: typing `Cheetah` in the Find box (Form_SpaceTrader.cs `btnFind_Click`, :3280-3530) sets `Game.CheatEnabled`, which unlocks 30 more Find codes and blocks the high-score entry. Palm 1.2.2 (`_STRA_CHEAT_` defined, Src/spacetrader.h:43): the Galactic Chart Find box accepts `Moolah`, `Very rare`, `Cheetah`, `Go <system>`, `Quests` and `Timewarp` without any unlock; `Cheetah` only reveals a Cheat button on the next Commander Status visit. Original Palm never blocks the high score for cheating, only for a Timewarp reload.
> **Parsec Merchant rule (PRD §8.3, normative):** every cheat, in every ruleset, sets `GameState.cheatsUsed` permanently. That flags the save, disables achievements and keeps the game out of the high-score table (SCORE-034, RUL-150).
> Ownership: the direct-warp pipeline is TRV-085; high-score eligibility is SCORE-034/035; save flags are SAV-002; the reload rules used by Palm's Timewarp are SAV-035. This spec owns the cheat codes, their parsing and effects, and the debug launch arguments.
> Notation: `n1`, `n2` = the integers parsed from the second and third word (CHEAT-008); "clamp(x, a, b)" = `min(b, max(a, x))`.

## 1. Command, flagging and availability

- **CHEAT-001** {M6} [M][W][P] Cheats are performed with `Command.cheat(CheatCode)`. An accepted cheat command sets `state.cheatsUsed = true` (if it was not already) and emits `GameEvent.cheatUsed` followed by any effect events; read-only codes (listings) set the flag too. A rejected cheat command changes nothing, including `cheatsUsed`. (source: Form_SpaceTrader.cs:3510-3513, Game.cs:3298-3308; PRD §8.3)
- **CHEAT-002** {M6} [M][W][P] `cheatsUsed` can never be cleared: no `Command` resets it, a new game starts with `false`, and save, load, migration, export and import keep it (SAV-028). (source: Game.cs:61, :170, :3070; PRD §8.3)
- **CHEAT-003** {M6} [M][W][P] Consequences tested together: after `.cheat(.enable)` a qualifying retirement reports `HighScoreOutcome.excludedForCheats` and is not stored (SCORE-034), and the save summary has `cheatsUsed == true` (SAV-002). In Palm this deliberately departs from the original, which let cheaters onto the table (RUL-150). (source: Form_SpaceTrader.cs:2826-2837; Palm: Src/Traveler.c:301-337; PRD §8.3)
- **CHEAT-004** {M10} [M][W][P] A game with `cheatsUsed` unlocks no achievements, and its events do not count toward progress (ACH folds skip it from the step where the flag is set onward, and the whole game once it is set). (source: PRD §6.6 "disabled when cheats are used"; UX-VISION §4.10)
- **CHEAT-005** {M6} [M][W][P] Cheat commands are accepted only while `phase == .docked` with no pending decision (the classic Find box exists only on the docked main screen and the Galactic Chart). Anything else is rejected with `.notAllowedInPhase`, except `dismissEncounter` (CHEAT-037). A game that has ended rejects them with `.gameOver` (SCORE-013). (source: Form_SpaceTrader.cs:3049 (`btnFind` shown only in the docked view); Palm: Src/WarpFormEvent.c:569)
- **CHEAT-006** {M6} [M][W][P] No cheat draws from the game RNG or the news RNG, except the C# `Go` direct warp, which runs the arrival pipeline and makes that pipeline's draws (TRV-085). A test applies every other code and checks that `state.rng` is unchanged. (source: Form_SpaceTrader.cs:3298-3500; Palm: Src/WarpFormEvent.c:592-697, Src/CmdrStatusEvent.c:149-226)
- **CHEAT-007** {M6} [M][W][P] Which codes exist is ruleset content (`content.cheatSet`): `.windows` (the C# codes of §3) in Modern and Windows 2.01, `.palm` (the codes of §4) in Palm 1.2.2. A `CheatCode` that is not in the ruleset's set is rejected with `.invalidArgument`. (source: PRD §4.1 "branch on flags or content")
- **CHEAT-008** {M6} [M][W][P] Cheats are allowed in an Ironman game. The game stays Ironman, gets `cheatsUsed`, and is excluded from the high-score table and achievements like any other cheated game. The Palm Timewarp reload stays refused in Ironman (CHEAT-046). (source: PRD §4.3, §8.3)

## 2. Parsing the Find text

- **CHEAT-009** {M6} [M][W][P] `FindInput.parse(_ text: String, cheatSet: CheatSet, cheatsEnabled: Bool) -> FindInput` (ParsecEngine, pure) turns what the player typed into the Find field into `.search(String)`, `.cheat(CheatCode)` or `.timewarp`. All code words are case-sensitive, as in both sources (C# `switch` on strings, Palm `StrCompare`). (source: Form_SpaceTrader.cs:3286-3300; Palm: Src/WarpFormEvent.c:592-704)
- **CHEAT-010** {M6} [M][W] C# splitting: the text is split on the single character `' '` (so two spaces in a row produce an empty word). `first`, `second` and `third` are words 0–2, or `""` when missing; further words are ignored. `n1` and `n2` are `second` and `third` parsed as a C# `int` (optional sign, decimal digits, in Int32 range), or 0 when that fails (`Functions.IsInt`). (source: Form_SpaceTrader.cs:3288-3294, Functions.cs:171-185)
- **CHEAT-011** {M6} [M][W] With `cheatsEnabled == false`, the only cheat is `first == "Cheetah"` → `.cheat(.enable)`; any other text, including the other code words, is `.search(text)`. With `cheatsEnabled == true`, a `first` equal to one of the 30 code words of §3 gives that code, and any other `first`, including `"Cheetah"`, is `.search(text)`. `cheatsEnabled` is `state.cheatsUsed`, the equivalent of C# `CheatEnabled`. (source: Form_SpaceTrader.cs:3298-3517)
- **CHEAT-012** {M6} [P] Palm matching is on the whole text, with no unlock needed: exactly `"Moolah"`, `"Very rare"`, `"Cheetah"`, `"Quests"` or `"Timewarp"`, or a text that starts with `"Go "` and is longer than 3 characters (→ `palmGo(rest)` with `rest` = the text after `"Go "`). Any other text is `.search(text)`; an empty text cancels and gives nothing (Palm treats an empty field as Cancel). (source: Palm: Src/WarpFormEvent.c:577-581, :592-704)
- **CHEAT-013** {M7} [UI] [M][W][P] The ⌘F context search sends `FindInput.parse` of its text: `.search` performs the normal system search (MAP), `.cheat` performs the command, and `.cheat(.enable)` (or Palm `Cheetah`) opens the **cheat console** sheet. The console states that the save is now flagged and offers every code of the ruleset's set as a labelled form (numeric fields pre-filled with current values, pickers for slots, item types, quests and mercenaries). Classic "Cheater!" and plain-text readouts become console content (ALR-001, ALR-024). (source: UX-VISION §12 "FormFind + Cheetah"; Form_Alert.cs:340-341)

## 3. Windows 2.01 / Modern codes

Each code below is accepted only when `cheatsUsed` is already true (CHEAT-011). The engine applies exactly the listed change.

- **CHEAT-014** {M6} [M][W] `enable` ("Cheetah"): sets `cheatsUsed` and changes nothing else. (source: Form_SpaceTrader.cs:3510-3513)
- **CHEAT-015** {M6} [M][W] `bazaar(n1)` ("Bazaar n"): `chanceOfTradeInOrbit = clamp(n1, 0, 1000)`. (source: Form_SpaceTrader.cs:3302-3304; Game.cs:987)
- **CHEAT-016** {M6} [M][W] `cover(slot: n1, shield: n2)` ("Cover i j"): if `0 ≤ n1 <` the ship type's shield slot count and `0 ≤ n2 <` the number of shield types in the ruleset table (3: Energy, Reflective, Lightning), shield slot `n1` becomes a new shield of type `n2` at full charge, replacing what was there or filling an empty slot. Otherwise nothing changes. (source: Form_SpaceTrader.cs:3305-3308; Consts.cs:213-219, Shield.cs:42-49)
- **CHEAT-017** {M6} [M][W] `deLorean(n1)` ("DeLorean n"): `commander.days = max(0, n1)`. Nothing else is recomputed. (source: Form_SpaceTrader.cs:3309-3311)
- **CHEAT-018** {M6} [M][W] `diamond` ("Diamond"): toggles `ship.hullUpgraded`. The current hull value is not adjusted, so it can exceed the new hull strength until the next repair or damage. (source: Form_SpaceTrader.cs:3312-3314)
- **CHEAT-019** {M6} [M][W] `energize` ("Energize"): toggles `quests.canSuperWarp` (the portable singularity). (source: Form_SpaceTrader.cs:3315-3317)
- **CHEAT-020** {M6} [M][W] `events` ("Events" with any second word other than `Reset`): emits `GameEvent.cheatReadout(.remainingVeryRare(list))` with `veryRareEncounters` in their stored order and changes nothing else. `eventsReset` ("Events Reset"): resets `veryRareEncounters` to the full list in the order Marie Celeste, Captain Ahab, Captain Conrad, Captain Huie, Dated (bottle old) Tonic, Good Tonic. (source: Form_SpaceTrader.cs:3318-3330, Game.cs:2991-3000, Strings.cs:1029-1038)
- **CHEAT-021** {M6} [M][W] `fame(n1)` ("Fame n"): `commander.reputationScore = max(0, n1)`. (source: Form_SpaceTrader.cs:3331-3333)
- **CHEAT-022** {M6} [M][W] `go(second)` ("Go name"): first selects, as the warp target, the lowest-index system whose name contains `second` case-insensitively (an empty `second` matches system 0); if none matches, the target is unchanged. Then, only if the selected system's name equals `second` case-insensitively, it performs the direct warp of TRV-085 to it (no fuel, cost, day, rip or encounters; the departure countdown, news reset, price calculation and full arrival pipeline do run). A partial match only changes the target. (source: Form_SpaceTrader.cs:3334-3346, Game.cs:3212-3220, :4302-4318)
- **CHEAT-023** {M6} [M][W] `ice(kind, n2)` ("Ice Pirate|Police|Trader n"): sets `commander.killsPirate`, `killsPolice` or `killsTrader` to `max(0, n2)`. Any other second word changes nothing, but the command is still accepted. (source: Form_SpaceTrader.cs:3347-3362)
- **CHEAT-024** {M6} [M][W] `indemnity(n1)` ("Indemnity n"): `commander.noClaim = max(0, n1)`. (source: Form_SpaceTrader.cs:3363-3365)
- **CHEAT-025** {M6} [M][W] `iou(n1)` ("IOU n"): `commander.debt = max(0, n1)`. (source: Form_SpaceTrader.cs:3366-3368)
- **CHEAT-026** {M6} [M][W] `iron(slot: n1, weapon: n2)` ("Iron i j"): if `0 ≤ n1 <` the ship type's weapon slot count and `0 ≤ n2 <` the number of weapon types (6: Pulse, Beam, Military, Morgan's, Photon, Quantum), weapon slot `n1` becomes a new weapon of type `n2`. Otherwise nothing changes. (source: Form_SpaceTrader.cs:3369-3372; Consts.cs:367-375)
- **CHEAT-027** {M6} [M][W] `juice(n1)` ("Juice n"): `ship.fuel = clamp(n1, 0, fuel tanks)`. (source: Form_SpaceTrader.cs:3373-3375)
- **CHEAT-028** {M6} [M][W] `knack(mercenary: n1, skills: third)` ("Knack id p,f,t,e"): if `0 ≤ n1 < mercenaries.count` (C# `CrewMemberId` order, so 0 is the commander and special crew are not excluded), `third` is split on `','` and, for each of the first 4 parts that parses as an int, that skill (pilot, fighter, trader, engineer in order) becomes `clamp(value, 1, 10)`. Parts that don't parse leave their skill unchanged. Prices are not recalculated. (source: Form_SpaceTrader.cs:3376-3386; Consts.cs:69)
- **CHEAT-029** {M6} [M][W] `lEngle(n1)` ("L'Engle n"): `quests.fabricRipProbability = clamp(n1, 0, 25)`. (source: Form_SpaceTrader.cs:3387-3389; Consts.cs:93)
- **CHEAT-030** {M6} [M][W] `lifeBoat` ("LifeBoat"): toggles `ship.escapePod`. (source: Form_SpaceTrader.cs:3390-3392)
- **CHEAT-031** {M6} [M][W] `monsterListing` ("Monster.com"): emits `GameEvent.cheatReadout(.monsterListing(…))` with three typed lists and changes nothing else: (a) every mercenary whose id is not a special crew id (Commander, Dragonfly, FamousCaptain, Jarek, Opponent, Princess, Scarab, Scorpion, SpaceMonster, Wild), with id, name, the 4 skills and a location that is `.crew` if aboard, `.system(id)` if placed, or `.unavailable`; (b) every system where `GameState.specialEventAvailable` is true, with its event; (c) every system with a shipyard, with the shipyard id. Lists are in id order; the app sorts them (mercenaries by name, the others by system name, as C# does by default) and selecting a system sets the warp target (`.selectTarget`). (source: Form_SpaceTrader.cs:3393-3395, Form_Monster.cs:630-659, :727-834; Consts.cs:283-295; QST-002)
- **CHEAT-032** {M6} [M][W] `planB` ("PlanB"): accepted, but changes nothing else, because Parsec Merchant always autosaves (SAV-038). In C# it set `Game.AutoSave`, the only way to enable autosave. (source: Form_SpaceTrader.cs:3396-3398, :3660-3680, Game.cs:3250-3260)
- **CHEAT-033** {M6} [M][W] `posse(slot: n1, mercenary: n2)` ("Posse slot id"): if `0 < n1 <` the ship's crew quarters, `0 < n2 < mercenaries.count` and `n2` is not a special crew id, mercenary `n2` is put in crew slot `n1` (replacing whoever is there, or filling the empty slot). Its own location is not updated, so it may also appear in a system or twice aboard (C# quirk, kept). If the ship's effective trader skill changed, buy prices at the current system are recalculated (ECO recalculation). Otherwise nothing changes. (source: Form_SpaceTrader.cs:3399-3408)
- **CHEAT-034** {M6} [M][W] `rapSheet(n1)` ("RapSheet n"): `commander.policeRecordScore = n1`, with no clamp (negative values allowed). `rarity(n1)` ("Rarity n"): `chanceOfVeryRareEncounter = clamp(n1, 0, 1000)`. `scratch(n1)` ("Scratch n"): `commander.cash = max(0, n1)`. `skin(n1)` ("Skin n"): `ship.hull = clamp(n1, 0, hull strength)`; a hull of 0 does not end the game by itself. (source: Form_SpaceTrader.cs:3409-3420)
- **CHEAT-035** {M6} [M][W] `status(quest, n2)` ("Status Q n"), where `Q` is exactly one of `Artifact`, `Dragonfly`, `Experiment`, `Gemulon`, `Japori`, `Jarek`, `Moon`, `Reactor`, `Princess`, `Scarab`, `Sculpture`, `SpaceMonster`, `Wild`: sets that `QuestState` field to `max(0, n2)` with no upper bound and no consistency check (status 0 if `n2` is missing). `statusList` ("Status" with any other or no second word) emits `GameEvent.cheatReadout(.questStatuses(…))` listing the 13 statuses in the order Artifact, Dragonfly, Experiment, Gemulon, Japori, Jarek, Moon, Princess, Reactor, Scarab, Sculpture, SpaceMonster, Wild, and changes nothing else. (source: Form_SpaceTrader.cs:3421-3483)
- **CHEAT-036** {M6} [M][W] `swag(item: n1, quantity: n2)` ("Swag i n"): if `0 ≤ n1 < 10` (trade item index), `cargo[n1] = clamp(n2, 0, freeCargoBays + cargo[n1])`. The cost basis (`priceCargo`) is not changed. `tool(slot: n1, gadget: n2)` ("Tool i j"): like CHEAT-026 for gadget slots and the 7 gadget types (Extra cargo bays, Auto-repair, Navigating, Targeting, Cloaking, Fuel compactor, Hidden cargo bays); the cargo is not checked against the new bay count. `varmints(n1)` ("Varmints n"): `ship.tribbles = max(0, n1)`. (source: Form_SpaceTrader.cs:3484-3497; Consts.cs:145-155)
- **CHEAT-037** {M6} [M][W] `yellow` ("Yellow"): sets `GameState.easyEncounters = true`; nothing turns it off. While it is set, `dismissEncounter` is accepted in `phase == .encounter` with no pending decision: the encounter ends with no state change from the encounter (no record, reputation, damage or RNG draw) and the trip resumes exactly as after an encounter that ended `.normal`. Without `easyEncounters`, or in any other phase, `dismissEncounter` is rejected with `.notAllowedInPhase`. This is C#'s close box (X) on the encounter window, whose `Continue` result simply continues the trip. (source: Form_SpaceTrader.cs:3498-3500, Form_Encounter.cs:135, :148-150, Game.cs:3129-3147, :3380-3390)
- **CHEAT-038** {M9} [UI] [M][W] `test` ("Test"): accepted, with no effect on game state. In Debug builds the app opens the developer tester sheet, which can present any ALR presentation and any special-event narrative sheet with sample values. In Release builds it only shows the console (C# `FormTest`: alert and special-event tester). (source: Form_SpaceTrader.cs:3488-3490, Form_Test.cs:263-292; UX-VISION §12 "FormMonster / FormTest")

## 4. Palm 1.2.2 codes

- **CHEAT-039** {M6} [P] `moolah` ("Moolah"): `commander.cash += 100000`. (source: Palm: Src/WarpFormEvent.c:592-595)
- **CHEAT-040** {M6} [P] `veryRare(happened:chanceOfVeryRare:chanceOfTradeInOrbit:)` ("Very rare" form): `veryRareEncounters` becomes the encounters *not* in `happened`, in canonical order (Palm keeps a bitmap of encounters that already happened: Marie 1, Ahab 2, Conrad 4, Huie 8, bottle old 16, bottle good 32). A non-nil chance (Palm: a non-empty field, 0–99999) replaces `chanceOfVeryRareEncounter` or `chanceOfTradeInOrbit` with no clamp; nil keeps it. Palm restores both chances to 5 and 100 at every load (SAV-037). (source: Palm: Src/WarpFormEvent.c:596-637, Src/spacetrader.h:294-299, Src/Global.c:623-625)
- **CHEAT-041** {M6} [P] `enable` ("Cheetah"): sets `cheatsUsed` and makes the Palm cheat form available in the console for the rest of the game. Palm showed the Cheat button only on the next Commander Status visit (`CheatCounter` 3, reset to 0 on opening); that one-shot visibility is presentation and is not kept. (source: Palm: Src/WarpFormEvent.c:639-642, Src/CmdrStatusEvent.c:110-115, :133-136)
- **CHEAT-042** {M6} [P] `palmCheatForm(PalmCheatForm)` applies Palm's Cheat form in this order: credits, debt and reputation each replaced when given (nil keeps); police record = the given magnitude if any, else the current record, and then negated if `policeRecordNegative` is set (so with no magnitude and the box checked, a negative record becomes positive, as in Palm); moon: `quests.moon` becomes "bought" when checked and it was "not started", and "not started" when unchecked and it was "bought"; `canSuperWarp` = the singularity box. Requires `cheatsUsed` (set by `enable`), else `.invalidArgument`. (source: Palm: Src/CmdrStatusEvent.c:149-194, :224)
- **CHEAT-043** {M6} [P] Cheat form equipment boxes, each applied only when the box differs from the current state: Lightning shield checked and none aboard, with at least one shield slot → shield slot 0 becomes a Lightning shield whose charge is left as slot 0 had it (0 if it was empty); unchecked while aboard → **every** Lightning shield becomes a Reflective shield with its charge unchanged. Fuel compactor: same with gadget slot 0, and unchecking turns every compactor into an **Auto-repair system**. Morgan's laser: same with weapon slot 0, and unchecking turns every Morgan's laser into a **Beam laser**. (Palm writes index 1 of each table, so these replacements are quirks kept as-is.) (source: Palm: Src/CmdrStatusEvent.c:195-223, Src/spacetrader.h:117-145)
- **CHEAT-044** {M6} [P] `palmGo(rest)` ("Go name"): finds the lowest system index `i` whose name compares ≥ `rest` under ASCII case-insensitive lexicographic order (Palm `StrCaselessCompare`; the Palm name table is alphabetical, so this is the first name not sorting before `rest`) and sets `commander.currentSystem = i`. Nothing else changes: no arrival pipeline, no visited flag, no price recalculation, no countdown, news or day. If no name qualifies, nothing changes except the flag. (source: Palm: Src/WarpFormEvent.c:643-658, Src/Traveler.c:1400)
- **CHEAT-045** {M6} [P] `quests` ("Quests"): emits `GameEvent.cheatReadout(.palmQuestLocations(…))` and changes nothing else. For each label (Dragonfly, Monster, Disease, Artifact, Tribbles, Reactor, Jarek, Invasion, Experiment, Wild, Scarab), the system is the highest-index system whose special event is the matching one; later matches overwrite earlier ones, as in Palm's loop. Artifact matches the artifact pickup, or the artifact delivery (labelled "Berger") when the artifact is aboard; Scarab matches the Scarab event, or the Scarab-destroyed event while the Scarab status is 1. Labels with no match are omitted. (source: Palm: Src/WarpFormEvent.c:659-697)
- **CHEAT-046** {M7} [UI] [P] `.timewarp` ("Timewarp") is not an engine command and does not set `cheatsUsed`. In a non-Ironman Palm game the app opens Open Saved Game, first warning that loading a save keeps this game off the high-score table when `reloadCount == 0` (Palm `DisableScoringAlert`), or asking for confirmation otherwise (`ReallyLoadAlert`). The load then follows SAV-034/035, and SCORE-035 applies. In an Ironman game the app refuses with an explanation. (source: Palm: Src/WarpFormEvent.c:700-722, Src/Traveler.c:331-332, :352-356)

## 5. Debug launch arguments (app level)

- **CHEAT-047** {M7} [UI] [M][W][P] Launch arguments are read by the app only, never by the engine. They are honoured only in Debug builds, except `-PMScenario smoke`, which the Release build accepts for the M13 smoke test (PRD §9 M13). (source: PRD §6.5 "Debug-only launch arguments", §9 M13; CLAUDE.md)
- **CHEAT-048** {M7} [UI] [M][W][P] `-PMSeed <n>` makes New Game and Quick Start use seed `n` (a UInt64), so the galaxy is reproducible. It does not set `cheatsUsed`, because the seed is public through the galaxy code anyway. (source: PRD §6.5, §6.6 "Galaxy code")
- **CHEAT-049** {M7} [UI] [M][W][P] `-PMScenario <name>` starts the app directly in a named fixture state, and every such game has `cheatsUsed = true` because its state was not reached by play. `smoke` creates a game, saves it to a slot, loads it back in the sandbox, checks that the loaded state equals the saved one and exits with status 0 (non-zero on any failure). An unknown name exits with a non-zero status. (source: PRD §6.5, §9 M13)
- **CHEAT-050** {M7} [UI] [M][W][P] `-PMFlavor template` forces `TemplateFlavorProvider`; `-PMFastTravel` makes the transit animation instant (like the Fast travel setting); `-PMAudio off` disables audio and haptics output. None of the three changes game state, RNG draws or `cheatsUsed`. (source: PRD §6.5, §6.6; UX-VISION §5.1)
- **CHEAT-051** {M7} [UI] [M][W][P] `-PMResetState` deletes, before anything is loaded, everything under the Debug build's `Application Support/Parsec Merchant/` (Saves, Corrupt, HighScores.json, achievements, designer templates) and its UserDefaults domain. It is the only code path that deletes `Corrupt/` (SAV-024). The Release bundle id has a separate container, so Release data is untouched. (source: PRD §6.5; CLAUDE.md "Debug bundle id ends in `.debug`")

## 6. API names proposed by this spec

Beyond the decided `Command.cheat(CheatCode)` and `GameState.cheatsUsed`:
- `CheatCode` cases: `enable`, `bazaar(Int)`, `cover(slot:shield:)`, `deLorean(Int)`, `diamond`, `energize`, `events`, `eventsReset`, `fame(Int)`, `go(String)`, `ice(KillKind, Int)`, `indemnity(Int)`, `iou(Int)`, `iron(slot:weapon:)`, `juice(Int)`, `knack(mercenary:skills:)`, `lEngle(Int)`, `lifeBoat`, `monsterListing`, `planB`, `posse(slot:mercenary:)`, `rapSheet(Int)`, `rarity(Int)`, `scratch(Int)`, `skin(Int)`, `status(QuestKey, Int)`, `statusList`, `swag(item:quantity:)`, `test`, `tool(slot:gadget:)`, `varmints(Int)`, `yellow`, `dismissEncounter`; Palm: `moolah`, `veryRare(happened:chanceOfVeryRare:chanceOfTradeInOrbit:)`, `palmCheatForm(PalmCheatForm)`, `palmGo(String)`, `quests`.
- `FindInput { search(String), cheat(CheatCode), timewarp }` with `FindInput.parse(_:cheatSet:cheatsEnabled:)` (CHEAT-009).
- `CheatSet { windows, palm }` as `Ruleset.content.cheatSet` (CHEAT-007).
- `GameState.easyEncounters: Bool` (CHEAT-037).
- `GameEvent.cheatUsed`, `GameEvent.cheatReadout(CheatReadout)` with `CheatReadout { remainingVeryRare([VeryRareEncounter]), questStatuses([(QuestKey, Int)]), monsterListing(MonsterListing), palmQuestLocations([(PalmQuestLabel, Int)]) }`.
- `PalmCheatForm { credits: Int?, debt: Int?, reputation: Int?, policeRecordMagnitude: Int?, policeRecordNegative: Bool, moon: Bool, lightningShield: Bool, fuelCompactor: Bool, morgansLaser: Bool, singularity: Bool }`.
