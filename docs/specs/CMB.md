# CMB: Combat

> Format (PRD §7): `- **ID** {Mn} [M][W][P] statement (source)`. `[M]` Modern, `[W]` Windows 2.01, `[P]` Palm 1.2.2.
> C# paths are relative to `/Users/megatih/Downloads/SpaceTraderSource201`. Palm paths are relative to `docs/reference/palm-src/`.
> **Modern = Windows 2.01 plus the closed MOD list (PRD §4.3).** A Windows quirk that no MOD entry fixes is tagged `[M][W]`.
> Every formula was re-read in the source on 2026-11-17. `[verify]` marks a statement that could not be confirmed fully.
> **Scope.** CMB owns the combat round, attack and flee *mechanics*, damage, disabling, escapes, the opponent's state changes caused by a round, continuous attack, kills, bounty, scooping and plunder. Police record and reputation *values* changed by attacking, fleeing, killing or plundering are listed in POL §3 and only referenced here. Initial reactions, opponent generation and the encounter-type button map are ENC.
>
> **Notation.** `D` = difficulty (Beginner 0, Easy 1, Normal 2, Hard 3, Impossible 4). `rand(n)` = one RNG draw `next(below: n)` (RNG-003/004: `rand(0) == 0` and still consumes one draw). `P`, `F`, `T`, `E` = a ship's **effective** Pilot, Fighter, Trader and Engineer skill (CRW-011 for [M][W], CRW-013 for [P]; the same function serves opponents, CRW-019). "Player" = the commander's ship. All divisions truncate. Encounter types use the engine `EncounterType` names; Palm codes map 1:1 (`POLICEINSPECTION` = `.policeInspect`, `POSTMARIEPOLICEENCOUNTER` = `.marieCelestePolice`, `FAMOUSCAPATTACK` = `.famousCaptainAttack`, …).

## 1. Encounter combat state and commands

- **CMB-001** {M3} [M][W][P] `EncounterState` holds, besides `type`, `opponent`, `opponentDisabled`, `round` and `clicks`: `cmdrFleeing` (C# `EncounterCmdrFleeing`), `oppFleeing` (`EncounterOppFleeing`), `cmdrHit` (`EncounterCmdrHit`, the player was hit this round), `oppHit` (`EncounterOppHit`), `oppFleeingPrev` (`EncounterOppFleeingPrev`), `continueAttacking` and `continueFleeing` (C# `EncounterContinue*`, Palm `AutoAttack`/`AutoFlee`) and `forceContinuous` (ENC-190). All are Codable so a save taken mid-encounter resumes exactly. (source: Game.cs:1142-1152, :3505-3520, :3615; Palm: Src/Encounter.c:894-904, Src/Global.c:661-663)
- **CMB-002** {M3} [M][W][P] When an encounter starts, `continueAttacking`, `continueFleeing`, `forceContinuous` and `opponentDisabled` are false. `cmdrFleeing` is set by every attack or flee command before a round runs, so its value from an earlier encounter is never read. (source: Game.cs:1093-1099, :1703, :1764; Palm: Src/Encounter.c:1474-1478, :1582-1586)
- **CMB-003** {M3} [M][W][P] `perform(.encounter(.attack))` is rejected with `CommandError.noWeapons` when the player's total weapon power (all weapon types) is 0. (source: Game.cs:1590-1594; Palm: Src/Encounter.c:1481-1485 `TotalWeapons(&Ship,-1,-1) <= 0`)
- **CMB-004** {M3} [M][W] `perform(.encounter(.attack))` is rejected with `CommandError.noLasers` when the opponent is not disableable (CMB-038) and the player's laser power (Pulse…Morgan's) is 0. (source: Game.cs:1595-1599)
- **CMB-005** {M4} [M][W] `perform(.encounter(.attack))` against the Scorpion is rejected with `CommandError.noDisruptors` when the player's disruptor power (Photon…Quantum) is 0. The three weapon checks run in the order CMB-003, CMB-004, CMB-005. (source: Game.cs:1600-1604)
- **CMB-006** {M3} [M][W][P] Attack type transitions (after the checks and any confirmation): `pirateIgnore`, `dragonflyIgnore`, `scarabIgnore`, `scorpionIgnore` and `spaceMonsterIgnore` become the matching `…Attack` type; police types follow POL-030; trader types follow CMB-007/CMB-008; `captainAhab/Conrad/Huie` become `famousCaptainAttack` (POL-033/POL-034). Every other type (an `…Attack` type, `pirateFlee`, `pirateSurrender`, `…Disabled`, `traderFlee`, `policeFlee`) is left unchanged. A successful attack sets `cmdrFleeing = false` and then runs one round (§2). (source: Game.cs:1607-1704, Form_Encounter.cs:1216-1222; Palm: Src/Encounter.c:1487-1576)
- **CMB-007** {M3} [M][W] Trader reaction to an attack: for `traderBuy`, `traderIgnore` and `traderSell` (after the record change of POL-032) and for `traderAttack` and `traderSurrender`, the engine draws `r = rand(1500)` **first** and sets `type = (r <= reputation*10/(opponentType+1) || opponent weapon power == 0) ? .traderFlee : .traderAttack`. `traderFlee` is never re-rolled. Each manual attack command on an attacking trader therefore consumes one draw; a continuous-attack tick (CMB-066) does not. (source: Game.cs:1644-1667)
- **CMB-008** {M5} [P] Palm trader reaction: for every trader type except `traderFlee`, if the opponent has no weapons the type becomes `traderFlee` **without a draw**; otherwise `rand(1500) <= reputation*10/(1+opponentType)` → `traderFlee`, else `traderAttack`. (source: Palm: Src/Encounter.c:1527-1535)
- **CMB-009** {M3} [M][W][P] `perform(.encounter(.flee))` sets `cmdrFleeing = true` (after the POL-035…POL-038 confirmations and record changes for `policeInspect` and `marieCelestePolice`, both of which turn the type into `policeAttack`) and runs one round. An unacknowledged confirmation returns `PendingDecision.confirm(…)` and changes nothing, including `cmdrFleeing`. Flee is accepted only in the types ENC lists for the Flee button; elsewhere it is rejected with `encounterActionUnavailable`. (source: Game.cs:1762-1789, Form_Encounter.cs:1243-1249; Palm: Src/Encounter.c:1577-1622)

## 2. Round structure (who fires)

- **CMB-010** {M3} [M][W] One round (`EncounterExecuteAction`, engine `executeRound`) first records `prevPlayerHull`, `prevOpponentHull`, sets both hit flags false, copies `oppFleeing` into `oppFleeingPrev`, sets `oppFleeing = false` and increments `round`. Then, by the type at the start of the round: (a) `dragonflyAttack`, `famousCaptainAttack`, `marieCelestePolice`, `pirateAttack`, `policeAttack`, `scarabAttack`, `scorpionAttack`, `spaceMonsterAttack`, `traderAttack`: the opponent fires at the player with `defenderFleeing = cmdrFleeing`, then, if `!cmdrFleeing`, the player fires with `defenderFleeing = false`; (b) `pirateFlee`, `pirateSurrender`, `policeFlee`, `traderFlee`, `traderSurrender`: only the player fires (if `!cmdrFleeing`) with `defenderFleeing = true`, and `oppFleeing = true`; (c) every other type: only the player fires (if `!cmdrFleeing`) with `defenderFleeing = false`. (source: Game.cs:1142-1179)
- **CMB-011** {M5} [P] Palm round: the opponent fires at the player (with `Flees = cmdrFleeing`) in `pirateAttack`, `policeAttack`, `traderAttack`, `spaceMonsterAttack`, `dragonflyAttack`, `marieCelestePolice`, `scarabAttack` and `famousCaptainAttack`. Then, if the player is not fleeing, the player fires with `Flees = true` only in `policeFlee`, `traderFlee` and `pirateFlee`, and with `Flees = false` otherwise, **including `pirateSurrender` and `traderSurrender`** (RUL-092 `surrenderingTargetShot`). (source: Palm: Src/Encounter.c:907-929)
- **CMB-012** {M3} [M][W] Derived consequence of CMB-010: fleeing from `policeSurrender` (C#'s surrender demand, which only Modern/Windows have, RUL-086) runs a round in which nobody fires; only the escape roll (CMB-049) and the state update (CMB-054) happen. (source: Game.cs:1154-1179, Form_Encounter.cs:1118-1125)
- **CMB-013** {M3} [M][W][P] A round's result (`RoundResult`) is one of `.continue` (the encounter stays open), `.normal` (the encounter closes and transit resumes, TRV), `.escapePod` (POL §9), or `.killed` (game over, phase `.gameOver(.killed)`); `.arrested` only comes from surrender/yield/submit, never from a round. The engine never leaves the encounter phase on `.continue`. (source: Game.cs:1144, :1182-1252, :3130-3143; Palm: Src/Encounter.c:941-1062, :1286)

## 3. To-hit

- **CMB-014** {M3} [M][W] A shot hits iff NOT (`D == Beginner` and the defender is the player and `defenderFleeing`) AND (`attacker is the player && opponentDisabled && player has a Targeting System` OR `rand(F_att + size_def) >= (defenderFleeing ? 2 : 1) * rand(5 + P_def/2)`). `size_def` is the defender spec's size (Tiny 0 … Huge 4). The left `rand` is drawn before the right one; neither is drawn when an earlier operand decides the result. (source: Game.cs:1296-1300, ShipSpec size; research 01 §7)
- **CMB-015** {M5} [P] Palm to-hit: on Beginner a fleeing player is never hit (no draw); otherwise the shot misses iff `rand(F_att + size_def) < (Flees ? 2 : 1) * rand(5 + (P_def >> 1))`. There is no Targeting-System auto-hit (Palm has no disabling). (source: Palm: Src/Encounter.c:799-808)
- **CMB-016** {M3} [M][W][P] Example: attacker Fighter 6 against a Small (size 1) defender with Pilot 7 that is not fleeing: hit iff `rand(7) >= rand(8)`; with the defender fleeing: hit iff `rand(7) >= 2*rand(8)`. (source: Game.cs:1298-1300; Palm: Src/Encounter.c:804-805)

## 4. Weapon power

- **CMB-017** {M3} [M][W] Weapon power: Pulse 15, Beam 25, Military 35, Morgan's 85 (lasers, enum Pulse…Morgan's); Photon 20, Quantum 60 (disruptors, enum Photon…Quantum). `lasers` and `disruptors` are the summed powers of the attacker's installed weapons in each range; `weapons = lasers + disruptors`. (source: Consts.cs:367-375, Game.cs:1306-1319, Ship.cs:767-781)
- **CMB-018** {M3} [M][W] Against the Scarab, the Beam and Military lasers and the Photon disruptor are subtracted: `lasers -= power(Beam…Military)`, `disruptors -= power(Photon)`. Pulse, Morgan's and Quantum still count (kept as designed #14, RUL-091). (source: Game.cs:1309-1313)
- **CMB-019** {M5} [P] Palm weapons are Pulse 15, Beam 25, Military 35 and Morgan's 85; all count. Against the Scarab only Pulse and Morgan's count; if the attacker has neither, damage is 0 with no draw. (source: Palm: Src/Encounter.c:810-821, Src/Global.c:207-214, Src/spacetrader.h:118-124)

## 5. Damage

- **CMB-020** {M3} [M][W] If the player hits an opponent while `opponentDisabled` is true, the opponent's hull becomes 0 and nothing else in CMB-021…CMB-036 or CMB-039 happens for that shot (no damage roll, no disable check). (source: Game.cs:1302-1304)
- **CMB-021** {M3} [M][W] Disable attempt instead of damage: if the defender is disableable (CMB-038), its total shield charge is 0, `!opponentDisabled`, `options.disableOpponents` is on and `disruptors > 0`, then `disrupt = rand(disruptors * (100 + 2*F_att) / 100)`; no damage roll is made, the hull is not touched and the shot does **not** count as a hit. Then CMB-039 runs. (source: Game.cs:1321-1325)
- **CMB-022** {M3} [M][W] Otherwise `damage = weapons == 0 ? 0 : rand(weapons * (100 + 2*F_att) / 100)` (no draw when `weapons == 0`). The shot counts as a hit iff `damage > 0`; with `damage == 0` the hull is untouched but CMB-039 still runs. (source: Game.cs:1328-1333, RUL-090 `damageSkill`)
- **CMB-023** {M5} [P] Palm damage uses the attacker's **Engineer**: `damage = rand(weapons * (100 + 2*E_att) / 100)` (weapons per CMB-019; no draw when weapon power is 0). `damage <= 0` ends the shot as a miss. (source: Palm: Src/Encounter.c:810-825)
- **CMB-024** {M3} [W] Reactor aboard and the player is the defender: `damage *= (int)(1 + (D+1) * (D < Normal ? 0.25 : 0.33))`, i.e. ×1, ×1, ×1, ×2, ×2 for D = 0…4 (C# truncates the factor). (source: Game.cs:1336-1337, RUL-114)
- **CMB-025** {M5} [M][P] MOD-014: with the reactor aboard and the player as defender, `damage = trunc(damage * (1 + (D+1) * (D < Normal ? 0.25 : 0.33)))` in double arithmetic (factors 1.25, 1.5, 1.99, 2.32, 2.65). Examples: damage 3 → 3, 4, 5, 6, 7; damage 100 → 125, 150, 199, 232, 265. (source: PRD §4.3 MOD-014; Palm: Src/Encounter.c:827-834)
- **CMB-026** {M3} [M][W][P] Shields absorb in slot order: for each installed shield while `damage > 0`, `applied = min(charge, damage)`, `charge -= applied`, `damage -= applied`. Shield charge never goes negative and a later shield is only touched when the earlier ones are empty. (source: Game.cs:1339-1345; Palm: Src/Encounter.c:835-848)
- **CMB-027** {M3} [M][W] If `damage > 0` after the shields: `damage = max(1, damage - rand(E_def))`; `disrupt = damage * disruptors / weapons`; `damage -= disrupt` (only the laser share hurts the hull). (source: Game.cs:1350-1357)
- **CMB-028** {M5} [P] Palm hull damage after the shields: `damage -= rand(E_def)`, then `damage <= 0 → 1`. There is no disruptor share. (source: Palm: Src/Encounter.c:855-859)
- **CMB-029** {M3} [M][W] Hull-damage cap: `damage = min(damage, HullStrength_def / (defender is player ? max(1, 4 - D) : 2))`, with `HullStrength` including the +50 upgrade when the defender's ship has it (SHP-018). Divisors: Beginner 4, Easy 3, Normal 2, Hard 1, Impossible 1; opponents always 2. (source: Game.cs:1360-1364, ShipSpec.cs:282-288)
- **CMB-030** {M5} [P] Palm cap: the same divisors, but the dividend is the defender's **base** spec hull, except when the player is the defender and `ScarabStatus == 3`, where it is the upgraded hull (`GetHullStrength()`, SHP-019). (source: Palm: Src/Encounter.c:860-866)
- **CMB-031** {M3} [W] Hardened hull: after the cap, if `QuestStatusScarab == 3` then `damage /= 2` for **every** defender, opponents included, and also for a Flea obtained after the escape pod (the status survives the pod, RUL-099). (source: Game.cs:1367-1368, RUL-104)
- **CMB-032** {M5} [M] MOD-004: the halving applies only when the defender is the player's ship and `QuestStatusScarab == 3`. (source: PRD §4.3 MOD-004, RUL-104)
- **CMB-033** {M5} [P] Palm never halves hull damage; the upgraded hull only raises the cap (CMB-030). (source: Palm: Src/Encounter.c:855-868, RUL-104)
- **CMB-034** {M3} [M][W][P] `hull = max(0, hull - damage)`. (source: Game.cs:1370; Palm: Src/Encounter.c:867-869)
- **CMB-035** {M3} [M][W] Example (Windows, Normal): a Gnat opponent (hull 100, no shields, Engineer 4) is hit by a player with two Pulse lasers (30) and Fighter 5: `damage = rand(30*110/100) = rand(33)`; a roll of 20 gives `max(1, 20 - rand(4))`, e.g. 18, capped at `100/2 = 50`, so hull 82. With the Scarab quest done (Windows) it becomes 9, hull 91; in Modern it stays 18. (source: Game.cs:1328-1370)
- **CMB-036** {M3} [M][W][P] Overflow guard: `weapons * (100 + 2*skill)` stays far below Int32 for every ship in the tables and every custom design (a few weapon slots of at most 85 power, effective skills well under 50), so the damage path needs no wrapping arithmetic. (source: Consts.cs:367-375, CRW-002)
- **CMB-037** {M3} [M][W][P] The damage path reads only the attacker's and defender's own ships, skills and the difficulty, never `ruleset.id`; the Fighter/Engineer choice, the Scarab weapon set, the reactor factor, the cap dividend and the halving scope are `RuleFlags` (`damageSkill`, `scarabVulnerableWeapons`, `reactorDamageRealFactor`, `palmHullCapDividend`, `hullHardeningScope`). (source: PRD §4.1, RUL-090/091/104/114) [verify: `palmHullCapDividend` needs a RUL row]

## 6. Disabling (Modern and Windows only)

- **CMB-038** {M3} [M][W] A ship is disableable iff it is not the player's ship and its type is not Bottle, Mantis or Space Monster. The Dragonfly, Scarab, Scorpion, famous captains, police, pirates and traders are disableable. (source: Ship.cs:905-912)
- **CMB-039** {M3} [M][W] Disable check after every player shot that reached the damage stage (CMB-021/CMB-022, hit or not): if `hull_def > 0` and the defender is disableable, draw `rand(100)`; if it is `< disrupt * 3 * 100 / hull_def` then `opponentDisabled = true`. The draw happens even when `disrupt == 0` (no disruptors), so it consumes RNG on every such shot. `disrupt` is 0 unless set by CMB-021 or CMB-027. (source: Game.cs:1372-1379, Consts.cs:100 `DisruptorSystemsMultiplier = 3`)
- **CMB-040** {M3} [M][W] `options.disableOpponents` defaults to false and only gates the no-damage disable attempt of CMB-021; the disruptor share of CMB-027 can disable an opponent with the option off. (source: GameOptions.cs, Game.cs:1321-1324, :1355, :1377)
- **CMB-041** {M5} [P] Palm has no disruptors, no `opponentDisabled` state and no disable draw; RUL-015 removes the option and all `…Disabled` types from the Palm ruleset. (source: Palm: Src/Encounter.c:793-889, RUL-015)
- **CMB-042** {M4} [M][W] The Scorpion never dies: after any player shot, if the defender is the Scorpion and its hull is 0, hull becomes 1 and `opponentDisabled = true`. (source: Game.cs:1381-1386)
- **CMB-043** {M3} [M][W] `opponentDisabled` stays true for the rest of the encounter (only CMB-002 clears it), and a disabled opponent never fires (the `…Disabled` types fall under CMB-010 (c)). (source: Game.cs:1093-1099, :1154-1179)

## 7. Round outcome

- **CMB-044** {M3} [M][W] Outcome order after the shots: (1) if the player's hull ≤ 0: with an escape pod the result is `.escapePod` (POL §9); otherwise the engine emits `GameEvent.bothDestroyed` if the opponent's hull is also ≤ 0, else `GameEvent.playerDestroyed`, and the result is `.killed` (phase `.gameOver(.killed)`); (2) else if `opponentDisabled`: CMB-045/CMB-046; (3) else if the opponent's hull ≤ 0: CMB-070 (won), result `.normal`; (4) else the escape checks (CMB-049…CMB-053). (source: Game.cs:1181-1252)
- **CMB-045** {M4} [M][W] A disabled Dragonfly, Scarab or Scorpion counts as defeated: Dragonfly → `pirateKills += 1`, record +1 (POL-040), Dragonfly status 5 (destroyed); Scarab → same kill and record, Scarab status 2 (destroyed); Scorpion → same kill and record, Princess status 4 (rescued). Then `GameEvent.opponentDisabled(ShipType)` (the Princess rescue is read from `quests.princess`), `reputation += opponentType/2 + 1`, result `normal` (the encounter ends). No bounty, no scoop. (source: Game.cs:1101-1120, :1195-1217)
- **CMB-046** {M3} [M][W] Any other disabled opponent: the state update CMB-054 runs (with its `rand(100)` draw), `oppFleeing = false`, `GameEvent.opponentDisabled(shipType)` is emitted and the result is `.continue`. No escape roll and no continuous-attack flag is set. (source: Game.cs:1218-1222)
- **CMB-047** {M3} [M][W] Port quirk (kept; RUL audit row needed): because CMB-044 tests `opponentDisabled` before the opponent's hull, shooting a disabled non-special opponent to hull 0 (CMB-020) never reaches `EncounterWon`: no kill, bounty, record change or scoop is applied, the type stays `…Disabled` and the encounter continues with a 0-hull wreck that can still be plundered (§13). (source: Game.cs:1193-1229, :1302-1304, Form_Encounter.cs:1129-1135) 
- **CMB-048** {M5} [P] Palm outcome order: (1) both hulls ≤ 0 → escape pod if owned, else `bothDestroyed` and game over; (2) opponent hull ≤ 0 → won (CMB-076); (3) player hull ≤ 0 → escape pod if owned, else `playerDestroyed` and game over; (4) escape checks. Any destruction clears `continueAttacking` and `continueFleeing`. (source: Palm: Src/Encounter.c:941-1056)
- **CMB-049** {M3} [M][W][P] Player escape: if `cmdrFleeing`, the player escapes when `D == Beginner` (no draw) or `(rand(7) + P_player/3) * 2 >= rand(P_opp) * (2 + D)` (left draw first). (source: Game.cs:1235-1241; Palm: Src/Encounter.c:1058-1092)
- **CMB-050** {M3} [M][W] Opponent escape (C#): if the player did not escape and `oppFleeing` (set this round by CMB-010 (b)), the opponent escapes when `rand(P_player) * 4 <= rand(7 + P_opp/3) * 2` (left draw first). This check also runs when the player was fleeing and failed. (source: Game.cs:1242-1247)
- **CMB-051** {M5} [P] Palm runs the opponent escape check (same formula) only when the player is **not** fleeing and the type is `policeFlee`, `traderFlee`, `pirateFlee`, `traderSurrender` or `pirateSurrender`. (source: Palm: Src/Encounter.c:1094-1108)
- **CMB-052** {M3} [M][W][P] An escape ends the encounter (result `.normal`), leaves no continuous attack/flee pending, and emits `GameEvent.playerEscaped(wasHit: cmdrHit)` or `GameEvent.opponentEscaped`. Damage dealt to a persistent special ship (Space Monster, Scarab, Dragonfly, Scorpion) persists: after every round the engine writes the opponent back to `specialShips` (Palm stores `MonsterHull = Opponent.Hull`; C# `Opponent` is a reference to the shared ship, Game.cs:786-811). (source: Game.cs:1237-1250; Palm: Src/Encounter.c:1061-1091; QST)
- **CMB-053** {M3} [M][W] If nobody escaped: the state update CMB-054 runs, then `oppFleeing = type ∈ {pirateFlee, pirateSurrender, policeFlee, traderFlee, traderSurrender}`, then CMB-064, and the result is `continue`. (source: Game.cs:1251-1283)

## 8. Opponent state update after a round

- **CMB-054** {M3} [M][W] `EncounterUpdateEncounterType` always draws `chance = rand(100)` first, then changes the type only if the opponent's hull dropped this round (`hull < prevOpponentHull`) or `opponentDisabled`. (source: Game.cs:1519-1523)
- **CMB-055** {M3} [M][W] Pirates (`pirateAttack`, `pirateFlee`, `pirateSurrender`): disabled → `pirateDisabled`; else if `hull < prevOpponentHull*2/3`: if the player's hull `< prevPlayerHull*2/3` then `chance < 60 → pirateFlee` (else unchanged); otherwise `chance < 10 && type != Mantis → pirateSurrender`, else `pirateFlee`. (source: Game.cs:1532-1551)
- **CMB-056** {M3} [M][W] Police (`policeAttack`, `policeFlee`): disabled → `policeDisabled`; else if `hull < prevOpponentHull/2 && (playerHull >= prevPlayerHull/2 || chance < 40)` → `policeFlee`. (source: Game.cs:1552-1558)
- **CMB-057** {M3} [M][W] Traders (`traderAttack`, `traderFlee`, `traderSurrender`): disabled → `traderDisabled`; else if `hull < prevOpponentHull*2/3`: `chance < 60 → traderSurrender`, else `traderFlee`; else if `hull < prevOpponentHull*9/10` and (`playerHull < prevPlayerHull*2/3 && chance < 20` or `playerHull < prevPlayerHull*9/10 && chance < 60` or `playerHull >= prevPlayerHull*9/10`) → `traderFlee`. (source: Game.cs:1559-1578)
- **CMB-058** {M3} [M][W] `famousCaptainAttack`: disabled → `famousCaptDisabled`; damage alone changes nothing. Every other type (Dragonfly, Scarab, Scorpion, Space Monster, `policeSurrender`, `…Disabled`, `marieCelestePolice`) is never changed by the update. (source: Game.cs:1525-1531, :1579-1581)
- **CMB-059** {M5} [P] Palm update (only if the opponent's hull dropped; no unconditional draw): police types: if `hull < prevOpponentHull >> 1` then (player hull `< prevPlayerHull >> 1` ? `rand(10) > 5 → policeFlee` : `policeFlee` without a draw); pirate types: if `hull < prev*2/3` then (player hull `< prev*2/3` ? `rand(10) > 3 → pirateFlee` : `pirateFlee`, then `rand(10) > 8 && opponentType < 10 → pirateSurrender`); trader types: if `hull < prev*2/3` then `rand(10) > 3 ? traderSurrender : traderFlee`; else if `hull < prev*9/10` then (player `< prev*2/3` ? `rand(10) > 7 → traderFlee` : player `< prev*9/10` ? `rand(10) > 3 → traderFlee` : `traderFlee`). The probabilities equal C# (40/60/10/60/20/60 %); only the draws differ. (source: Palm: Src/Encounter.c:1111-1173)
- **CMB-060** {M5} [P] Palm never changes `famousCaptainAttack`, Space Monster, Dragonfly or Scarab types in the update. Its `marieCelestePolice → policeAttack` branch is unreachable because attacking or fleeing always converts that type first. (source: Palm: Src/Encounter.c:1124-1129, :1496-1503, :1600-1612)
- **CMB-061** {M3} [M][W][P] When the CMB-053 update changes the type, the engine emits `GameEvent.encounterChanged(newType)` (after `combatRound`) so the combat log can say "the pirate is fleeing" / "the trader surrenders". ## 14. RNG draw order per round

- **CMB-094** {M3} [M][W] Windows/Modern draw order within one attack or flee command: (0) trader re-roll `rand(1500)` (CMB-007, manual attack only); (1) opponent's shot if it fires: to-hit `rand(F+size)`, `rand(5+P/2)`; if hit and `weapons > 0`: damage roll; if damage survives the shields: `rand(E_player)`; (2) player's shot if it fires: to-hit pair (skipped by the Targeting auto-hit); if hit and not disabled: disrupt roll (CMB-021) or damage roll; if damage survives shields: `rand(E_opp)`; disable draw `rand(100)` (CMB-039); (3) player escape `rand(7)`, `rand(P_opp)`; (4) opponent escape `rand(P_player)`, `rand(7+P_opp/3)`; (5) update `rand(100)`; or, if the opponent was destroyed, scoop `rand(D)` then `rand(filledCargo)`. Steps are skipped exactly when the source short-circuits. (source: Game.cs:1142-1283, :1288-1390, :1471-1481, :1519-1521, :1658)
- **CMB-095** {M5} [P] Palm draw order: (0) trader re-roll (CMB-008, only if the trader is armed); (1) opponent's shot: to-hit pair, damage roll, `rand(E_def)`; (2) player's shot: same; (3) player escape pair, or else opponent escape pair; (4) update draws `rand(10)` only where CMB-059 needs them; or scoop `rand(D)`, `rand(10)`, optional `rand(10)`.
