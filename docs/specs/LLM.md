# LLM: Flavor text

> Format (PRD §7): `- **ID** {Mn} [UI] [M][W][P] statement (source)`. `[M]` Modern, `[W]` Windows 2.01, `[P]` Palm 1.2.2. `[UI]` = verified by app tests (`SpaceTraderMacTests`) or XCUITest (`SpaceTraderMacUITests`). Bullets without `[UI]` are pure logic in `Packages/ParsecKit/Sources/ParsecInsights/Flavor/` (tested in `ParsecInsightsTests`), unless they name an app type (`SpaceTraderMac/Session/Flavor/`), in which case they are unit-tested in `SpaceTraderMacTests`. `[manual]` = a QA-REPORT row.
> Milestones: everything here is {M10} (PRD §9 M10 exit: "With `-PMFlavor template` the app behaves identically"). Template localization completeness is {M12}; the live on-device check is {M13} [manual].
> Normative inputs: PRD §1.1 G3 ("Foundation Models (optional)"), §6.1 (ParsecInsights holds `TemplateFlavor`), §6.5 (GameSession owns the Flavor service; `-PMFlavor template`), §6.6 "Flavor (LLM)": "`FlavorProvider` with two implementations: `TemplateFlavorProvider`: deterministic. `FoundationModelsFlavorProvider`: behind `#if canImport(FoundationModels)` and an availability check, with a 4 s timeout and fallback. Results are cached in the log, and flavor never changes game state. Tests force the template provider."; §11 risk "Foundation Models unavailable → Optional; timeout; template fallback"; UX-VISION §2 (Settings › Intelligence (Foundation Models)), §4.9 ("Optional flavor text: a template sentence, or on-device Foundation Models prose when enabled"); research 05 §6 (FoundationModels API notes: `SystemLanguageModel.default.availability`, `LanguageModelSession(instructions:)`, `respond(to:)`; on-device model only).
> **Ownership (do not restate, reference).** Which entries carry flavor (`LogEntryKind.flavorSubject`) and where the cached text lives (`LogEntry.flavor`): LOG-008, LOG-011. Persistence of the journal: LOG-001…007. The `-PMFlavor template` launch argument's non-effects on state, RNG and `cheatsUsed`: CHEAT-050.

## Conventions (normative for every bullet below)

- **Cosmetic only.** Flavor is decoration on a log entry. No flavor value is ever read by the engine, the journal recorder (except to attach it, LOG-013 step 5), STAT, ACH, INT, the presentation router or any enablement rule.
- **No game RNG.** Template selection uses its own stable hash of the entry; it never reads `GameState.rng`, never calls a `RandomSource` and never uses Swift's `Hasher`/`hashValue` (randomly seeded per process).
- **No free text from the player in prompts.** Commander and ship names are user input; prompts say "the commander" and "the ship" instead, so a name can never steer the model.

## 1. Protocol and values

- **LLM-001** {M10} [M][W][P] `protocol FlavorProvider: Sendable { var source: FlavorSource { get }; func flavor(for request: FlavorRequest) async -> FlavorText? }` (ParsecInsights). A nil result means "no flavor from this provider"; the caller keeps the template (LLM-020). (source: PRD §6.6 "`FlavorProvider` with two implementations")
- **LLM-002** {M10} [M][W][P] `FlavorRequest { entryID: Int, day: Int, system: Int, subject: FlavorSubject }` is a `Sendable, Equatable` value built from a `LogEntry` alone (no `GameState`, no `GameEngine`), so a provider cannot read or change game state. (source: PRD §6.6 "flavor never changes game state")
- **LLM-003** {M10} [M][W][P] `FlavorSubject` cases with typed facts only: `arrival(system: Int, viaWormhole: Bool, firstVisit: Bool, uneventful: Bool, encounterCount: Int)`, `encounter(type: EncounterType, opponent: ShipType, result: EncounterResultClass, rounds: Int, minHullPercent: Int)`, `quest(SpecialEventType)`, `gameEnded(GameEndType)`, `achievement(AchievementID)`. `LogEntryKind.flavorSubject` (LOG-011) produces them. (source: UX-VISION §4.9)
- **LLM-004** {M10} [M][W][P] `FlavorText` is `Codable, Sendable, Equatable` with cases `template(FlavorLine)` and `generated(text: String)`; `FlavorLine { key: String, args: [FlavorArg] }` with `FlavorArg` cases `system(Int)`, `ship(ShipType)`, `item(TradeItemType)`, `count(Int)`, `credits(Int)`, `skill(SkillType)`. Template lines are stored as key plus typed arguments, not as prose, so ParsecInsights produces no user-facing strings and the app localizes them at display time (LLM-011). (source: CLAUDE.md "must not produce user-facing strings" applied to the package; UI-SHELL Conventions "Localization")
- **LLM-005** {M10} [M][W][P] `FlavorSource` is `template` or `foundationModels`; `FlavorText.source` returns it. The log row shows a small "Apple Intelligence" mark (symbol plus text in the help tag) on generated text. (source: UX-VISION §4.9 "a template sentence, or on-device Foundation Models prose")

## 2. Template provider (deterministic)

- **LLM-006** {M10} [M][W][P] `TemplateFlavorProvider` (ParsecInsights) has a synchronous `line(for request: FlavorRequest) -> FlavorLine` and implements `FlavorProvider` by returning `.template(line(for:))`. It is a pure function of the request. (source: PRD §6.6 "`TemplateFlavorProvider`: deterministic")
- **LLM-007** {M10} [M][W][P] Variant choice: `FlavorSeed.make(_ request:) -> UInt64` is FNV-1a 64 over the little-endian bytes of `entryID`, `day`, `system` and the subject's stable code (`FlavorSubject.code`, a fixed `UInt32` per case and variant group); the variant index is `seed % variantCount`. Golden test with fixed vectors committed in the test (the hash is process-independent by construction). (source: research 06 §C "deterministic, seeded from the event hash"; PRD §6.2 "Determinism")
- **LLM-008** {M10} [M][W][P] The journal recorder attaches `.template(line)` to every new entry whose `flavorSubject` is non-nil, in the same step (LOG-013 step 5), so a journal recorded under `-PMFlavor template` is fully deterministic: the same seed and commands give byte-identical journals (LOG-014). (source: PRD §6.6 "Results are cached in the log")
- **LLM-009** {M10} [M][W][P] Template catalog: keys are `flavor.<group>.<n>` with groups `arrival.quiet`, `arrival.eventful`, `arrival.firstVisit`, `arrival.wormhole`, `encounter.won`, `encounter.fled`, `encounter.surrendered`, `encounter.lost`, `encounter.other`, `quest.<chain or generic>`, `gameEnded.killed`, `gameEnded.retired`, `gameEnded.moon`, `achievement`; every group has at least 3 variants. `TemplateFlavorProvider.catalog` lists every key with its argument types; a test checks each generated line's arguments match its key's declaration. (source: UX-VISION §4.9)
- **LLM-010** {M10} [M][W][P] Group choice is a pure mapping of the subject: arrival → `wormhole` if via wormhole, else `firstVisit` if first visit, else `eventful` if `encounterCount > 0`, else `quiet`; encounter → its result class; quest → the chain of the event type (QST-INDEX §1) or `generic`; game end → `killed`, `retired` or `moon` (`boughtMoon`/`boughtMoonGirl`). Unit test per branch. (source: LLM-003)
- **LLM-011** {M10} [M][W][P] `FlavorCatalogText.text(for line: FlavorLine, state:) -> String` (app) maps every catalog key to a `Localizable.xcstrings` entry with typed interpolation (system and ship names via `Names`, credits formatted). A test renders every key of `TemplateFlavorProvider.catalog` with fixture arguments and fails on a missing key or an unresolved placeholder. (source: UI-SHELL Conventions "Localization")

## 3. Foundation Models provider (app)

- **LLM-012** {M10} [M][W][P] `FoundationModelsFlavorProvider` lives in the app target (`SpaceTraderMac/Session/Flavor/`) and is compiled only under `#if canImport(FoundationModels)`; without the framework the app builds and `FlavorAvailability` reports `.unsupportedBuild`. It depends on a `FlavorModelClient` protocol (`func respond(instructions: String, prompt: String) async throws -> String`); the production client wraps `LanguageModelSession(model: SystemLanguageModel.default, instructions:)` and `respond(to:)`, and tests inject fakes. (source: PRD §6.6 "behind `#if canImport(FoundationModels)`"; research 05 §6)
- **LLM-013** {M10} [M][W][P] Availability check before every request: `FlavorAvailability.current` maps `SystemLanguageModel.default.availability` to `.available`, `.deviceNotEligible`, `.appleIntelligenceNotEnabled`, `.modelNotReady`, `.unsupportedLanguage` (the current locale's language is not in the model's supported languages) or `.unsupportedBuild`. Anything but `.available` returns nil without calling the client. (source: PRD §6.6 "an availability check"; research 05 §6 "it reports a reason when unavailable")
- **LLM-014** {M10} [M][W][P] Timeout: each model call is raced against `timeout` (default 4 s, injected `Clock` and duration for tests); when the timeout wins, the call's task is cancelled and the provider returns nil. A test with a fake client that never returns and a test clock checks nil after advancing 4 s and no result applied afterwards. (source: PRD §6.6 "with a 4 s timeout and fallback")
- **LLM-015** {M10} [M][W][P] Errors (guardrail violations, cancellation, any thrown error) return nil. Output validation: trimmed; newlines collapsed to spaces; Markdown emphasis and quotes stripped; must be non-empty and at most 240 characters (a longer text is cut at the last sentence end before 240, or rejected if there is none); otherwise nil. Unit tests per rule with fake outputs. (source: PRD §11 "Foundation Models unavailable → … template fallback")
- **LLM-016** {M10} [M][W][P] Prompting: fixed instructions ("You write one or two short sentences for a starship captain's log in a classic space trading game. Past tense, plain text, no lists, no numbers or names that are not given, never invent game events.") plus a prompt built by `FlavorPromptBuilder.prompt(for request:, names:)` from the subject's facts with localized system, ship and item names and the language to write in. Commander and ship names are never included (Conventions). Golden tests of the prompt for one request per subject case. (source: research 05 §6; PRD §6.6 "flavor never changes game state")
- **LLM-017** {M10} [M][W][P] Only the on-device default model is used: no network, no account, no Private Cloud Compute, no entitlement changes. (source: research 05 §6 "We use only the on-device default model, with no network and no account"; PRD §1.2 "No network play")

## 4. Flavor service and cache (app)

- **LLM-018** {M10} [M][W][P] `FlavorService` (`@MainActor`, the `SessionFlavor` implementation) has `mode: FlavorMode` (`templateForced`, `templateOnly`, `foundationModels`), derived from the launch argument (LLM-024) and the Settings toggle (LLM-025). In `foundationModels` mode, after each step it enqueues a request for every new entry with a flavor subject (`JournalStepOutput.newEntries`), tagged with the session's `gameID`. Entries recorded in earlier sessions are never requested. (source: PRD §6.5 "services (… Flavor)")
- **LLM-019** {M10} [M][W][P] Queue: at most one request in flight; at most 8 waiting (the oldest waiting request is dropped first, keeping its template); requests run off the main actor; the queue is cancelled on Close Game, New Game, load and when the mode leaves `foundationModels`. Unit tests with a fake provider and a test clock. (source: PRD §6.5 "Heavy pure work … runs off the main actor")
- **LLM-020** {M10} [M][W][P] Fallback: an entry keeps its template line whenever the provider returns nil (unavailable, timeout, error, invalid output, dropped from the queue). The template is already in the entry when the request starts (LLM-008), so a fallback changes nothing visible. (source: PRD §6.6 "fallback"; §11)
- **LLM-021** {M10} [M][W][P] Cache: a generated result is written on the main actor into `journal.entries[i].flavor = .generated(text:)` for the entry with that `entryID`, only if the session's `gameID` still equals the request's and the entry's flavor is still `.template`. It is saved with the journal by the next save (LOG-027) and shown as is after reload; an entry with `.generated` flavor is never requested again. (source: PRD §6.6 "Results are cached in the log"; research 05 §6 "Cache the result per log entry")
- **LLM-022** {M10} [M][W][P] Flavor never changes game state: applying a generated flavor changes only `journal.entries[i].flavor`; a test checks `engine.state`, `stateGeneration`, the feed, the presentation queue and the canonical state hash are unchanged across it, and that no persistence trigger ran. (source: PRD §6.6 "flavor never changes game state")
- **LLM-023** {M10} [M][W][P] `FlavorService` never blocks the main actor: `send(_:)` returns before any model work starts, and a fake provider that takes 3 s does not delay the next `send`. (source: PRD §6.5 "Engine calls are synchronous")

## 5. Launch argument and settings

- **LLM-024** {M10} [M][W][P] `-PMFlavor template` (Debug launch argument, CHEAT-050) sets `FlavorMode.templateForced`: no `FoundationModelsFlavorProvider` is created, no availability check runs, no request is enqueued. Every UI test and every app unit test that creates a `GameSession` uses template mode (UI tests pass `-PMFlavor template`; unit tests inject `FlavorService(mode: .templateForced)`). (source: PRD §6.5 "`-PMFlavor template`", §6.6 "Tests force the template provider")
- **LLM-025** {M10} [UI] [M][W][P] Settings › Intelligence: "Write log entries with Apple Intelligence" (`settings.flavor.foundationModels`, key `settings.flavor.useFoundationModels`, default off), enabled only when `FlavorAvailability.current == .available`; below it a status line (`settings.flavor.status`) with the localized availability reason ("Available", "This Mac doesn't support Apple Intelligence", "Turn on Apple Intelligence in System Settings", "The model is downloading", "Not available in your language", "Not available in this build"), and in `templateForced` mode "Template text is forced by a launch argument" with the toggle disabled. No setting reaches the engine or the save (OPT-028). (source: UX-VISION §2 "Intelligence (Foundation Models)"; OPT-028)
- **LLM-026** {M10} [UI] [M][W][P] Turning the toggle off cancels the queue; already generated texts stay in the log (they are cached data). Turning it on affects only entries recorded afterwards. (source: LLM-018, LLM-021)
- **LLM-027** {M10} [UI] [M][W][P] "Show flavor text in the Captain's Log" (`settings.flavor.show`, key `settings.flavor.show`, default on) hides or shows the flavor line in log rows and in the Markdown export (LOG-031, LOG-033); entries keep their flavor either way. (source: UX-VISION §4.9 "Optional flavor text")

## 6. "Behaves identically"

- **LLM-028** {M10} [M][W][P] Identical behaviour test (the M10 exit criterion): the same scripted session (Quick Start with a fixed seed, trades, a trip with an encounter, a special event, a newspaper, retirement) is run three times: with `templateForced`, with `foundationModels` and a fake provider that returns fixed prose, and with `foundationModels` and a fake provider that always times out. After every step the three runs have equal state hashes, `stateGeneration`, feed items, presentation sequences, high-score outcome and achievement unlocks, and their journals are equal after replacing every `FlavorText` with nil. (source: PRD §9 M10 "With `-PMFlavor template` the app behaves identically")
- **LLM-029** {M10} [UI] [M][W][P] UI flows 1–5 and the identifier walks run with `-PMFlavor template` and stay green; the Logbook's log rows show template flavor in a flow-2 game (`logbook.entry.<id>` contains the localized template text). (source: PRD §8.2 flows; LLM-024)

## 10. Notes

- **Default off.** Generated prose is opt-in, so a default install behaves exactly like `-PMFlavor template` until the player turns it on.
- **Why templates are cached as keys.** Storing `FlavorLine` (key and typed arguments) keeps the journal deterministic and language-independent: a save made in one language shows template flavor in the reader's language. Generated prose is stored as text in the language it was written in.
- **Cross-spec follow-ups:** CHEAT-050's `-PMFlavor template` is implemented by LLM-024; the `SessionFlavor` stand-in (`TemplateFlavor`, SessionServices.swift) is replaced by `FlavorService`.
