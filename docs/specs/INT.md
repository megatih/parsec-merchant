## Conventions (normative for every bullet below)

- **Fairness rule (PRD §6.6, normative).** Every value INT shows is computed only from (a) information the player has legitimately seen, each with the day it was seen, and (b) the standard-price estimate the classic games showed on the Average Price List / Target column. INT never reads the RNG state, the stock, prices, countdown, pressure or true special resource of any system other than the current one while docked, or any field the classic UI hid. This is enforced structurally (INT reads only `IntelSnapshot` and `IntelBook`, INT-002) and by differential tests (INT-004).
- **Pure core.** All INT logic is `Sendable`, deterministic, draws no random numbers, uses no `Date`, locale or `Hasher`, and returns typed values; the app localizes them. Ties are always broken by a stated key ending in the lower `TradeItemType` raw value or system index.
- **Integer math.** Prices, profits and ages are `Int`; divisions truncate as in the engine. No floating point.

## 1. Fairness and inputs

- **INT-001** {M10} [M][W][P] The intel inputs are exactly two values: `IntelBook` (what the player has seen, stored in the journal, INT-007) and `IntelSnapshot` (public facts of the current state, INT-002). Every `TradeIntel` and `HeatmapModel` function takes only these two plus explicit parameters (an item, a target index, a mode); none takes a `GameState` or `GameEngine`. (source: PRD §6.6 "Fairness: only information the player has legitimately seen")
- **INT-002** {M10} [M][W][P] `IntelSnapshot.init(_ state: GameState)` copies only public facts: `day` (`commander.days`); `currentSystem`; `isDocked` (`phase == .docked`); per system `x`, `y`, `size`, `techLevel`, `politics`, `visited`, `knownResource` (the special resource only when visited, else `.nothing`), and `shipyard` only when visited; the wormhole ring; the distance rule and `fuelCapacity`; the indices of `destinations` (in range now); for the current system only `buyPrices`, `sellPrices`, `tradeItems` (stock) and `pressure`; the hold (`ship.cargo`, `priceCargo`), `marketRows` (`maxBuy`, `maxSell`) and `policeRecordScore`. It holds no RNG state, no other system's stock, countdown, pressure or true resource, and no special-event placement. (source: PRD §6.6 "Never hidden RNG or unvisited actual prices"; World.swift `knownResource`)
- **INT-003** {M10} [M][W][P] `IntelSnapshot` and `IntelBook` are `Sendable, Equatable`; the app builds the snapshot on the main actor and may run any INT function off the main actor (MAP-062 pattern). (source: PRD §6.5 "runs off the main actor on Sendable snapshots")
- **INT-004** {M10} [M][W][P] Fairness differential test, per ruleset over 50 seeds: take a state, make a copy that differs only in hidden fields (another system's `tradeItems`, `countDown`, `pressure`, `specialResource` of every unvisited system, `specialEvent` placement, and the RNG state), and check that `IntelSnapshot`, every `TradeIntel` result of §3–§5 for every item and system, every `HeatmapModel` mode of §6 and the `lowestRisk` route of INT-027 are equal for both. In Modern the true resource of unvisited systems changes real prices (MOD-006); the test proves that estimates still ignore it. (source: PRD §6.6 "Fairness"; MOD-006; MAP-097 "A fairness test checks that hidden prices never change the output")
- **INT-005** {M10} [M][W][P] Public facts used without having been "seen": system positions, size, tech level and government (and the government's police, pirate and trader activity levels from the ruleset table), wormholes, distances, and which items a government/tech level trades (`Pricing.itemTraded` / `itemUsed`). The classic short-range chart and system information showed these for every system. (source: Palm: Src/Traveler.c:762-830 `ShowAveragePrices` uses size, tech and government of an unvisited `WarpSystem`; Form_SpaceTrader.cs:2951-3021)
- **INT-006** {M10} [M][W][P] Newspaper headlines are seen information: a headline read by the player that names a system's pressure (`Headline.externalPressure(template:pressure:system:)`) becomes a `PressureHint` (INT-011). Unread newspapers contribute nothing. (source: PRD §6.6 "newspaper hints"; Newspaper.swift `Headline`)

## 2. The intel book (seen prices)

- **INT-007** {M10} [M][W][P] `IntelBook { systems: [SystemIntel] }` has exactly one `SystemIntel` per galaxy system (array index = system index; no dictionaries, so the sorted-key JSON of SAV-004 is deterministic). `SystemIntel { lastVisitDay: Int?, visitCount: Int, history: [MarketObservation], pressureHint: PressureHint? }`; `latest` is `history.last`. `MarketObservation { day, buy: [Int], sell: [Int], stock: [Int], pressure: SystemPressure }` with one element per `TradeItemType`. All fields are `Int`, enums or arrays; no floats, no `Date`. (source: PRD §6.6 "Price snapshots for each visited system and day"; SAV-004, SAV-006)
- **INT-008** {M10} [M][W][P] Observation rule, applied by the journal recorder after every accepted, non-confirmation step (LOG-013): when `after.phase == .docked`, the current system's `buyPrices`, `sellPrices`, `tradeItems` and `pressure` are observed with `day = after.commander.days`. If `history.last` has the same day it is replaced; otherwise the observation is appended. An observation equal in every field to `history.last` is not appended again. Nothing is observed in transit, in an encounter or after the game has ended. (source: UX-VISION §4.2 "remembered prices at this system")
- **INT-009** {M10} [M][W][P] `history` keeps the newest `IntelPolicy.historyLimit` (24) observations per system, dropping the oldest. A unit test docks 30 times on different days at one system and checks 24 entries, oldest first, ending with the newest. (source: UX-VISION §4.2 "History: … sparkline")
- **INT-010** {M10} [M][W][P] Visits: an `arrived(system:)` event sets that system's `lastVisitDay` to the arrival day and increments `visitCount`. Starting a journal (LOG-005) sets them for the starting system. A journal bootstrapped from an existing state (LOG-006) marks every `visited` system with `visitCount = 1` and `lastVisitDay = nil` ("visited, date unknown"), except the current system, which gets the current day. (source: UX-VISION §4.7 heatmap "Last visited")
- **INT-011** {M10} [M][W][P] `PressureHint { pressure: SystemPressure, day: Int, source }` with `source` `.news` (INT-006) or `.observed` (the current system's pressure when docked, INT-008). The newest hint per system wins; a later observation at the system replaces a news hint. A hint is shown with its age and never changes a price number (INT-016). (source: PRD §6.6 "newspaper hints")

## 3. Quotes, staleness and estimates

- **INT-012** {M10} [M][W][P] `TradeIntel.quote(item:, system:, book:, snapshot:) -> PriceQuote` returns `PriceQuote { item, system, sell: Int?, buy: Int?, stock: Int?, source: QuoteSource, age: Int?, staleness: Staleness, pressureHint: PressureHint? }` with source chosen in this order: (1) `.live` when `system == currentSystem` and docked: the current prices, age 0; (2) `.observed(day)` from `history.last`, age = `snapshot.day − day`; (3) `.estimate`: `sell` = the standard price of INT-013, `buy` and `stock` nil. A price of 0 (not traded or not bought there) is returned as nil ("—"). (source: UX-VISION §4.2 "Target: … from current intel; dimmed if the data is old")
- **INT-013** {M10} [M][W][P] The estimate is the classic standard price: `Pricing.standardPrice(spec, in: system', ruleset:)` where `system'` is the system with `specialResource` replaced by its `knownResource`, so the resource counts only once visited in every ruleset, including Modern where the engine's real prices use the hidden resource (MOD-006). It includes the base for the tech level, the government's wanted bonus, trader activity and size, and excludes pressure, the random fluctuation and the criminal factor. Unit test: equals Palm's Average Price List value for a fixture system, visited and unvisited. (source: Palm: Src/Traveler.c:806-812 `StandardPrice(…, Visited ? SpecialResources : -1)`; Form_SpaceTrader.cs:2951-3021; Pricing.swift `standardPrice`; MOD-006)
- **INT-014** {M10} [M][W][P] `Staleness` from the age in days: `.live` for source live; `.fresh` for age 0…`IntelPolicy.recentDays` (7); `.old` for older observations; `.estimate` for estimates. The app dims `.old` values and marks `.estimate` values "est." (text, not colour alone). Unit tests at ages 0, 7, 8. (source: UX-VISION §4.2 "dimmed if the data is old"; §1.7 "Color is never the only signal")
- **INT-015** {M10} [M][W][P] `TradeIntel.profitPerBay(item:, target:, book:, snapshot:) -> Int?` is `quote(target).sell − here.buyPrice` when the item is bought here (`buyPrice > 0`, from the current market) and the target quote's `sell` is non-nil; otherwise nil. One unit occupies one bay, so per unit = per bay. (source: UX-VISION §4.2 "profit per bay"; §1.3)
- **INT-016** {M10} [M][W][P] A known `PressureHint` whose pressure is the item's price-hike pressure (`TradeItemSpec.pressurePriceHike`) sets `PriceQuote.pressureHint` for estimates and observations older than the hint; the number is unchanged, and the app adds "News on day N: <pressure>" to the cell's help tag. (source: PRD §6.6 "newspaper hints"; ECO pressure ×3/2 rule)

## 4. "Why this price?"

- **INT-017** {M10} [M][W][P] `PriceExplanation.make(_ breakdown: PriceBreakdown) -> PriceExplanation` turns the engine's ECO-082 breakdown of the current system into ordered `steps: [PriceExplanationStep { factor, valueAfter, delta }]` with `factor` in this order: `base` (tech level), `wanted` (government), `traderActivity`, `size`, `resource` (known resource), `pressure`, `criminal`, `fluctuation`, then `buyMarkup` for the buy price. A step whose delta is 0 is kept but flagged `isNeutral` so the view can collapse it. The sell price equals the last sell step's `valueAfter`; the buy price equals sell + `buyMarkup`. Unit test for a fixture with every factor active. (source: UX-VISION §4.2 "the price breakdown from legitimate information: base for the tech level, government, size, pressure, the resource if known, and your record"; MarketTime.swift `PriceBreakdown`)
- **INT-018** {M10} [M][W][P] Fairness of the explanation: it is offered only for the current system while docked, where every input is visible (the system is visited, so `knownResource` is the true resource). The `fluctuation` step is labelled "Market fluctuation" and is the difference to the visible price, never an RNG value. (source: PRD §6.6 "Fairness"; ECO-082)

## 5. Recommendations

- **INT-019** {M10} [M][W][P] `TradeIntel.bestBuys(for target:, book:, snapshot:, limit: 3) -> [TradeRecommendation]`: items with `buyPrice > 0`, stock > 0 here and `profitPerBay > 0`, sorted by profit per bay descending, then item raw value. `TradeRecommendation { item, profitPerBay, units, projectedProfit, quoteSource, staleness }` with `units = marketRow.maxBuy` (respects Leave Empty and Reserve Money, ECO-042/046) and `projectedProfit = profitPerBay × units`. Empty when the target is the current system. (source: UX-VISION §4.2 "Best buy here for {target}: Robots +412/bay")
- **INT-020** {M10} [M][W][P] `TradeIntel.holdValue(at system:, book:, snapshot:) -> HoldValue { revenue, costBasis, profit, unsellable: [TradeItemType], usesEstimates }`: for each held item whose quote `sell` is non-nil, revenue `qty × sell` and cost basis `priceCargo[item]`; items with a nil sell price are listed as unsellable and excluded from both sums. `usesEstimates` is true when any counted quote is an estimate. (source: UX-VISION §4.2 "a projected profit summary for the current hold at the target")
- **INT-021** {M10} [M][W][P] `TradeIntel.bestDestinations(book:, snapshot:, limit: 3) -> [DestinationRecommendation]`: over `snapshot.destinations` (systems in range now, excluding the current one) with a non-empty hold, the systems with `holdValue.profit > 0`, sorted by profit descending, then distance ascending, then index. Empty when the hold is empty. (source: UX-VISION §4.2 "Best destinations within range for your hold")
- **INT-022** {M10} [M][W][P] `TradeIntel.sellAdvice(item:, book:, snapshot:) -> SellAdvice?` for a held item: the profit per unit if sold here (`sellPrice − priceCargo/held`, integer division) and the best other system by known or estimated sell price among `destinations` (ties by distance, then index), with its quote source and age. Nil when the item is not held. (source: PRD §6.6 "best buys and destinations"; UX-VISION §1.3)
- **INT-023** {M10} [M][W][P] Recommendations never consult another system's live state: a test changes only the target's real `sellPrices`/`tradeItems` and checks that every recommendation is unchanged until the player docks there. (source: PRD §6.6 "Fairness")

## 6. Heatmaps, risk and search

- **INT-024** {M10} [M][W][P] `HeatmapMode` cases: `none`, `price(TradeItemType)`, `holdProfit`, `police`, `pirates`, `techLevel`, `lastVisited` (MAP-096). `HeatmapModel.values(mode:, intel: IntelBook, snapshot: IntelSnapshot) -> HeatmapResult { values: [HeatmapValue], scale: HeatmapScale }` (the API named by MAP-097) returns one `HeatmapValue { value: Int?, note: HeatmapNote?, age: Int? }` (`HeatmapNote` is `.estimate` or `.dateUnknown`) per system and `scale { min, max }` over the non-nil values (both 0 when none). (source: UX-VISION §4.7 "Heatmap modes"; MAP-097)
- **INT-025** {M10} [M][W][P] Mode values: `price(item)` = `quote(system).sell` (nil when not bought there), note `.estimate` for estimates, `age` for observations; `holdProfit` = `holdValue(at:).profit` (nil for an empty hold or the current system); `police` / `pirates` = the government's police / pirate `Activity` raw value (`.na` → 0); `techLevel` = raw tech level; `lastVisited` = `snapshot.day − lastVisitDay` (nil when never visited; nil with note `.dateUnknown` for "visited, date unknown", INT-010); `none` = all nil. Unit test per mode on a fixture galaxy. (source: UX-VISION §4.7 "never-visited systems use the Average-Price estimate the original showed, marked 'estimate'")
- **INT-026** {M10} [M][W][P] Route risk for MAP-069: `RouteSnapshot` gains `hopRisk: [Int]`, one weight per system computed from public data only: the system government's pirate activity raw value plus, when `policeRecordScore < -5` (the engine's criminal threshold), its police activity raw value (`.na` counts 0). A hop's risk is the weight of its destination system, because travel encounters are rolled against the destination's government. MAP-094's field list is extended by the politics table and `policeRecordScore`. (source: PRD §6.6 "minimizing jumps, cost or risk"; Travel.swift encounter rolls use the warp system's politics; MAP-069, MAP-094)
- **INT-027** {M10} [M][W][P] `RouteObjective.lowestRisk` uses the lexicographic key (risk, jumps, credits) with MAP-058's tie-breaking. Property test over 100 seeds per ruleset: its total risk is ≤ that of `fewestJumps` and `cheapest` for the same pair, and every hop is a MAP-055 edge. (source: MAP-057, MAP-058, MAP-069)
- **INT-028** {M10} [M][W][P] `SystemSearchFilter.sells(TradeItemType)` (MAP-072) matches a system whose `history.last` shows `buy > 0` and stock > 0 for the item, or, when never observed, where `Pricing.itemTraded` is true (public rule); the latter results are marked "estimate" in the suggestion row. (source: UX-VISION §4.7 "filters ('… sells Robots')"; MAP-072)

## 7. Market (app)

- **INT-029** {M10} [M][W][P] `MarketIntelModel.make(book:, snapshot:, target:) -> MarketIntelModel` (app, pure) holds per row the target quote, profit per bay, the history series, the sell advice and the explanation, plus the recommendations and the footer projection, all from INT-012…022. It is rebuilt once per `stateGeneration` or journal change, off the main actor. (source: PRD §6.5; UX-VISION §4.2)
- **INT-030** {M10} [UI] [M][W][P] The Target column (UI-SHELL-061) is replaced by the intel quote for any target (no longer only in range): the target's sell price, or "—"; the data age ("today", "3 d ago") or "est."; `.old` values dimmed; Δ vs the here buy price with sign and ▲/▼; and the profit per bay. Identifier `market.row.<item>.target`; the help tag names the source and day. (source: UX-VISION §4.2 "Target"; UI-SHELL-061 "Intel dimming … {M10}")
- **INT-031** {M10} [UI] [M][W][P] The History column shows a Swift Charts sparkline of the sell price over the current system's `history` (`market.row.<item>.history`); it is empty with the text "No history" when fewer than 2 observations exist. Its accessibility value reads "Sell price over N visits: from A to B credits". (source: UX-VISION §4.2 "History: Swift Charts sparkline of remembered prices at this system")
- **INT-032** {M10} [UI] [M][W][P] "Why this price?": the selected row's detail panel below the table (`market.why`, an inline panel, never a popover) lists the INT-017 steps with their deltas, neutral steps collapsed behind "Show all" (`market.why.showAll`). - **INT-033** {M10} [UI] [M][W][P] Recommendations strip above the table (`market.recommendations`): "Best buy here for <target>: <item> +<profit>/bay (<units> bays, +<projected>)" (`market.recommendation.buy.<n>`, n from 1) and "Best destinations for your hold: <system> +<profit>" (`market.recommendation.destination.<n>`). - **INT-034** {M10} [UI] [M][W][P] Footer: after the UI-SHELL-066 texts, "Hold at <target>: +<profit>" (or "−") from `holdValue(at: target)` (`market.footer.projected`), with "est." when it uses estimates and "<n> items not bought there" for unsellable items. ## 14. Notes

- **Cross-spec follow-ups (owned elsewhere):** MAP-094's field list gains the politics table and `policeRecordScore` (INT-026); UI-SHELL-061's in-range-only Target rule is superseded at M10 by INT-030; the hover card (MAP-047) and heatmap model (MAP-097) are specified by INT-036 and INT-024/025.
- **Design decision: estimates never include pressure.** The Average Price List did not include it, and pressure of other systems is not visible in the classic UI. News hints are shown beside the number (INT-016) instead of being folded into it, so every estimate equals the classic value exactly.
- **Not stored:** quotes, recommendations and heatmaps are recomputed from `IntelBook` + `IntelSnapshot`; only observations, visits and hints are persisted (in the journal, LOG-001).
