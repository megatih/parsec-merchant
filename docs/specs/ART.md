## Conventions (normative for every bullet below)

- **Drawn in code, nothing else.** Every picture in the app is produced at run time (or by `make-icon.sh`) from SwiftUI `Shape`/`Path`/`Canvas`/`GraphicsContext` code in `ParsecArt`, or from pixel buffers that `ParsecArt` generates at run time from seeded noise (the planet maps and sphere projections of §5). Metal is allowed in the app target only, as a presentation of `ParsecArt`'s maps (ART-073…076); `ParsecArt` itself never imports Metal. No bitmap, PDF, SVG, font-glyph image or base64 blob is shipped as art. SF Symbols are allowed for UI chrome only (UX-VISION §7 "Iconography").
- **No original Space Trader images, in any form.** The images in `SpaceTraderSource201/images/`, `App.ico` and the Palm `Rsc/` bitmaps are never opened, viewed, traced, sampled for colours or used as layout references while designing art. Ship shapes follow each ship's statistics through the generator of §3 (ART-009…012): what a ship carries, mounts and costs decides how it looks. Ship names are game data and never shape the art: no ship has insect anatomy (no antennae, legs, stingers, pincers, mandibles, segmented abdomens or insect wings; ART-087) (PRD §1.2, §2 D2, §3; PRD-1.1 §4 D5).
- **No game state.** `ParsecArt` imports SwiftUI, CoreGraphics and Foundation only. It does **not** import `ParsecEngine` and never sees `GameState`. Inputs are small `Sendable, Hashable` value types defined in `ParsecArt` (`ShipArtInput`, `PlanetArtInput`, …). The app maps engine values to them in `SpaceTraderMac/Art/ArtAdapters.swift` with exhaustive `switch`es and no `default`, so a new engine case fails to compile (PRD §6 "no game state").
- **Deterministic.** The same input value, size, scale, colour scheme and accessibility flags produce the same pixels. Art never reads the clock, `Date`, `random()`, `SystemRandomNumberGenerator`, `Hasher` or `hashValue` (process-randomised), the game RNG (RNG-036) or global mutable state. Animation is an explicit `phase: Double` (seconds) input supplied by the app (a `TimelineView`, or the display link of the live planet, ART-076); a still frame is `phase = 0`.
- **Accessibility as inputs.** Reduce Motion, Increase Contrast, Reduce Transparency and Differentiate Without Color reach art as an `ArtAccessibility` value (read by the host view from the environment), so tests can render every variant without changing system settings.
- **Files.** `Packages/ParsecKit/Sources/ParsecArt/` with the subfolders `Core/`, `Ships/`, `Planets/`, `Space/`, `Glyphs/`, `Effects/`, `Scenes/`, `Icon/`. Every file starts with the SPDX header. Swift 6 mode, zero warnings.

## 1. Package, inputs and determinism core

- **ART-001** {M11} [M][W][P] `ParsecArt` depends on no other ParsecKit target and declares no `resources:` in `Package.swift`. A test (`ParsecArtTests`, reading `Package.swift` and `Sources/ParsecArt/**` via `#filePath`) checks: no `import ParsecEngine`/`AppKit`/`UIKit`; no `resources`; no source contains `Image("`, `NSImage(named:`, `NSImage(contentsOf`, `UIImage(`, `Bundle.module`, `Data(base64Encoded`, `Date(`, `.random`, `SystemRandomNumberGenerator`, `Hasher` or `hashValue`; no string literal is longer than 400 characters (no embedded image data). (source: PRD §6 "ParsecArt … no game state", §2 D2, §3)
- **ART-002** {M11} [M][W][P] `ArtRandom` is a value-type SplitMix64 generator (`next() -> UInt64`, `unit() -> Double` in `[0, 1)`, `range(_:)`) and `ArtSeed` derives seeds with fixed arithmetic only: `ArtSeed.mix(_ a: UInt64, _ b: UInt64)` = SplitMix64 finaliser of `a ^ (b &* 0x9E37_79B9_7F4A_7C15)`; `ArtSeed.system(galaxySeed:index:)`, `ArtSeed.crew(galaxySeed:crewID:)`, `ArtSeed.kind(_:)` (a constant per ship kind). Golden-value tests pin the first five outputs for seed 0 and seed 42 so a refactor cannot silently change every planet. It is independent of every engine generator (RNG-036). (source: RNG-036; UX-VISION §7 "seeded per system id")
- **ART-003** {M11} [M][W][P] `ArtPalette` defines every art colour in code as a token with light and dark variants and an Increase Contrast variant: `spaceTop`/`spaceBottom` (indigo → near-black), `visited` (cyan-blue), `unvisited` (green), `wormholeA`/`wormholeB` (amber → magenta), `brass` (the accent gold), `danger`, `profit`, `shieldEnergy`/`shieldReflective`/`shieldLightning`, `engineGlow`, `scorch`, and the planet and livery ramps used below. `ArtPalette.resolve(_ token:, scheme:, contrast:)` returns a `Color` in the sRGB space. Map tokens equal the values the M8 map already uses (MAP-024, MAP-037); a test compares them. (source: UX-VISION §7 "Palette", §9 "Increase Contrast")
- **ART-004** {M11} [M][W][P] `ArtAccessibility { reduceMotion, increaseContrast, reduceTransparency, differentiateWithoutColor: Bool }` is passed to every animated or translucent art view. Rules shared by all art: `reduceMotion` forces `phase = 0` for ambient animation and swaps effects for flashes (§9); `increaseContrast` multiplies outline widths by 1.5 and uses the contrast palette; `reduceTransparency` replaces translucent fills (shield bubble, nebula, glass wings, clouds) by opaque or outline-only equivalents; `differentiateWithoutColor` adds the shape twins named in each bullet. (source: UX-VISION §1.7, §7 "Motion", §9; research 05 §5)
- **ART-005** {M11} [M][W][P] Geometry is pure: blueprints and recipes produce `Path` values in a unit coordinate space (ships: the length axis from tail `x = 0` to nose `x = 1`, centreline `y = 0.5`, facing right; planets: a unit disk) through functions with no SwiftUI view state, testable without rendering (bounding box inside the unit square, non-empty, closed, area above a floor). Views only scale, flip and fill these paths. Catmull-Rom splines are converted to cubic Béziers with a fixed tension of 0.5. (source: PRD §6 "SwiftUI Shapes/Canvas"; UX-VISION §7 "parametric vector silhouettes … hull outline (Bézier)")
- **ART-006** {M11} [M][W][P] Performance budgets (measured in `ParsecArtTests` with release-like renders, and in `scripts/bench-map.sh`): a ship portrait at 240×160 pt renders in ≤ 4 ms; a **warm** planet still at 160 pt (its projected image already in `PlanetCache`, ART-080) renders in ≤ 4 ms; a **cold** hero bake (`PlanetTextureBaker.bake` at 512×256, ART-070) takes ≤ 80 ms and is `Sendable` work the app runs off the main actor; recipes and paths are cached per input value (`ArtCache`, a bounded LRU of 512 entries, `@MainActor`), so the map with mini-planet sprites (ART-029), starfield and vortices stays within the MAP benchmark budget of 8 ms per frame. (source: PRD-1.1 §6 M14; PRD §8.1 "map benchmark"; MAP-003; UX-VISION §4.7)

## 2. Ship art kinds and adapters

- **ART-007** {M11} [M][W][P] `ShipArtKind: Int, CaseIterable, Sendable` has 17 cases in `ShipType` order with equal raw values: `flea, gnat, firefly, mosquito, bumblebee, beetle, hornet, grasshopper, termite, wasp, spaceMonster, dragonfly, mantis, scarab, bottle, custom, scorpion`. `ArtAdapters.shipKind(_ t: ShipType) -> ShipArtKind` is an exhaustive switch; a test checks the raw values match for every `ShipType.allCases` and that the counts are both 17. (source: Model/Enums.swift `ShipType`; PRD §9 M11 "17 ship types")
- **ART-008** {M11} [M][W][P] `ShipArtInput` = `{kind, stats: ShipArtStats, facing: .right | .left, hullFraction: Double (0…1), shield: ShieldDisplay? (`kind: .energy | .reflective | .lightning` = the strongest installed shield, `fraction` = summed charge over summed power), disabled: Bool, cloaked: Bool, variant: UInt64?, phase: Double, accessibility: ArtAccessibility}`; `sizeClass` reads `stats.sizeClass`. `ShipArtStats` = `{sizeClass (0…5, `ShipSpec.size`), cargoBays, weaponSlots, shieldSlots, gadgetSlots, crewQuarters, fuelTanks, hullStrength, priceTier (0…5), techTier (0…7), weapons: [Int]?, shields: [Int]?, gadgets: [Int]?}`; the three optional arrays are the installed equipment's raw type values (nil = not known, draw every slot filled). `ArtAdapters.shipStats(spec:ship:)` builds it from the ruleset's `ShipSpec` (through `ShipMath`, so a custom ship uses `Ship.customSpec`) and, when a ship instance is given, from its installed equipment; `priceTier` is the count of the thresholds 5,000, 20,000, 50,000, 90,000 and 200,000 cr. that `spec.price` reaches, and `techTier` is `spec.minTechLevel` clamped to 0…7 (7 for ships no shipyard sells). `ShipArtInput(kind:)` without stats uses `ShipArtStats.standard(kind)` (ART-088). Unit test over every ship type and the three rulesets: every field equals the ruleset's `ShipSpec`. (source: Model/Specs.swift; World.swift `customSpec`; ShipMath.swift; UI-ENC-018; PRD-1.1 §4 D5)

## 3. Ship shape grammar and per-type designs

  1. **Flea**: teardrop pod, no wings, one engine, forward bubble cockpit, two aft landing `skids`; grey-blue livery.
  2. **Gnat**: slim dart, short swept stub wings, one engine, mid-forward bubble cockpit, twin nose `antennae`; brass and slate livery.
  3. **Firefly**: small fore body with a bulbous aft cargo section and a large `abdomenLight` (yellow-green glow that doubles as the engine glow), small delta wings.
  4. **Mosquito**: needle hull with a long `proboscis` gun, long thin straight wings, two small engines, `hardpoints(2)`.
  5. **Bumblebee**: round stout hull, wide short rounded wings, `stripes(3)` livery bands, two engines.
  6. **Beetle**: wide domed shell with an `elytraSeam` down the centre, no wings, four small engines; freighter livery (rust and cream).
  7. **Hornet**: arrowhead hull, forward-swept wings, `stripes(2)`, `stinger` aft, `hardpoints(3)`.
  8. **Grasshopper**: long body, small forward canards, long `rearLegs` (outrigger nacelles reaching past the tail), slit cockpit.
  9. **Termite**: long hauler of `segments(3)` boxy sections, `mandibles` docking clamps at the nose, three engines.
  10. **Wasp**: fore and aft hulls joined by a narrow `waist`, large swept wings, `stinger`, two large engines, `hardpoints(3)`; black and amber warship livery.
  
  (source: UX-VISION §7 "Ships"; Model/Specs.swift slots and bays as motif hints)
  1. **Space monster** (`symmetric = false`): an organic body built from a seeded blob outline, `tentacles(6)` with per-tentacle curl from `ArtSeed.kind`, `eyes(3)` glowing, no engines or cockpit; alien palette (violet and teal); the engine glow is replaced by a slow bioluminescent pulse.
  2. **Dragonfly**: long thin tail boom, `wings` with `count = 2` long narrow `glass` pairs, a `compound` cockpit; iridescent green-blue livery.
  3. **Mantis**: triangular head-cockpit, `raptorialArms` folded forward, slender abdomen; alien palette.
  4. **Scarab**: heavy round armoured dome, a `hornRam` at the nose, no visible wings, dark livery with an iridescent sheen band.
  5. **Bottle**: a literal corked glass bottle (`bottle`, `cork`, `scroll` inside), drawn with glass translucency (outline-only under Reduce Transparency), no engines; it bobs gently with `phase`.
  6. **Scorpion**: two forward `pincers`, a `curledTail(5)` arching over the hull to a `stinger`, two engines; crimson and black livery.
  
  (source: UX-VISION §5.2 "Very rare encounters", §7; Model/Enums.swift `ShipType`)
- **ART-014** {M11} [M][W][P] **Size scaling and layout.** `ShipArtLayout.scale(bounds:size:mode:sizeClass:)` is the one layout function. `.fit`: the silhouette, with room for the shield bubble (×1.16), fills the frame on its tighter axis (ship grid, inspector, designer). `.relative`: `k(sizeClass) × fit-to-reference-box`, where `k = 0.5 + 0.1 × sizeClass` (tiny 0.5 … gargantuan 1.0) and the reference box is 0.90 × 0.56 unit-space units (the envelope of every generated hull), bounded by both axes of the frame and never larger than the `.fit` scale; anchored at the frame centre (encounter panes and transit), so a Flea looks small next to a Wasp and a ship in a wide, short pane uses the height it has. `ShipArtLayout.frame(_:mode:in:)` returns the silhouette's bounding box in view space, and the encounter effects aim at it (ART-083). Tests: in `.relative` mode the mask bounding-box width ratio of a size-4 and a size-0 ship with otherwise equal statistics is 0.9/0.5 within 3%; in a 600 × 200 pane and a 400 × 200 pane the same ship has the same size (bounded by the height), larger than in a 200 × 200 pane (bounded by the width). (source: UX-VISION §5.2 layout; UI-ENC-018; PRD-1.1 §4 D7)
- **ART-015** {M11} [M][W][P] **Facing and lighting.** `.left` mirrors the geometry horizontally, but shading keeps the light from the top-left in both facings (a mirrored render is not a pixel mirror of the right-facing one). Tests: the alpha masks of `.left` and `.right` are mirrors (the geometry is mirrored exactly; Core Graphics anti-aliasing of curves may differ by at most 8 alpha levels on edge pixels); the colour pixels are not. (source: UX-VISION §5.2 "[vector ship facing left]")

## 4. Ship overlays

- **ART-016** {M11} [M][W][P] **Engines and lights:** each `EngineMount` draws a dark nozzle and a bloom plume in the livery `glow` token (a bright core with a longer soft tail aft); with `phase` it flickers with a 0.4 s period and ±12% intensity; it is off when `disabled` and steady under Reduce Motion. Navigation lights (red to port, green to starboard, white at the tail) are small glows drawn with the ship, off when `disabled`. Shading uses one light direction (upper left) for every part: a plating gradient, panel lines, edge occlusion darkening inside the outline, a specular strip along the lit flank and a glass gradient on the cockpit. (source: UX-VISION §7; PRD-1.1 §4 D6)
- **ART-017** {M11} [M][W][P] **Shield bubble:** an ellipse 12% larger than the silhouette's bounding box, tinted by `shield.kind`, with fill opacity `0.12 + 0.40 × fraction` and a rim stroke; nothing is drawn when `shield` is nil or `fraction == 0`. Under Reduce Transparency it is a solid rim stroke whose width encodes the fraction (1…4 pt); under Differentiate Without Color the rim is dashed with dash count proportional to the fraction. Test: bubble pixel coverage is monotonic in `fraction`. (source: UX-VISION §5.2 "shield bubble", §7; UI-ENC-098)
- **ART-018** {M11} [M][W][P] **Scorch mask:** a deterministic set of scorch blotches (seeded by `ArtSeed.kind`) clipped to the hull path, revealed in a fixed order until the covered fraction of hull area equals `1 − hullFraction` within ±3 percentage points (measured on a 256×256 render; test at 0, 25, 50, 75 and 100% hull). Under Differentiate Without Color the scorch adds diagonal hatching. At `hullFraction = 0` (destroyed) the art is not drawn; the explosion effect (ART-046) replaces it. (source: UX-VISION §5.2 "live scorch mask whose coverage equals the hull percentage"; UI-ENC-098)
- **ART-019** {M11} [M][W][P] **Disabled and cloaked:** `disabled` desaturates the livery to 30%, turns off the glow and draws two small spark marks; `cloaked` draws the ship as a dashed outline at 35% opacity (used for the player's ship when `encounterStarted.playerCloaked`). (source: UI-ENC-018 "Disabled" tag; GameEvent `encounterStarted(…, playerCloaked:)`)

### 4a. Stat-driven ships (1.1)

## 5. Planets

- **ART-020** {M11} [M][W][P] `PlanetArtInput` = `{seed: UInt64, sizeClass: Int (0…5), tech: Int (0…7), government: Int (0…16), resource: Int? (a `SpecialResource` raw value, nil = unknown), pressure: Int? (a `SystemPressure` raw value, nil = not shown), phase, accessibility}`. `ArtAdapters.planetInput(system:state:showPressure:)` sets `seed = ArtSeed.system(galaxySeed: state.seed, index: system.id)`, reads `system.knownResource` (never `specialResource`) and passes `pressure` only where the UI shows the pressure as text (the Bridge system card, UI-SHELL-054); the map passes nil. Fairness test: two states differing only in an unvisited system's true resource give equal inputs. (source: PRD §6.6 "Fairness"; UX-VISION §4.1 "style set by tech level, size and government"; MAP-002)
- **ART-021** {M11} [M][W][P] `PlanetRecipe.make(_ input) -> PlanetRecipe` is pure and deterministic and does no pixel work: it fixes the planet class (ART-068/069), the palette tint, the land ratio, axial tilt (−25°…25°), cloud cover, ice extent, the natural-ring modifier, the three noise offsets and the tech, government and pressure looks below. Equal inputs give equal recipes; changing `seed` alone changes the recipe (test over 200 seeds: at least 195 distinct recipes). (source: PRD-1.1 §4 D1, D3; UX-VISION §7)
- **ART-022** {M11} [M][W][P] **Tech layers** (`PlanetStyle`, 8 cases in `TechLevel` order) are the table `farmland, cityLights, smog, ring, satellites`: pre-agricultural `0, 0, 0, none, 0`; agricultural `0.5, 0.012, 0, none, 0`; medieval `0.7, 0.03, 0, none, 0`; renaissance `0.8, 0.07, 0, none, 0`; early industrial `0.6, 0.15, 0.25, none, 0`; industrial `0.5, 0.30, 0.40, none, 0`; post-industrial `0.3, 0.55, 0.15, partial, 0`; hi-tech `0.2, 0.90, 0, full, 2`. `farmland` tints fertile lowland in the albedo map, `cityLights` is the density of the city-light channel of the auxiliary map (ART-070; gas giants have none), `smog` is a grey-brown haze uniform, and the orbital ring and satellites are thin vector overlays above the sphere. City lights are shown by the projector only on the night side: their weight is `(1 − day)²` (ART-072). (source: PRD-1.1 §4 D3; UX-VISION §7 "hi-tech: city lights on the night side")
- **ART-023** {M11} [M][W][P] **Size:** in a portrait the disk radius is `0.55 + 0.08 × sizeClass` of the half-frame (tiny 0.55 … gargantuan 0.95), reduced when the planet has a natural ring so that the ring's outer edge stays inside 0.98 of the half-frame; a mini-planet (`fillsFrame`) fills its frame and draws no ring, and on the map its radius follows MAP's glyph radius table (MapStyle). **Government** adds one motif from `GovernmentMotif` (an exhaustive table over the 17 governments), drawn as a vector overlay above the sphere: `debrisField` (anarchy), `defensePlatforms` (military, dictatorship, fascist), `beacons` (capitalist, corporate, confederacy), `grid` on the night side (cybernetic, technocracy, communist, socialist), `halo` (pacifist, satori, theocracy), `none` (democracy, feudal, monarchy). (source: UX-VISION §4.1, §7; Model/Enums.swift `PoliticalSystemType`)
- **ART-024** {M11} [M][W][P] **Known resource** decides the planet class and tint through the table of ART-069, so the picture is truthful about what the player knows; nothing (`.nothing`) and unknown use the seed-weighted class (ART-068) and give the same recipe apart from `look`. Each of the 12 real resources renders differently from the seed look. (source: Model/Enums.swift `SpecialResource`; World.swift `knownResource`; ECO-007; PRD-1.1 §4 D3)
- **ART-025** {M11} [M][W][P] **Pressure overlay** (only when `pressure != nil`): war: emissive fire points in the auxiliary map that flicker (steady under Reduce Motion) under dark smoke; plague: a sickly yellow-green haze; drought: a lower sea level and desaturated land; boredom: none; cold: enlarged ice; crop failure: brown patches on fertile land; employment: none. The overlay is a decoration only; the pressure tag text (UI-SHELL-054) stays the primary signal. (source: Model/Enums.swift `SystemPressure`; UX-VISION §1.7 "Color is never the only signal")
- **ART-026** {M11} [M][W][P] **Motion:** the surface turns once per 24 s of `phase`, the cloud layer once per 20 s and a gas giant's bands once per 15 s (`PlanetSphere.surfacePeriod`, `cloudPeriod`, `bandPeriod`); all three divide the app's 600 s phase wrap, so `phase = 600` renders exactly as `phase = 0` and nothing jumps. Under Reduce Motion `phase = 0`. Under Reduce Transparency clouds are opaque; under Increase Contrast the disk gets a rim stroke 1.5× wide. (source: PRD-1.1 §4 D4; UX-VISION §4.1)

### 5a. Sphere-projected planets (1.1)

- **ART-068** {M14} [M][W][P] **Class taxonomy.** `PlanetClass: Int, CaseIterable, Sendable` has 10 cases in this order: `terran, ocean, desert, ice, jungle, rocky, barren, volcanic, toxic, gasGiant`. With no known resource (nil or `.nothing`) the class is seed-weighted by the table `terran 22, ocean 10, desert 12, ice 10, jungle 8, rocky 12, barren 8, volcanic 6, toxic 4, gasGiant 8`; `gasGiant` has weight 0 below size class 3 (large), so gas giants appear only at large, huge and gargantuan sizes. A natural ring is a modifier, not a class: probability 0.6 for gas giants, 0.08 for ice, rocky and barren worlds, 0 otherwise; never on a mini-planet. Test over 2,000 seeds per size: every class occurs, the shares follow the weights within 5 percentage points, and no gas giant occurs below size 3. (source: PRD-1.1 §4 D3)
- **ART-069** {M14} [M][W][P] **Resource-to-class table** (`PlanetClass.forResource`, exhaustive over the 13 `SpecialResource` raw values, tint in brackets): 0 nothing → seed-weighted; 1 mineral rich → `rocky` [rust and ore, metallic glints]; 2 mineral poor → `rocky` [dull grey]; 3 desert → `desert`; 4 sweet oceans → `ocean`; 5 rich soil → `terran` [dark fertile green]; 6 poor soil → `terran` [pale, dry]; 7 rich fauna → `jungle`; 8 lifeless → `barren`; 9 weird mushrooms → `toxic` [violet fungal patches]; 10 special herbs → `jungle` [teal herb fields]; 11 artistic → seed-weighted with a warm amber atmosphere; 12 warlike → seed-weighted with a red-tinted atmosphere. The table is total over size × resource (test: every pair gives a class, and resources 1…10 give the listed class at every size). (source: PRD-1.1 §4 D3; Model/Enums.swift `SpecialResource`)
- **ART-070** {M14} [M][W][P] **Baker.** `PlanetTextureBaker.bake(_ recipe: PlanetRecipe, lod: PlanetLOD) -> PlanetMaps` is pure, `Sendable` and deterministic. It evaluates seeded 3D fBm value noise (`PlanetNoise`, integer-hashed lattice, no tables read from outside) on the unit sphere, so the maps are seamless in longitude and undistorted at the poles. `PlanetMaps` holds two equirectangular RGBA8 buffers of the LOD's size (`hero` 512×256, `still` 128×64, `mini` 64×32, and `cinema` 1024×512, asked for by name by the endings' limb views, ART-084/085): **albedo** (sRGB colour; alpha = the water and specular mask) and **aux** (`r` cloud density, `g` city lights, `b` emissive: lava and war fires, `a` height). Rows are baked in parallel, which never changes the bytes. Tests: two bakes are byte-identical; a bake on a background task equals a main-actor bake; the three LODs of one recipe sample the same field (their mean albedo colours and water shares agree within 4%). (source: PRD-1.1 §4 D1)
- **ART-071** {M14} [M][W][P] **Class looks** are recognisable from map statistics, weighted by each texel's area on the sphere (test over 12 seeds per class, still LOD): `desert` and `barren` and `rocky` and `volcanic` have no water pixels; `ocean` is ≥ 80% water; `terran` has 40–80% water; `ice` has mean luminance ≥ 0.70; `jungle` land is green-dominant (mean land green > red and > blue); `barren` has no clouds and low saturation; `volcanic` has emissive pixels on 2–30% of the map; `toxic` has ≥ 55% mean cloud density; `gasGiant` has no water and is banded (the variance of row means exceeds 4× the mean variance within rows) with no city lights. Two terran recipes with different seeds differ in ≥ 25% of albedo texels. (source: PRD-1.1 §6 M14 tests and look criteria)
- **ART-072** {M14} [M][W][P] **Projector.** `PlanetSphere.project(_ maps: PlanetMaps, uniforms: PlanetSphere.Uniforms, pixelSize: Int) -> CGImage?` returns a square premultiplied RGBA8 sRGB image of exactly `pixelSize` pixels: an orthographic ray–sphere projection of the maps (bilinear, wrapping in longitude) with axial tilt, a soft day/night terminator from one light direction (`PlanetSphere.lightDirection`, upper left, towards the viewer), height-map relief, an ocean glint from the water mask, a separate cloud layer with its own turn and a shadow offset towards the light, city lights weighted `(1 − day)²`, emissive glow on both sides, limb darkening, an atmosphere rim inside the limb and a halo outside it on the lit side, and an analytic ring (a tilted annulus with bands, a gap and the planet's shadow, drawn behind and in front of the disk). Pixels outside the disk, halo and ring are transparent; the limb is anti-aliased over one pixel. Rows are projected in parallel; the result is deterministic. Tests: the image has the requested size; the corner pixels are transparent; the lit limb is brighter than the dark limb; a ringed recipe covers more width than the same recipe without the ring; two tilts differ; twice is byte-identical. (source: PRD-1.1 §4 D1, §3 "Realistic planet technique")
- **ART-073** {M14} [M][W][P] **Shared uniforms.** `PlanetSphere.Uniforms` is a `Sendable` value of twelve `SIMD4<Float>` fields (192 bytes, the layout of the shader's `Uniforms` struct): viewport, turn, light, atmosphere, cloud, night, emissive, surface, haze, ring, ringColor, ringNormal. `PlanetSphere.uniforms(recipe:phase:accessibility:pixelSize:radius:)` is the only place that turns a recipe and a phase into rendering parameters; the CPU projector and the app's Metal shader both consume it and nothing else. `phase` enters only through the turns (ART-026) and the war flicker (whole cycles per 600 s). Test: `MemoryLayout<Uniforms>.size == 192`; uniforms at phase 0 and 600 are equal; phase 6 differs. (source: PRD-1.1 §4 D2)
- **ART-074** {M14} [UI] [M][W][P] **GPU/CPU parity.** `PlanetSphereShader.source` (Metal source in a Swift string, app target, no `.metal` file) compiles with `MTLDevice.makeLibrary(source:)`. An offscreen Metal render of a recipe at 256 px and the CPU projection with the same maps and uniforms agree with a mean absolute difference ≤ 3/255 per channel, for a terran, a gas giant with a ring and a volcanic world. When the test host has no Metal device the test records the skip in its output and passes. (source: PRD-1.1 §4 D2, §6 M14 tests)
- **ART-075** {M14} [UI] [M][W][P] **Fallback.** `PlanetPortrait` shows the live Metal view only when `PlanetLiveSupport.mode(reduceMotion:deviceAvailable:pipelineReady:)` returns `.live`; under Reduce Motion, with no Metal device, or when the pipeline failed to compile it shows the CPU still (`PlanetArt` at `phase = 0`), and while the hero maps are being baked off the main actor it shows the still from the smaller LOD. ## 12. App icon pipeline

> Format facts verified on 2026-11-17 with Xcode 27.2 (`actool` 27.2, bundle 25408): an Icon Composer document is a folder `AppIcon.icon/` holding `icon.json` and `Assets/<layer>.png`. `icon.json` keys seen in a real bundle: `fill-specializations` (`value` `automatic`, optional `appearance: dark`), `groups[]` each with `layers[]` (`image-name`, `name`, `glass`, `hidden`), `shadow` (`kind` `neutral`, `opacity`), `translucency` (`enabled`, `value`), and `supported-platforms` (`squares: "shared"`, `circles: ["watchOS"]`). `xcrun actool --compile <out> --platform macosx --minimum-deployment-target 27.0 --app-icon AppIcon --output-partial-info-plist <p> AppIcon.icon` compiles it with no warnings into `Assets.car` (IconGroup renditions plus generated fill colours/gradients) and `AppIcon.icns`, and writes `CFBundleIconFile`/`CFBundleIconName = AppIcon`.
