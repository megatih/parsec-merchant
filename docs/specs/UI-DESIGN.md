# UI-DESIGN: design system and platform conventions

> Format (PRD §7): `- **ID** {Mn} [UI] [M][W][P] statement`. `[M]` Modern, `[W]` Windows 2.01, `[P]` Palm 1.2.2. `[UI]` = verified by app tests hosted in the app or by XCUITest.
> Milestones: M18–M28 (`docs/PRD-UI-Revamp.md` §7). The first number on the PROGRESS status line is the last finished milestone; an ID becomes due when its milestone is finished.
> Normative input: `docs/PRD-UI-Revamp.md` §3, which holds the wireframes, tables and reasons. These bullets are the testable statements; where a bullet and the PRD differ, fix the bullet.

## UI-DS

- **UI-DS-001** {M21} [M][W][P] The main window's content minimum is 1200 × 680 pt and its default is 1440 × 860 pt, defined once in `SceneMetrics`. `-PMWindowSize min|default` applies those two sizes.
- **UI-DS-002** {M21} [M][W][P] **Interface scale.** `s = clamp(min(W / 1200, H / 680), 1.0, 2.0)`, rounded down to a multiple of 0.05, where W × H is the window's content size. Every font size, spacing token, control size and fixed panel dimension in the game area is multiplied by `s`. `s` is published in the environment (`\.pmScale`).
- **UI-DS-003** {M21} [M][W][P] **Leftover space.** Space beyond `1200·s × 680·s` goes to the flexible regions named in each wireframe (on the Bridge: the chart and the cargo rows). No element is added or removed at any size.
- **UI-DS-004** {M27} [M][W][P] **Text Size.** The in-app Text Size setting has five steps that set the lower clamp of `s`: Standard 1.0, Large 1.15, Larger 1.3, Extra Large 1.5, Largest 2.0 (the HIG asks for enlargement up to 200% where possible, and macOS has no Dynamic Type). A step raises the window minimum to `1200·floor × 680·floor`. A step whose minimum does not fit the main screen's visible frame is disabled with a help tag giving the reason; entering full screen or enlarging the window always remains a way to get larger text, because `s` follows the window. This replaces the 0.85–2.0 `textScale` range; a stored value maps to the nearest available step at or below it.
- **UI-DS-010** {M21} [M][W][P] Contrast, computed by a unit test with the WCAG relative-luminance formula: `textPrimary` and `textSecondary` on `panel`, `panelRaised` and `panelInset` ≥ 7:1; every signal and role colour on `panel` ≥ 4.5:1; `textDisabled` on `panel` ≥ 4.5:1; `strongLine` and `accent` against `panel` ≥ 3:1. If a hex value in the table fails, adjust its lightness until it passes and record the new value in this table.
- **UI-DS-011** {M21} [M][W][P] With Increase Contrast on, `hairline` is replaced by `strongLine`, `textSecondary` by `textPrimary`, and panel borders are 2 pt.
- **UI-DS-012** {M21} [M][W][P] Every use of `profit`, `loss`, `caution` or a role colour is paired with a symbol or word from the `ColorSignal` catalogue (`APP/Accessibility/DisplayStyles.swift`), which is extended to list every pairing. A unit test iterates the catalogue and asserts each entry has a non-colour twin.
- **UI-DS-020** {M21} [M][W][P] Tokens exist as `PMColor`, `PMFont`, `PMSpace`, `PMRadius`, `PMMotion` in `APP/Design/`.
- **UI-DS-021** {M27} [M][W][P] Source audit: under `APP/Views/` and `APP/Map/` (except `MapStyle.swift`) there is no `Color(red:`, `Color(.s`, `Color.red|green|blue|orange|yellow|purple|pink`, `.foregroundStyle(.red|.green|.orange|.yellow|.blue)`, no `.font(.system(size:`, and no `cornerRadius:` literal other than through `PMRadius`.
- **UI-DS-022** {M27} [M][W][P] Source audit: no `.padding(` with a numeric literal under `APP/Views/`; padding uses `PMSpace`.
- **UI-DS-023** {M27} [M][W][P] Source audit: `GroupBox`, `Form`, `NavigationSplitView`, `.inspector(` and `.toolbar` do not appear under `APP/Views/` except in `Views/Settings/`, `Views/About/` and `Views/Developer/`.
- **UI-DS-024** {M25} [M][W][P] Source audit: `.glassEffect(` and `GlassEffectContainer` appear nowhere in the app target; `.popover(` stays banned.
- **UI-DS-030** {M21} [M][W][P] Each component exists, has an accessibility identifier parameter, applies `PointerTarget.minimum`, uses the system focus effect when keyboard-focused (a custom 2 pt `accent` ring only where the system effect cannot draw, such as a `Canvas` selection), has a visible pressed state, and has a unit test that renders every state without clipping at `s` = 1.0, 1.3 and 2.0.
- **UI-DS-031** {M21} [M][W][P] A disabled `PMButton` always carries a help tag with the reason from `ReasonText`; the initializer takes the reason so it cannot be omitted. The existing audit "every `.disabled` has a `.help`" stays.
- **UI-DS-032** {M27} [M][W][P] Every interactive component instance has an `.accessibilityIdentifier` matching `AXID.pattern`, an accessibility label that does not depend on colour or position, and a help tag (§3.6).

## UI-HIG

- **UI-HIG-001** {M27} [UI] [M][W][P] **Menu bar.** Menus in this order: App, File, Edit, View, Trade, Game, Encounter, Window, Help. Titles and items are in title case; an item ends with "…" only when it needs more input before acting. Every command reachable by a button in the game area also has a menu item (the list is §4.15) with the same name, and both are enabled and disabled by the same `MenuRules` entry.
- **UI-HIG-002** {M27} [UI] [M][W][P] **Reserved shortcuts** are never rebound: ⌘Q, ⌘W, ⌥⌘W, ⌘H, ⌥⌘H, ⌘M, ⌥⌘M, ⌘, (Settings), ⌘` , ⌘Tab, ⌃⌘F (full screen), ⌘?, ⌘., ⌘N/⌘O/⌘S/⇧⌘S/⌘P, ⌘Z/⇧⌘Z, ⌘X/⌘C/⌘V/⌘A, ⌘F/⌘G (Find only), ⌘Space, ⌥⌘D, ⇧⌘3/4/5, ⌘F5, ⌥⌘8. No binding uses Control as its only modifier. `KeyAudit` asserts no binding in `KeyBindingTable` collides with them or with another binding in the same context.
- **UI-HIG-003** {M27} [UI] [M][W][P] **Full keyboard operation.** With the system's keyboard navigation on, Tab and ⇧Tab reach every control on every page in reading order (left to right, top to bottom, panel by panel); Space or Return activates; arrow keys move within the cargo table, the chart, segmented controls and lists; Esc goes back (§4.1). A UI test completes the whole core loop without the pointer (UI-BRG-041).
- **UI-HIG-004** {M27} [UI] [M][W][P] **Help tags.** Every control has one. Wording follows the HIG: a brief phrase of at most 75 characters that says what the control does, starting with a verb, in sentence case, with no ending punctuation and without repeating the control's name; the shortcut follows in parentheses if there is one (for example "Buy as many as cash and bays allow (⇧B)"). A unit test checks length, ending punctuation and that the text differs from the control's label. A disabled control's help tag is the reason instead.
- **UI-HIG-005** {M27} [UI] [M][W][P] **VoiceOver.** Every control and every value has a label; a value is read with its unit and its label ("Cash, 12,345 credits"); a cargo row is one element with a full sentence value and custom actions Buy, Buy Maximum, Sell, Sell All; drawn art has a label from `ArtSurfaceAccessibility`; the existing rotors stay and gain "Cargo Rows". Announcements stay with `Announcer`.
- **UI-HIG-006** {M27} [UI] [M][W][P] **System settings are respected:** Reduce Motion, Reduce Transparency (already satisfied: no materials), Increase Contrast (UI-DS-011), Differentiate Without Colour (already satisfied by UI-DS-012, and patterns on gauges). `-PMA11y` keeps overriding them for tests.
- **UI-HIG-007** {M21} [UI] [M][W][P] The window supports full screen and standard title-bar behaviour; closing the main window does not quit (unchanged); the app keeps one Settings window (⌘,) for app-wide settings and uses the Options page for per-game options.
