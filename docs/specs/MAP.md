## Conventions (normative for every bullet below)

- **No `.popover`.** Hover cards, the legend, search suggestions and the route panel are SwiftUI overlays above the `Canvas` (PRD §6.5; UI-SHELL Conventions; UI-SHELL-108 lint rule).
- **One component.** The Galaxy section, the Galaxy Chart window and the Bridge mini chart all use the same `GalaxyMapView`, configured by a `MapScope` value (`galaxy`, `galaxyWindow`, `miniChart`). `MapScope` supplies the identifier prefix (`galaxy.`, `galaxyWindow.`, `bridge.miniChart.`) so that a UI test never sees two elements with the same identifier when the section and the window are both on screen.
- **Pure core.** Projection, viewport arithmetic, hit testing, glyph styling, label layout, hover-card content, pointer-to-command mapping, search, accessibility text and rotor membership are pure functions over Sendable values (`MapSnapshot`, `MapViewport`, `MapProjection`). They import Foundation/CoreGraphics only, never touch `GameSession`, and are unit-tested without a window. Views only wire them up.
- **Commands only through the session.** Every map action is a `Command` sent with `GameSession.send(_:)` (UI-SHELL-003). The map never mutates `GameState`.
- **Fairness.** The map shows only what the player legitimately knows (PRD §6.6 "Fairness"): never an unvisited system's true resource, stock, prices or special event.
- **Localization.** Every string (labels, legend, hover card, accessibility text, rotor names) comes from `Localizable.xcstrings`; system names are data (`Text(verbatim:)`); distances use the plural-aware "N parsecs" entry.

## 1. Snapshot and data flow

- **MAP-001** {M8} [M][W][P] `MapSnapshot` (app, `SpaceTraderMac/Map/MapSnapshot.swift`) is a `Sendable, Equatable` value built by `MapSnapshot.make(state: GameState, generation: Int, route: Route?)`. Fields: `generation`, `galaxyWidth`, `galaxyHeight` (from `ruleset.tables`), `distanceRule` (`ruleset.flags.distance`), `systems: [MapSystem]`, `wormholes: [Int]` (ring order), `currentSystem`, `warpSystem`, `targetWormhole`, `trackedSystem`, `fuel`, `fuelCapacity`, `showTrackedRange`, `wormholeSelectionScope` (`ruleset.flags.travel.wormholeSelectionScope`), `isDocked`, `route`. `MapSystem` holds `index`, `name`, `x`, `y`, `size`, `techLevel`, `politics`, `visited`, `knownResource`, `police` and `pirates` levels (as the Bridge target card shows them, UI-SHELL-059), `wormholeDestination: Int?`, `distance` (from the current system, ruleset rule), `squaredDistance`, `inRange`, `questKinds: [QuestLogKind]` and `hasSpecialEventHere`. (source: PRD §6.5 "Sendable snapshots"; World.swift `StarSystem`, `Galaxy`)
- **MAP-002** {M8} [M][W][P] Fairness of the snapshot: it reads `knownResource` (never `specialResource`), takes quest markers only from `GameState.questLog` systems, takes `hasSpecialEventHere` only from `specialEventAvailable` for the current system, and reads no market stock, prices, `specialEvent` field or RNG state. A unit test builds two states that differ only in hidden fields (an unvisited system's true resource, special event, stock and price inputs) and checks the snapshots are equal. (source: PRD §6.6 "Fairness"; World.swift `knownResource`; SpecialEvents.swift `specialEventAvailable`)
- **MAP-003** {M8} [M][W][P] `GameSession.stateGeneration: Int` increases on every accepted step (including target, track and option changes), on load, on new game and on close; `GameSession.mapSnapshot` is rebuilt only when the generation or the planned route changes. Hover, pan, zoom and window resizes never rebuild it; a unit test counts builds across 100 viewport changes and one `selectTarget`. (source: PRD §8.1 performance; UX-VISION §4.7)
- **MAP-004** {M8} [M][W][P] `MapSystem.inRange` equals `GameState.destinationOK(i)` for every system (wormhole partner included, current system excluded), and `distance` equals `GalaxyGenerator.distance(current, i, rule:)`. A unit test compares against `GameState.destinations` for fresh games of every ruleset and for fuel values 0…`fuelCapacity`. (source: Travel.swift `destinationOK`, `destinations`; C# `StarSystem.DestOk`)

## 2. Projection and viewport

- **MAP-005** {M8} [M][W][P] `MapProjection { scale: Double /* points per parsec */, origin: CGPoint /* galaxy coordinate at the view's top-left */ }` maps galaxy to view as `v = (g − origin) × scale` and back as `g = v / scale + origin`. The y axis grows downward, as in both classic charts (no flip). A unit test checks round trips to within 1e-9 for random points and scales. (source: Form_SpaceTrader.cs:3829-3871 draws `X + OFF_X, Y + OFF_Y`; WarpFormEvent.c:210-260)
- **MAP-006** {M8} [M][W][P] The content rectangle is the galaxy plus a 4-parsec margin: `[−4, galaxyWidth + 4] × [−4, galaxyHeight + 4]`, with width and height read from `ruleset.tables` (154×110 for Modern and Windows 2.01, 150×110 for Palm), never hard-coded. Unit test per ruleset. (source: Ruleset.swift `galaxyWidth`/`galaxyHeight`; Form_SpaceTrader.cs:270-272 `OFF_X`/`OFF_Y` = 3)
- **MAP-007** {M8} [M][W][P] `MapProjection.fitScale(viewSize:content:)` = `min(viewWidth / contentWidth, viewHeight / contentHeight)`. Golden value: an 800×600 view of a 154×110 galaxy (content 162×118) gives 800/162 = 4.938…; the Palm galaxy (158×118) gives 5.063…. (source: UX-VISION §4.7 "Fit Galaxy")
- **MAP-008** {M8} [M][W][P] `MapViewport { zoom: Double, center: CGPoint /* galaxy coordinates */ }` is resolution-independent: `scale = fitScale(viewSize) × zoom` and `origin = center − viewSize / (2 × scale)`. Resizing the window keeps `zoom` and `center`. Unit test: resizing a viewport keeps the galaxy point at the view centre fixed. (source: UX-VISION §2 "large, detachable map")
- **MAP-009** {M8} [M][W][P] Limits: `zoom ∈ [1, 12]` (1 = Fit Galaxy). `center` is clamped to the galaxy rectangle `[0, galaxyWidth] × [0, galaxyHeight]`; at `zoom == 1` it is forced to the content centre. Every viewport operation returns a clamped value; unit tests cover each edge. (source: UX-VISION §4.7)
- **MAP-010** {M8} [M][W][P] `MapViewport.zoomed(by factor:, anchor: CGPoint, viewSize:)` keeps the galaxy point under `anchor` under `anchor` after the zoom, unless a clamp applies. `panned(byViewDelta:)` moves the centre by `−delta / scale`. Unit tests with fixed values. (source: UX-VISION §4.7 "pinch … to zoom")
- **MAP-011** {M8} [M][W][P] `MapViewport.fitGalaxy` is `zoom 1` at the content centre. `MapViewport.fitRange(snapshot:viewSize:)` centres on the current system and picks the zoom at which a circle of radius `max(R, 5)` parsecs plus a 20% margin fills the shorter view side, where `R` is the range-ring radius of MAP-030 (clamped by MAP-009). Unit tests with fixture snapshots. (source: UX-VISION §4.7 "Fit Range and Fit Galaxy buttons")
- **MAP-012** {M8} [M][W][P] `MapViewport.centered(on: systemIndex, snapshot:)` sets the centre to the system (clamped) and raises the zoom to at least 3. Search, Show on Map and rotor navigation use it. Unit test. (source: UX-VISION §4.7 "Find … focusing the map")

## 4. Hit testing

- **MAP-019** {M8} [M][W][P] `MapHitTester.hit(at: CGPoint, snapshot:, projection:, metrics: GlyphMetrics) -> MapHit?`, with `MapHit` = `.system(Int)` or `.wormhole(Int)` (the wormhole glyph beside system `i`). Candidates are every system centre and every wormhole glyph centre (MAP-033) inside the view bounds. The result is the candidate nearest to the point (Euclidean, view points) within that candidate's hit radius. Ties go to the system over the wormhole glyph, then to the lower system index. Golden tests use hand-placed snapshots. (source: research 02 pain point 17 "chart hit-testing" moves out of the form; Form_SpaceTrader.cs:3787-3827)
- **MAP-020** {M8} [M][W][P] Hit radii are `max(glyphRadius + 4, 8)` pt for a system and `max(wormholeGlyphRadius + 3, 6)` pt for a wormhole glyph. They replace the classic ±2 px squares (C#) and ±1 px / ±3 px squares (Palm), which were too small to hit reliably. (source: Form_SpaceTrader.cs:3799-3818; WarpFormEvent.c:484-506; research 02 pain point 4)
- **MAP-021** {M8} [M][W][P] Property test over 200 seeds per ruleset at Fit Galaxy in an 800×600 view: hitting the exact centre of every system returns `.system(thatIndex)` (or the lower index when two systems share coordinates), and hitting the exact centre of every wormhole glyph returns `.wormhole(thatIndex)` or a system whose centre is nearer. (source: GalaxyGenerator.swift placement with `minDistance`; MAP-019)
- **MAP-022** {M8} [M][W][P] Points outside the view bounds and points within no radius return nil. The mini chart uses the same hit tester with its own projection (MAP-074). (source: Form_SpaceTrader.cs:3873-3921 uses a separate short-range test; unified here)

## 7. Range ring

- **MAP-033** {M8} [M][W][P] Engine: `DistanceRule.maxSquaredDistance(withinRange r: Int) -> Int` returns the largest integer `dx² + dy²` whose distance under the rule is at most `r`: `.floor` → `(r + 1)² − 1`; `.rounded` → `r² + r`; `r < 0` → `−1`. Package test: for every `sq` in 0…6400 and `r` in 0…40, `(sq ≤ maxSquaredDistance(r))` equals `distance(sq) ≤ r` as `GalaxyGenerator.distance` computes it. (source: GalaxyGenerator.swift `distance`, `palmSqrt`; Functions.cs:83-86; Math.c:44-55; GAL-008)
- **MAP-034** {M8} [M][W][P] The `rangeRing` layer draws a circle centred on the current system with radius `√maxSquaredDistance(fuel)` parsecs × scale, a translucent `MapRange` fill and a 1.5 pt stroke; nothing is drawn when `fuel == 0` (C# `if (fuel > 0)`). Because coordinates are integers, a system lies inside or on the ring iff it is in non-wormhole range under the ruleset's `DistanceRule`. Unit test over fixtures: every system with `squaredDistance ≤ maxSquaredDistance(fuel)` is within the ring radius (+1e-9) and every other system is outside it. (source: UX-VISION §4.7 "fuel range circle"; Form_SpaceTrader.cs:3839-3840; WarpFormEvent.c:233-235)
- **MAP-035** {M8} [M][W][P] Deliberate deviation: the C# and Palm charts draw radius = fuel, which places reachable systems (for example at 14.6 parsecs with 14 fuel under `floor`) outside the circle. Parsec draws the true boundary of MAP-034 in every ruleset; game rules are unchanged. (source: Form_SpaceTrader.cs:3840; UX-VISION §1.6 "Modernization only removes friction")
- **MAP-036** {M8} [M][W][P] When `fuel < fuelCapacity`, the `fullTankRing` layer draws a dashed, unfilled ring of radius `√maxSquaredDistance(fuelCapacity)`, which is the per-hop limit the route planner uses (MAP-054). It is hidden at a full tank. With Differentiate Without Color on, both rings carry a text label ("Range 11", "Full tank 14") at their top. Unit test of the radii and visibility. (source: UX-VISION §4.7 "fuel range circle", §9 "Color pairing")

## 12. Route planner (ParsecInsights)

- **MAP-054** {M8} [M][W][P] API in `ParsecInsights` (pure, `Sendable`, no RNG, callable from any isolation):
  - `RouteSnapshot` (Sendable, Equatable), built by `init(_ state: GameState)`. Fields: `points: [(x, y)]`, `wormholes: [Int]`, `distanceRule`, `fuelCapacity`, `currentFuel`, `fuelCostPerParsec`, `wormholeTax` (MAP-093), and `perWarpCosts` = mercenaries + insurance + interest of `dailyCosts`.
  - `enum RouteObjective { case fewestJumps, cheapest }`. `lowestRisk` is {M10}.
  - `enum RoutePlanner` with `static func plan(from: Int, to: Int, in: RouteSnapshot, objective: RouteObjective = .fewestJumps) -> Route?` and `static func jumpCounts(from: Int, in: RouteSnapshot) -> [Int?]`.

  Tested in `ParsecInsightsTests`. (source: PRD §6.5 "route planning … runs off the main actor on Sendable snapshots", §6.6 "route planner: Dijkstra over in-range hops plus wormholes"; UX-VISION §4.7 "Route planner")
- **MAP-055** {M8} [M][W][P] Graph: nodes are systems. A directed edge a→b (a ≠ b) is a **wormhole edge** when `wormholeExists(from: a, to: b)`: it uses 0 fuel and costs `wormholeTax + perWarpCosts`. Otherwise it is a **normal edge** iff `distance(a, b, rule) ≤ fuelCapacity`: it uses `distance` fuel and costs `distance × fuelCostPerParsec + perWarpCosts`. A wormhole edge replaces any normal edge between the same pair, because the engine always counts that warp as via the wormhole. `jumpCounts` is a breadth-first search over these edges: 0 at `from`, nil when unreachable. (source: World.swift `wormholeExists`; Travel.swift `warpTargetPreview` `via`, `fuelAfter`; ShipMath.swift `wormholeCosts`; Bank.swift `dailyCosts`)
- **MAP-056** {M8} [M][W][P] Refuel assumption: fuel can be bought at every stop (docked), so every normal hop is limited by `fuelCapacity`, not by the current fuel. The planner simulates fuel from `currentFuel`: before a normal hop with less fuel than its distance it buys exactly the shortfall (`refuelUnits`, `refuelCost = refuelUnits × fuelCostPerParsec`); wormhole hops use no fuel. Costs are estimates because mercenaries, insurance and interest are taken at their current values. Unit tests with a fixture whose first hop needs fuel and whose second is a wormhole. (source: Services.swift `fuelCapacity`, `fullTankCost`; C# fuel is sold at every system, Form_BuyFuel)
- **MAP-057** {M8} [M][W][P] Objectives are lexicographic Dijkstra keys: `fewestJumps` = (jumps, parsecs, credits) and `cheapest` = (credits, jumps, parsecs), where a wormhole hop adds 0 parsecs and credits are edge costs. (source: UX-VISION §4.7 "the fewest-jumps route or the cheapest route")
- **MAP-058** {M8} [M][W][P] Deterministic tie-breaking: the frontier is ordered by (key, system index). When a relaxation reaches a node with an equal key, the predecessor with the lower system index is kept. The same snapshot always gives the same route. A unit test uses a hand-built symmetric snapshot with two equal routes and checks the lower-index route on every run. (source: PRD §6.2 "Determinism")
- **MAP-059** {M8} [M][W][P] `Route { from, to, objective, hops: [RouteHop], totalJumps, totalParsecs, estimatedCredits, totalRefuelUnits }` and `RouteHop { from, to, viaWormhole, distance, fuelBefore, refuelUnits, refuelCost, cost }` are `Sendable, Equatable`. `plan` returns nil when `from == to`, when either index is out of range, or when `to` is unreachable. Unit tests for each nil case. (source: UX-VISION §4.7 "showing costs per hop")
- **MAP-060** {M8} [M][W][P] Property tests over 200 seeds per ruleset and random pairs: every hop is an edge of MAP-055, hops are contiguous from `from` to `to`, `fewestJumps.totalJumps == jumpCounts[to]`, no route is shorter in jumps than the BFS optimum, `cheapest.estimatedCredits ≤ fewestJumps.estimatedCredits`, and the fuel simulation never goes below 0 or above `fuelCapacity`. (source: MAP-055…057)
- **MAP-061** {M8} [M][W][P] Agreement with the engine: when `from` is the current system and `to` is in `destinations` with a full tank, `fewestJumps` returns one hop whose `viaWormhole` equals `warpTargetPreview(to).viaWormhole`, and whose `cost − refuelCost` equals `warpTargetPreview(to).costs.total` plus the fuel used × `fuelCostPerParsec`. Tested for fresh games of every ruleset. (source: Travel.swift `warpTargetPreview`; TRV-086)
- **MAP-062** {M8} [M][W][P] `GameSession.planRoute(to: Int, objective: RouteObjective)` builds the `RouteSnapshot` on the main actor, runs `RoutePlanner.plan` off the main actor (a `nonisolated` async function), and applies the result on the main actor only if `stateGeneration` has not changed (otherwise it discards the result and replans once). `jumpCounts` for the hover card runs the same way once per generation.
