# SAV: Persistence

> Format (PRD §7): `- **ID** {Mn} [M][W][P] statement (source)`. `[M]` Modern, `[W]` Windows 2.01, `[P]` Palm 1.2.2. `[UI]` marks requirements covered by app or UI tests.
> Milestones: the envelope, codec, migrator, `SlotStore`, `HighScoreStore`, the reload and Ironman rules that can be tested without UI are {M6} (ParsecPersistence and ParsecEngine tests); menu commands, Welcome, file panels and Finder open are {M7} [UI]; the game-over presentation is {M9} [UI].
> C# sources are relative to `/Users/megatih/Downloads/SpaceTraderSource201` (read with `iconv -f cp1252 -t utf-8`); Palm sources are `docs/reference/palm-src/Src/…`. Every citation was re-read on 2026-11-17.
> **Persistence is a Parsec Merchant feature, not a ruleset rule.** C# saves a `BinaryFormatter` hashtable; Palm saves a raw `SAVEGAMETYPE` struct into a preferences record, plus one "Snapshot" database and one "Switch Game" database. Neither format is read or written. The classic sources are cited only for the behaviour this spec keeps: version rejection, dirty tracking, abandon prompts, the reload block and the classic save locations that are replaced. Every SAV requirement therefore applies to all three rulesets unless a bullet says otherwise.
> Ownership: the high-score table and its ranking are SCORE (SCORE-029…041); cheats and `cheatsUsed` are CHEAT; per-save options are OPT; alert presentation is ALR (ALR-091, ALR-092, ALR-094). This spec owns the file format, the store layout, autosave, Ironman, `reloadCount`, import and export.
> Root: `SlotStore(root:appVersion:)` and `HighScoreStore(root:)` take an injected directory URL. The app passes `Application Support/Parsec Merchant/` inside its sandbox container; tests pass a fresh temporary directory. Below, `root` means that URL.

## 1. Envelope and canonical JSON

- **SAV-001** {M6} [M][W][P] A save file is one UTF-8 JSON object, the `SaveEnvelope`, with exactly these top-level keys: `format` (the string `"parsec-merchant-save"`), `schemaVersion` (Int ≥ 1), `appVersion` (String), `rulesetID` (the `RulesetID` raw value), `gameID` (String), `generation` (Int ≥ 1), `summary` (`SaveSummary`), `state` (`GameState`) and, from M10, `journal` (`GameJournal`, LOG-001…004, ADR-0003). (source: PRD §6.4; research 06 §B "Saves")
- **SAV-002** {M6} [M][W][P] `SaveSummary` holds `commander` (commander name), `day` (`commander.days`), `worth` (`GameState.worth`, so the ruleset's worth rule of RUL-119/MOD-019 applies), `system` (the current system's id, which is also its index in the ruleset's system-name table), `ironman` (`state.ironman`), `cheatsUsed` (`state.cheatsUsed`) and `ended` (true iff `state.phase` is `.gameOver`). The summary is always derived from `state` when the envelope is built; a decoded summary is display data only and is never used for game logic. (source: PRD §6.4; UX-VISION §2 "list of recent saves")
- **SAV-003** {M6} [M][W][P] `SaveEnvelope(state:appVersion:)` sets `format`, `schemaVersion = SaveMigrator.currentSchemaVersion`, `rulesetID = state.rulesetID` and the summary from the state. `appVersion` is informational: no load, migration or compatibility decision reads it. `gameID` and `generation` are assigned by `SlotStore` when the envelope is written (SAV-031, SAV-032). (source: PRD §6.4)
- **SAV-004** {M6} [M][W][P] `SaveCodec.encode(_:) -> Data` writes UTF-8 JSON with lexicographically sorted keys at every level, no escaped forward slashes and non-ASCII characters written as UTF-8 (not `\u` escapes). The output depends only on the envelope's value: no dates, locale, dictionary iteration order or process state enter it, and encoding the same envelope twice gives identical bytes. (source: PRD §6.4)
- **SAV-005** {M6} [M][W][P] Round trip: for every envelope `e`, `decode(encode(e)) == e` and `encode(decode(encode(e)))` is byte-identical to `encode(e)`. The M6 exit test checks this over 500 states sampled from `pmsim fuzz` across all three rulesets, including states in every `GamePhase` (docked, in transit, mid-encounter with pending scoop or plunder, game over). (source: PRD §9 M6 exit criteria)
- **SAV-006** {M6} [M][W][P] Integer fidelity: every `UInt64` and `Int` in `GameState`, including the RNG state words, the seed and values equal to `UInt64.max`, `Int.min` and `Int.max`, survives `encode` → `decode` exactly, including through the raw-JSON migrator path of SAV-012. `GameState` holds no floating-point fields; a test asserts that the encoded `state` object contains no JSON number with a fraction or exponent. (source: PRD §6.4; RNG.md state layouts)
- **SAV-007** {M6} [M][W][P] A commander or ship name containing non-ASCII text (for example `Zoë 🚀`) and JSON-special characters (`"`, `\`, `/`) round-trips exactly per SAV-005. (source: PRD §6.4)

## 2. Decoding, validation and errors

- **SAV-008** {M6} [M][W][P] `SaveCodec.decode(_:)` throws `SaveError.notASave` when the data is not a JSON object, or is a JSON object whose `format` is missing or not exactly `"parsec-merchant-save"`. A classic C# `.sav` file (a `BinaryFormatter` stream) and a Palm database are therefore rejected with `notASave`; neither classic format is importable. (source: Functions.cs:187-217 (classic `FileFormatBad`); research 01 §1 "save format can't be read from Swift")
- **SAV-009** {M6} [M][W][P] A save-format object whose `schemaVersion` is missing, not an integer or less than 1 throws `SaveError.corrupt(_)`. One whose `schemaVersion` is greater than `SaveMigrator.currentSchemaVersion` throws `SaveError.unsupportedFutureVersion(v)` before any other validation, carrying the file's version. This replaces C#'s `FutureVersionException` (version string compared with `"2.00"`) and Palm's rejection of preference versions above 1. (source: Game.cs:147-149, :3050, FutureVersionException.cs:29-31, Form_SpaceTrader.cs:2900-2903; Palm: Src/Merchant.c:419-422)
- **SAV-010** {M6} [M][W][P] After migration, typed decoding of the envelope that fails for any reason throws `SaveError.corrupt(reason)`. Decoding also throws `corrupt` when `rulesetID` is not a known `RulesetID`, when it differs from `state.rulesetID`, when `state.galaxy` does not have the ruleset's system count, or when `commander.currentSystem`, `warpSystem` or `trackedSystem` (if set) is not a valid system index. (source: PRD §6.4 "unreadable files")
- **SAV-011** {M6} [M][W][P] `SaveError` has exactly the cases `notASave`, `unsupportedFutureVersion(Int)`, `corrupt(String)` and `migrationFailed(from: Int)`. The `String` payload is diagnostic only; the app maps every case to `SystemAlert.openFailed(file:reason:)` with a localized reason (ALR-091) and never shows the payload as user text. (source: ALR-091; CLAUDE.md "no user-facing strings" rule applies by analogy to persistence)

## 3. Schema migration

- **SAV-012** {M6} [M][W][P] Decoding first parses the data with `JSONSerialization` into a raw `[String: Any]` object and passes it to `SaveMigrator.migrate(_:)`, which applies the steps `n → n+1` in order from the file's `schemaVersion` up to `currentSchemaVersion`, setting `schemaVersion` after each step. Typed decoding runs only on the fully migrated object. (source: PRD §6.4; research 06 §B)
- **SAV-013** {M6} [M][W][P] `SaveMigrator.currentSchemaVersion` is 1 for the first released format. The step table has exactly one step for every version from 1 to `currentSchemaVersion − 1`, with no gaps; a test fails when `currentSchemaVersion` is raised without the matching step and a new fixture. (source: PRD §6.4)
- **SAV-014** {M6} [M][W][P] A missing step for version `n`, or a step that throws, makes `migrate` throw `SaveError.migrationFailed(from: n)`. Migration of an object already at `currentSchemaVersion` returns it unchanged (an identity step chain). (source: PRD §6.4)
- **SAV-015** {M6} [M][W][P] Fixtures: `Packages/ParsecKit/Tests/Fixtures/saves/v<N>/` holds at least one save per ruleset for every schema version ever released, and they are never deleted or edited. A test decodes every fixture to the current version and checks that it re-encodes deterministically and satisfies SAV-010. Fixtures for version 1 are written in M6 from fixed seeds. (source: PRD §6.4 "Fixtures for every schema version stay in the tests forever"; research 06 §A layout)
- **SAV-016** {M6} [M][W][P] Migration is tested with an injected step table (`SaveMigrator.migrate(_:steps:target:)`): a synthetic v1 object goes through two synthetic steps to v3, each step sees the previous step's output, and a throwing second step yields `migrationFailed(from: 2)`. Palm's own 1.1.x → 1.2 upgrade in `FillGlobals` is the precedent for in-place upgrades of old saves. (source: Palm: Src/Merchant.c:236-243, :296-320)

## 4. Store layout and atomic writes

- **SAV-017** {M6} [M][W][P] Layout under `root`: `Saves/slot-<id>.parsecsave` for manual slots, where `<id>` is a lowercase UUID string; `Saves/slot-<id>.parsecsave.bak1` … `.bak3` for their backups; `Saves/autosave.parsecsave` for the autosave; `Corrupt/` for quarantined files; `HighScores.json` for the high-score tables. Directories are created on first write. This replaces C#'s working-directory folders (`save/`, `data/HighScores.bin`, `data/DefaultSettings.bin`, `autosave_*.sav`) and Palm's preference record and two databases. (source: Consts.cs:45-46, Form_SpaceTrader.cs:267-268; Palm: Src/Merchant.c:55-56; PRD §6.4)
- **SAV-018** {M6} [M][W][P] Every write of a save, backup promotion or `HighScores.json` is atomic (write to a temporary file in the same directory, then rename over the target), so the target always holds either the complete old or the complete new bytes. After any successful store operation, `Saves/` contains no temporary files. (source: PRD §6.4)
- **SAV-019** {M6} [M][W][P] The reserved id `"autosave"` names `Saves/autosave.parsecsave`. `SlotStore.newSlotID()` returns a fresh lowercase UUID, never `"autosave"`. (source: PRD §6.4)
- **SAV-020** {M6} [M][W][P] `SlotStore.save(_:slot:gameID:)` (and `autosave(_:gameID:)`) of a non-Ironman state to an existing manual slot rotates its backups first: delete `.bak3`, rename `.bak2` → `.bak3` and `.bak1` → `.bak2`, copy the current main file to `.bak1`, then write the new main file atomically. A new slot has no backups. After `k` saves to one slot it has `min(k − 1, 3)` backups and `.bak1` holds the previous version. The autosave keeps no backups. (source: PRD §6.4 "3 rotating backups")
- **SAV-021** {M6} [M][W][P] Saving a state with `ironman == true` never creates backups, and deletes any existing `.bak1…3` of that slot, so an Ironman game has exactly one file on disk. (source: PRD §4.3 "Ironman mode: one save"; PRD §8.3)

## 5. Listing, loading, deleting

- **SAV-022** {M6} [M][W][P] `SlotStore.list()` returns one `SlotInfo` (`id`, `url`, `summary`, `rulesetID`, `gameID`, `generation`, `modified`, `isAutosave`, `recoveredFromBackup`) for every readable main file in `Saves/` named `slot-<uuid>.parsecsave` or `autosave.parsecsave`, sorted newest first by modification date, ties broken by `id` ascending. Backups, temporary files and other names are ignored, neither listed nor quarantined. A missing `Saves/` directory gives an empty list. (source: PRD §6.4; UX-VISION §2)
- **SAV-023** {M6} [M][W][P] `SlotStore.load(slot:)` returns the decoded, migrated envelope. Loading never modifies the file, except for quarantine and backup recovery (SAV-024, SAV-025). Loading an older schema version does not rewrite the file; the next save writes the current version. (source: PRD §6.4)
- **SAV-024** {M6} [M][W][P] Quarantine: when `list()` or `load(slot:)` meets a main file that fails to decode with `notASave`, `corrupt` or `migrationFailed`, the file is moved (never copied, never deleted) into `Corrupt/` under its own file name, prefixed `1-`, `2-`, … when that name is taken. No store API deletes anything in `Corrupt/`. A file that fails with `unsupportedFutureVersion` is left in place untouched and is omitted from `list()`, because a newer app can read it. (source: PRD §6.4 "Unreadable files move to `Corrupt/`; never delete them")
- **SAV-025** {M6} [M][W][P] Backup recovery: after quarantining an unreadable main file, the store tries `.bak1`, `.bak2`, `.bak3` in that order; the first that decodes is renamed to the main file name and loaded, the other backups keep their names, and the resulting `SlotInfo` (from `list()` or `info(slot:)`; `LoadedGame.recoveredFromBackup` for `loadForPlay`) has `recoveredFromBackup == true` (the app tells the player, ALR-091 family). Unreadable backups met on the way are quarantined too. With no readable backup, `load` rethrows the main file's error and the slot disappears from `list()`. (source: PRD §6.4 "3 rotating backups")
- **SAV-026** {M6} [M][W][P] `SlotStore.delete(slot:)` removes the main file and all its backups. Deleting a slot that does not exist is a no-op without error. Deleting `"autosave"` is allowed. (source: PRD §6.4)

## 6. Import and export

- **SAV-027** {M6} [M][W][P] `SlotStore.importSave(_ data:) throws -> String` decodes and migrates the data (SAV-008…014), then writes it to a new slot with a fresh slot id and a fresh `gameID`, at the current schema version, and returns the slot id. On any decode error nothing is written and the error is rethrown; the source file is never moved or quarantined, because it lives outside the store. (source: PRD §6.4 "Import and export use fileImporter and fileExporter")
- **SAV-028** {M6} [M][W][P] An imported game is never Ironman and always counts as reloaded: the stored state has `ironman = false` and `reloadCount = original + 1`; `cheatsUsed` and every other field are kept unchanged. A file copied out of the sandbox and imported back therefore cannot restore an Ironman game or hide a rewind (PRD §8.3). (source: PRD §4.3, §8.3)
- **SAV-029** {M6} [M][W][P] `SlotStore.exportSave(slot:) throws -> Data` returns `SaveCodec.encode` of the loaded envelope; for a slot already at the current schema the bytes equal the file's bytes. Any slot can be exported, including the autosave and an Ironman slot (whose import then follows SAV-028). (source: PRD §6.4)
- **SAV-030** {M7} [UI] [M][W][P] File › Import… uses `fileImporter` restricted to the UTType `io.github.megatih.parsecmerchant.save` (extension `.parsecsave`); File › Export… ⇧⌘E uses `fileExporter` with the default name `<Commander> – Day <N>.parsecsave`. Opening a `.parsecsave` from Finder (`application(_:open:)`) imports it into a new slot (SAV-027) and then offers to load it. Import or export failures show `SystemAlert.openFailed` or `saveFailed` (ALR-091, ALR-092). (source: PRD §6.4; UX-VISION §2 "Window behavior", §10.1 File menu)

## 7. Game identity and generations

- **SAV-031** {M6} [M][W][P] Every game has a `gameID` (lowercase UUID string) assigned by the app when the game is created (New Game, Quick Start, scenario) and stored in every envelope written for that game, slot or autosave. Loading keeps it; only import assigns a new one (SAV-027). It is persistence metadata, not part of `GameState`, so it never affects engine behaviour or the state hash. (source: PRD §6.4)
- **SAV-032** {M6} [M][W][P] `SlotStore` stamps each written envelope with `generation = 1 + max(generation of every readable main file in Saves/ with the same gameID)`, or 1 if there is none. The newest write of a game therefore always has the highest generation on disk. (source: PRD §8.3 (needed for SAV-035))

## 8. Reload accounting (`reloadCount`)

- **SAV-033** {M6} [M][W][P] `GameState.reloadCount` starts at 0 in a new game, is changed only by SAV-028 and SAV-035, never decreases, and is kept by save, load, export and migration. It feeds the high-score ↺ marker (SCORE-029) and, in Palm, the reload block (SCORE-035, RUL-150). (source: PRD §4.3, §8.3)
- **SAV-034** {M6} [M][W][P] `SlotStore.loadForPlay(slot:revert:currentGameID:) throws -> LoadedGame` loads a slot for play and returns `LoadedGame { state, gameID, slotID, countedAsReload, recoveredFromBackup }` whose `state` is `envelope.state.resumedAfterLoad(countsAsReload:)` (SAV-036), where `countsAsReload` is decided by SAV-035. `currentGameID` is the game in memory, or `nil` when no game is loaded or the loaded game has ended. Loading only to inspect or export uses `load(slot:)` and never changes `reloadCount`. (source: PRD §8.3)
- **SAV-035** {M6} [M][W][P] A load for play counts as a reload iff the state is not Ironman and at least one of these holds: (a) it is a revert (Revert to Autosave); (b) the save's `gameID` equals `currentGameID`, the game currently in memory, and that game has not ended (the app passes `nil` for an ended game, SAV-034); (c) another readable main file with the same `gameID` has a higher `generation`. So resuming the newest save of a game (Continue at launch, switching back to another game's latest slot) is not a reload, and any rewind is. This refines PRD §8.3 ("loading a non-autosave increments `reloadCount`") so that the autosave can't be used to rewind for free and a game saved to a slot and resumed later is not marked. (source: PRD §8.3; Palm: Src/WarpFormEvent.c:704-722, Src/Merchant.c:364 (Palm's Switch Game restores `GameLoaded` rather than setting it))
- **SAV-036** {M6} [M][W][P] `GameState.resumedAfterLoad(countsAsReload:) -> GameState` (ParsecEngine, pure) returns the state with `reloadCount + 1` when `countsAsReload`, and otherwise unchanged except for SAV-037. It draws no random numbers and changes nothing else. (source: PRD §8.3)
- **SAV-037** {M6} [P] Palm's cheat-adjustable chances are not saved between sessions: `resumedAfterLoad` resets `chanceOfVeryRareEncounter` to 5 and `chanceOfTradeInOrbit` to 100 whenever a Palm game is loaded, whatever the save holds (flag `flags.travel.cheatChancesPersist = false`). Windows 2.01 and Modern save and restore both values (`cheatChancesPersist = true`). (source: Palm: Src/Global.c:623-625, Src/Merchant.c:473-480, Src/spacetrader.h:285, :302; Game.cs:160, :3060, :3097)

## 9. Autosave

- **SAV-038** {M7} [UI] [M][W][P] For a non-Ironman game the app writes `Saves/autosave.parsecsave` when the game is created, after every step whose result moves the phase into `.docked` (arrival, including after arrest, escape pod or a direct-warp cheat), when the game ends (the state with `phase == .gameOver`), and on quit through `applicationShouldTerminate` on the `NSApplicationDelegateAdaptor`, whatever the phase. It is never written mid-encounter except on quit. Autosave is always on and has no option (C# turned it on only with the `PlanB` cheat and wrote `autosave_departure.sav` / `autosave_arrival.sav` around each warp). (source: PRD §6.4; UX-VISION §2 "Quitting autosaves"; Form_SpaceTrader.cs:3660-3680, :3336-3343)
- **SAV-039** {M7} [UI] [M][W][P] Because the autosave holds the ended state once a game is over, Revert to Autosave can't undo a death or retirement: File › Revert to Autosave is enabled only when a game is loaded, it is not Ironman, the autosave's `gameID` equals the current game's and the autosave summary is not `ended`. Reverting asks for confirmation and loads with `revert: true` (SAV-035). (source: UX-VISION §10.1 File menu; PRD §8.3)
- **SAV-040** {M7} [UI] [M][W][P] Welcome › Continue loads, with `revert: false`, the newest listed save that is either the autosave or an Ironman slot, and that is not `ended`. It is hidden when there is none. (source: UX-VISION §2 "Welcome")

## 10. Manual save, open and abandon

- **SAV-041** {M7} [UI] [M][W][P] File › Save ⌘S writes the current game to the slot it was last loaded from or saved to; when there is none (new game, or loaded from the autosave), it behaves as Save As. File › Save As… ⇧⌘S always writes a new slot (`newSlotID()`), which becomes the current slot. Both are disabled when no game is loaded or the game has ended. This replaces C#'s "Save reuses the last path, else Save As". (source: Form_SpaceTrader.cs:3715-3733)
- **SAV-042** {M7} [UI] [M][W][P] File › Open Saved Game… ⌘O and Open Recent ▸ (the 10 newest slots) list slots with commander, day, worth, system name, ruleset, Ironman badge, a cheat flag and an "Ended" mark (SAV-002). Opening an ended save shows its game-over card and accepts no commands (SCORE-013). (source: UX-VISION §2, §10.1)
- **SAV-043** {M7} [UI] [M][W][P] Before New Game, Quick Start, Open, loading an import, or Main Menu replaces a non-Ironman, not-ended game whose `commander.days` differs from the days at its last manual save (0 if never saved manually, like C# `SaveGameDays`), the app asks `AppConfirmation.discardUnsavedGame` (ALR-094). Quitting never asks, because quitting autosaves (UX-VISION §2 overrides ALR-094's mention of Quit). (source: Form_SpaceTrader.cs:3228-3240, :3687-3698, :3707-3713, :2911)

## 11. Ironman

- **SAV-044** {M6} [M][W][P] `state.ironman` is set only from `NewGameConfig.ironman` at creation; no `Command` changes it, and only import clears it (SAV-028). (source: PRD §4.3; GameState.swift `NewGameConfig.ironman`)
- **SAV-045** {M6} [M][W][P] An Ironman game lives in exactly one slot whose id equals its `gameID`. It is written there by the same `save(_:slot:gameID:)` call as any slot (with `slot == gameID`), so SAV-021 keeps it free of backups, and `loadForPlay` of it never counts as a reload: SAV-035(c) can't hold with a single file, and (b) is prevented by SAV-047. (source: PRD §4.3 "one save, no manual loading")
- **SAV-046** {M7} [UI] [M][W][P] The app writes an Ironman game's slot when it is created, after every accepted command (a `StepResult` without a rejection), when the game ends, before switching to another game and on quit. It never writes the autosave for an Ironman game, so the autosave can't hold an older Ironman state. (source: PRD §4.3, §8.3)
- **SAV-047** {M7} [UI] [M][W][P] While an Ironman game is loaded: Save As, Revert to Autosave and Open of its own slot are disabled; ⌘S rewrites its slot; opening another save or starting a new game first writes the Ironman slot and never shows `discardUnsavedGame`. The Palm "Timewarp" code is refused in an Ironman game (CHEAT-046). (source: PRD §8.3 "Ironman disables manual loading")
- **SAV-048** {M6} [M][W][P] When an Ironman game ends, its slot is kept with the final state (`summary.ended == true`) and is not deleted automatically, so the log and career card stay viewable. The player may delete it (SAV-026). Its high-score entry is recorded once (SCORE-037) with the Ironman badge (SCORE-029). (source: PRD §4.3; UX-VISION §5.5)

## 12. High-score storage

- **SAV-049** {M6} [M][W][P] `HighScoreStore(root:)` keeps `root/HighScores.json` as `{"format":"parsec-merchant-highscores","schemaVersion":1,"tables":{<RulesetID raw value>: HighScoreTable},"recordedGames":[gameID…]}`, encoded with sorted keys and written atomically. `recordedGames` lists every game already offered to a table, so `record(_:end:gameID:)` runs once per game (SCORE-037). A missing file means every table is empty (SCORE-038). The ranking and insertion logic stays in the engine (`HighScoreTable.inserting(_:eligible:)`, SCORE-036). (source: PRD §6.4 "High scores are the top 10 per ruleset"; Form_SpaceTrader.cs:2771-2778; Consts.cs:45)
- **SAV-050** {M6} [M][W][P] An unreadable `HighScores.json` (not JSON, wrong `format`, or undecodable) is quarantined to `Corrupt/` per SAV-024 and the store continues with empty tables; one with a future `schemaVersion` is left in place, and the store refuses to overwrite it (writes throw `unsupportedFutureVersion`). Tables under ruleset keys this build does not know are kept unchanged when the file is rewritten. (source: PRD §6.4)

## 13. Classic save features mapped

- **SAV-051** {M6} [P] Palm's Snapshot (`SaveGame(1)`, one fixed save) and Switch Game (`SaveGame(2)`, a second commander kept aside, with `SharePreferences`) have no special implementation: both are covered by manual slots, and Palm's Timewarp reload by opening a slot (SAV-035, CHEAT-046). Palm `GameLoaded` is represented by `reloadCount > 0` (SCORE-035). (source: Palm: Src/AppHandleEvent.c:58-81, Src/Merchant.c:568-740, :329-393, Src/WarpFormEvent.c:704-722)
- **SAV-052** {M7} [UI] [M][W][P] A save written by a newer app (`unsupportedFutureVersion`) is reported, when the player tries to open or import it, as `SystemAlert.openFailed` with the reason "made by a newer version", and the file is left where it was (ALR-091). (source: Form_SpaceTrader.cs:2900-2903; Strings.cs:138-139)

## 14. API names proposed by this spec

Beyond the decided API (`SaveEnvelope`, `SaveCodec`, `SaveMigrator`, `SaveError`, `SlotStore`, `HighScoreStore`, `GameState.reloadCount`, `GameState.ironman`):
- `SaveEnvelope.gameID: String`, `SaveEnvelope.generation: Int` (SAV-031/032).
- `SaveSummary.cheatsUsed: Bool`, `SaveSummary.ended: Bool` (SAV-002).
- `SlotInfo { id, url, summary, rulesetID, gameID, generation, modified, isAutosave, recoveredFromBackup }` (SAV-022/025).
- `SlotStore(root:appVersion:)` (the implementation's initializer), `SlotStore.newSlotID()`, `save(_:slot:gameID:)`, `autosave(_:gameID:)`, `info(slot:)`, `importSave(_:)`, `exportSave(slot:)`, `loadForPlay(slot:revert:currentGameID:) -> LoadedGame` (SAV-034).
- `SaveMigrator.migrate(_:steps:target:)` test overload (SAV-016).
- `GameState.resumedAfterLoad(countsAsReload:)` (SAV-036) and ruleset flag `flags.travel.cheatChancesPersist` (SAV-037).
